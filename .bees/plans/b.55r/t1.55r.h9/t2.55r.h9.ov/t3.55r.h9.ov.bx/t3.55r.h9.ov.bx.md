The feature is a producer/consumer context-window guard: a status-line-fed per-session gauge file (`<tempdir>/.quorum/context-usage-<session_id>.json`, produced via `context_gauge.py produce`) supplies a context-usage percentage the model cannot read natively; the three execution skills (`/quo-execute`, `/quo-breakdown-epic`, `/quo-fix-issue`) read it at Epic/Issue boundaries via `context_gauge.py read` and STOP (recommending a fresh session) before an ill-timed auto-compaction. Relationship to b.ja9: b.ja9 made any un-prevented compaction LOSSLESS via state-externalization; this guard prevents the ill-timed compactions in the first place. This is a user-facing feature (new orchestrator stop behavior + configure-now gate) AND an architecture change, so per the doc-writer categorization it warrants entries in BOTH the cumulative PRD and the cumulative SDD.

PRD subsection (`## Per-feature scope`) — user-facing behavior only:
- **Stop-before-compaction.** The three execution orchestrators check remaining context headroom at each Epic (execute/breakdown) or Issue (fix) boundary and stop, recommending the operator start a fresh session, when usage has climbed far enough that starting another unit risks an ill-timed auto-compaction. Frame in terms the user sees, not internals.
- **Configure-now gate.** When no gauge reading is being published (`missing`), the orchestrator fires a hard-stop gate offering to configure the producer inline via `/quo-setup --configure-gauge-producer`.
- **Persistent opt-out.** The run-unguarded marker (written by /quo-setup) suppresses ONLY the missing-reading hard-stop; it never suppresses a genuine over-threshold stop when a reading is present. Cross-reference the existing README opt-out prose rather than restating the path.
- **The single silent carve-out.** When `CLAUDE_CODE_SESSION_ID` is unset, the guard is skipped silently (no gauge file can be keyed without a session id).

SDD subsection (`## Per-feature design`) — architecture:
- **Producer/consumer split.** Producer = the status-line `context_gauge.py produce` writing the per-session gauge file (Epic 1 machinery); consumer = the boundary check in the three execution skills calling `context_gauge.py read --session-id <id>`. The two halves share only the file contract; they never talk directly.
- **Boundary-gate shape.** The consumer runs at each Epic/Issue boundary, maps the four `read` outputs (integer percentage / `no-reading` / `stale` / `missing`) to a routing decision, and stops the run recommending a fresh session when the reading is at/above the stop threshold. Record the landed `STOP_THRESHOLD_PERCENT` value (feature intent: ~50%, chosen as a conservative margin below the harness's ~83% auto-compaction point because usage only grows within a session) — but take the actual number from the landed constant. Note the consumer obtains the threshold from the helper's `stop-threshold` subcommand (single definition site), not a restated literal.
- **Unsupported/unset-session-id silent carve-out vs missing-reading hard-stop.** Distinguish the two: an unset `CLAUDE_CODE_SESSION_ID` skips the guard silently (no diagnostic, no gate), whereas a configured session whose reading is `missing` fires the hard-stop configure-now gate. `no-reading` (fresh file, number not yet populated) is transient and must not be treated as a stop.
- **Option A stale-routing decision.** Record the landed decision that a `stale` reading STILL stops the run (stale biases low and cannot be trusted as headroom), paired with a freshness-window bump (feature intent: raised from 120s to a turn-scale ~15-20 min so a normally-refreshing producer is not misread as stalled). Take the actual `FRESHNESS_WINDOW_SECONDS` value from the landed constant. Note the monotonic-floor `stale:<n>` rework was considered and rejected to keep the protected `read` four-value contract stable.
- **Relationship to b.ja9.** b.ja9's state-externalization made any un-prevented compaction lossless; this guard is the complementary half that prevents ill-timed compactions from firing mid-unit. Note the two are independent and additive.
