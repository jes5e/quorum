## Context

The capability payoff of the whole feature: wire the boundary consumer check into the three execution skills so a long boundary-crossing run stops cleanly before auto-compaction. Depends on Task 1 (the self-introspection carve-out that lets this diff pass the review criteria) and Task 2 (the threshold seam and the enlarged freshness window). The check mirrors the existing `CLAUDE_EFFORT` floor-check shape (read first, evaluate, only then decide whether to fire a gate; silent-skip on unset).

## What Needs to Change

Add the boundary-guard check at each **continuing, in-session** boundary in the three execution skills, co-located with the post-b.ja9 state-externalization checkpoint prose:
- `skills/quo-execute/SKILL.md` §4.2 — the Mode 1 continue path and the Mode 2 auto-continue path (branch 2).
- `skills/quo-breakdown-epic/SKILL.md` Section 7 — the Mode 2 no-reshape-risk auto-continue-to-next-Epic path.
- `skills/quo-fix-issue/SKILL.md` — the `all`/list inter-issue loop-back boundary (Section 7 step 5 area). quo-fix-issue has no prior boundary context discipline, so this ADDS the check there.

At each such boundary:
1. Run one literal command — `printenv CLAUDE_CODE_SESSION_ID` (POSIX) / `Write-Output $env:CLAUDE_CODE_SESSION_ID` (PowerShell) — and **trim trailing whitespace/newline** from the value before use (a trailing newline fails the helper's session-id validation). Evaluate BEFORE creating any gate task (mirror the CLAUDE_EFFORT ordering rule; do not strand a `gate-*` task).
2. Branch:
   - **session id unset/empty** → skip the guard silently (the ONLY silent-skip; unsupported-CLI carve-out).
   - **session id present** → run `context_gauge.py read --session-id <trimmed-id>` (sibling-resolved helper, one literal Bash call) and obtain the stop threshold from Task 2's seam, then branch on the read output:
     - integer **≥ threshold** → **stop** at this boundary with a fresh-session resume recommendation naming the exact resume command for the active skill (`/quo-execute <bee-id>`, `/quo-breakdown-epic <bee-id>`, or `/quo-fix-issue all`/the remaining ids), reporting the current percentage.
     - integer **< threshold** → continue, no output.
     - **`no-reading`** → continue (transient fresh-but-null; producer alive).
     - **`stale`** → **stop** at this boundary (stalled-producer signal; note the producer appears stalled and that recurring staleness across fresh sessions means the operator should check their status-line producer). Do NOT let `stale` fall through to continue.
     - **`missing`** → **hard-stop** via the two-step `TaskCreate` → `AskUserQuestion` contract, UNLESS the persistent opt-out marker is present (then skip silently). The gate (a) states the environment may override user status-line config, (b) publishes the file contract (path + required fields + overwrite-per-session semantics), (c) offers to run `/quo-setup --configure-gauge-producer` inline via the Skill tool. Options at minimum: **Configure now** / **Proceed without the guard (this run)** / **Never guard me (persistent opt-out)** / **Stop here**. Because a freshly-configured producer only activates next session, after a successful Configure now the gate **recommends resuming in a fresh session** rather than implying the current run is now guarded.
     - **non-zero exit / empty stdout** (`read` exits 2 on a malformed gauge OR an invalid `--session-id`) → route to the same fail-safe **stop-and-ask** as `stale` (untrustworthy reading; never fall through to continue). Do NOT assume exit 2 implies a corrupt file.
3. Single-unit runs (no boundary crossed) do NOT invoke the guard.
4. Wire the check ONLY into continuing in-session paths. Do NOT add it to run-ending paths (next unit `none`): a fresh-session stop recommendation is noise there, and the missing-reading hard-stop would fire an `AskUserQuestion` immediately before final review. The state-externalization checkpoints are unconditional on every exit path; the guard deliberately is NOT — do not inherit their unconditionality.

Fold in the skill-behavior documentation for each skill's new stop behavior (in the skill prose / its own surfaces — NOT the cumulative PRD/SDD subsection, which is Task 4).

## Why

This is the acting half of the guard: b.ja9 made any un-prevented compaction lossless; this check prevents the ill-timed ones by stopping at a clean boundary before ~83% compaction fires.

- Depends on Task 1 (self-introspection carve-out present) and Task 2 (threshold seam + enlarged freshness window). Obtain the threshold from Task 2's seam — never restate 50.

## Success Criteria

- On a boundary-crossing run with an over-threshold reading, each of the three skills stops at the boundary with a correct fresh-session resume command. (Demo per skill: force a high gauge; observe the stop.)
- Under-threshold and `no-reading` continue silently; `stale` stops (stalled-producer note, never continue); a non-zero/empty `read` result routes to the same fail-safe stop-and-ask as `stale`; `missing` fires the hard-stop gate with the file contract + inline `/quo-setup --configure-gauge-producer` offer, unless the opt-out marker is present.
- Unset `CLAUDE_CODE_SESSION_ID` skips the guard silently; the session-id value is trimmed before being passed to the helper.
- Single-unit runs and run-ending (`none`) paths show no guard behavior.
- The gate conforms to the two-step contract (a `gate-*` task precedes the `AskUserQuestion`; no stranded gate tasks); Configure-now recommends a fresh session; all snippets paired POSIX + PowerShell; prose project-neutral; no reintroduction of the removed "clear your working context" instruction.
