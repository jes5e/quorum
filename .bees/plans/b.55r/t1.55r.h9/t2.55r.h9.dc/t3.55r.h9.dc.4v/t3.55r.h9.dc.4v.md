## Context

This is the acting half of the context-window guard for `/quo-fix-issue`. Epic 1 shipped `skills/quo-setup/scripts/context_gauge.py` whose `read --session-id <id>` prints one of four values — an integer percentage, `no-reading`, `stale`, or `missing` — exiting 0 for all four and exiting 2 on a malformed gauge OR an invalid `--session-id`. b.ja9 already made any un-prevented harness compaction lossless via the Issue-boundary state-externalization checkpoint; this Subtask adds the check that STOPS the run at a clean Issue boundary before ~83% auto-compaction fires during a multi-issue (`all` / list) run. `/quo-fix-issue` has no prior boundary context discipline of its own, so this ADDS the guard at the inter-issue boundary.

The check mirrors the existing `CLAUDE_EFFORT` floor-check shape (Section 1's `#### Check session reasoning effort`): read the environment variable FIRST with one literal command, evaluate it, and only THEN decide whether to create a gate task — never strand a `pending` `gate-*` task. Read that sub-section before you start so the new prose matches its ordering discipline and its two-step `TaskCreate` → `AskUserQuestion` contract.

**Review-cleanliness (depends on Task 1).** The guard reads an EXTERNAL gauge file written by a separate status-line process — it does NOT measure the orchestrator's own token usage and is not self-introspection. Task 1 landed the self-introspection-vs-external-gauge carve-out so this diff passes the review criteria; frame the new prose as reading an external producer's file, and do NOT introduce any "clear your working context" instruction — the fresh-session recommendation is the only reclamation lever, and the orchestrator has no model-invocable self-clear/self-compact lever.

## What Needs to Change

Edit `skills/quo-fix-issue/SKILL.md` Section 7. Co-locate the guard with the `#### Issue-boundary state-externalization checkpoint` and Section 7 step 5. The guard fires ONLY on the one continuing, in-session path — **batch mode (`all` or list) with a next Issue remaining in the batch**, i.e. step 5's "proceed to the next issue in the batch (go back to step 2)". The guard fires AFTER the Issue-boundary checkpoint has run (so state is already durable on disk and a fresh session can resume) and BEFORE control loops back to step 2.

Do NOT add the guard to the run-ending paths: single mode (proceeds to Section 8) and batch mode when the batch is exhausted (also proceeds to Section 8). On a run-ending path a fresh-session stop recommendation is noise and the missing-reading gate would fire an `AskUserQuestion` immediately before final review. The Issue-boundary checkpoint is unconditional on every path; the guard deliberately is NOT — do not inherit its unconditionality. A single-Issue run crosses no boundary and does NOT invoke the guard.

**Canonical guard branch logic** (author this once, self-contained, at the step-5 inter-issue boundary):

1. **Read the session id — one literal command, evaluated before any gate task is created** (mirror the `CLAUDE_EFFORT` ordering rule; a stranded `pending` `gate-*` task violates the two-step contract's yield-control discipline):
   - POSIX: `printenv CLAUDE_CODE_SESSION_ID`
   - PowerShell: `Write-Output $env:CLAUDE_CODE_SESSION_ID`
   **Trim trailing whitespace/newline** from the value before use — a trailing newline fails the helper's `--session-id` validation.
2. **Session id unset/empty → skip the guard silently and continue.** This is the ONLY silent-skip path (the unsupported-CLI carve-out), matching the `CLAUDE_EFFORT` unset handling.
3. **Session id present:**
   a. Resolve the helper as a sibling of this skill's base directory — `<this skill's base directory>/../quo-setup/scripts/context_gauge.py` (POSIX `/`, PowerShell `\`); the base directory is in the skill invocation header. Same sibling-resolution discipline this skill already uses for `scoped_marker_resolver.py` and `hive_commit.py`.
   b. **Obtain the stop threshold from Task 2's threshold-emitting seam** — a single literal `context_gauge.py <threshold-subcommand>` call that prints the integer. Read `context_gauge.py` at runtime to find the exact subcommand name Task 2 added (`stop-threshold`). **NEVER restate the numeric threshold in prose.**
   c. Run one literal Bash call: `python3 "<...>/../quo-setup/scripts/context_gauge.py" read --session-id <trimmed-id>` (paired POSIX/PowerShell).
   d. Branch on the read output and exit status:
      - **integer ≥ threshold → STOP** at this boundary. Report the current percentage and recommend resuming in a **fresh session**, naming the exact resume command `/quo-fix-issue all` (or `/quo-fix-issue <remaining-ids>` for the un-fixed subset of a list run). Then exit the skill.
      - **integer < threshold → continue**, no output.
      - **`no-reading` → continue** (transient fresh-but-null; producer alive).
      - **`stale` → STOP** at this boundary (stalled-producer signal). Note the producer appears stalled, and that recurring staleness across fresh sessions means the operator should check their status-line producer. Recommend the fresh-session resume with the resume command. Do NOT let `stale` fall through to continue.
      - **non-zero exit / empty stdout → same fail-safe stop-and-ask as `stale`** (untrustworthy reading). `read` exits 2 on a malformed gauge OR an invalid `--session-id`, so do NOT assume exit 2 implies a corrupt file. Never fall through to continue.
      - **`missing`** → first check the persistent opt-out marker at `<tempdir>/.quorum/context-guard-opt-out` (POSIX `/tmp/.quorum/context-guard-opt-out`, Windows `%TEMP%\.quorum\context-guard-opt-out`) via a single literal existence check (POSIX `test -f`, PowerShell `Test-Path`). **If the marker is present → skip the guard silently and continue.** If absent → **hard-stop via the two-step `TaskCreate` → `AskUserQuestion` gate** described next.
4. **The missing-reading gate.** First `TaskCreate` a `gate-askuserquestion-<short-suffix>` TaskList task naming this boundary context-guard gate (distinct per-fire suffix; honor the yield-control discipline — do not yield while it is `pending`/`in_progress`), then call `AskUserQuestion` in the same turn; mark it `completed` once the answer is consumed. The question text (a) states the environment may override the operator's user status-line config so no reading is being published; (b) publishes the gauge file contract — its path, required fields, and overwrite-per-session semantics; (c) states that Configure now runs `/quo-setup --configure-gauge-producer` inline. Options (multi-choice only; no fake free-text options):
   - **Configure now** — invoke `/quo-setup --configure-gauge-producer` inline via the Skill tool (the same inline-Skill precedent Section 1's URL-resolution sub-step uses). Because a freshly-configured producer only activates NEXT session, after a successful Configure now the gate **recommends resuming in a fresh session** rather than implying the current run is now guarded.
   - **Proceed without the guard (this run)** — continue, write no marker.
   - **Never guard me (persistent opt-out)** — write the marker via the sibling helper's `context_gauge.py write-opt-out` (one literal call), then continue.
   - **Stop here** — exit with the `/quo-fix-issue all` (or remaining-ids) fresh-session resume command.
