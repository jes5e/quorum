## Context

Epic 3 of Bee b.55r adds the context-window guard's boundary consumer: `skills/quo-execute/SKILL.md` gains prose that reads the machine-written context-usage gauge (via `context_gauge.py read`) and stops at a unit boundary when the reading crosses the stop threshold. The gauge itself, its file contract, and the `read`/`produce` subcommands are already documented in `docs/doc-writing-guide.md` `## The context-gauge file contract`, and the `STOP_THRESHOLD_PERCENT` seam is defined there for exactly this consumer.

Today CONTRIBUTING.md `## Known limitations` (the doc named under CLAUDE.md `## Documentation Locations` `Engineering best practices`) carries a do-not bullet under `### Model-initiated context clearing / compaction is unavailable`:

> - Add prose instructing the orchestrator to measure its own token usage, report a remaining-context percentage, or gate a branch on one. The orchestrator cannot read its own usage; `#34879` and `#27969` track the upstream capability and are covered by `b.cj2`.

As written, that bullet reads as a blanket ban on gating a branch on any context-usage number — which the Epic 3 boundary consumer would appear to violate. The distinction the bullet must now preserve: the model still cannot *introspect its own* token usage (no model-invocable lever exists — that is the mechanism-unavailable class this whole entry documents), but reading an **out-of-band, machine-written gauge file** that a status-line process produced, and stopping at a boundary on that reading, is an ordinary file/command read the model CAN perform. That is a permitted, executable-verb action, not self-introspection. Without a carve-out, a future reviewer applying this bullet would (wrongly) flag the Epic 3 consumer prose as re-shipping the banned instruction.

This Subtask is the sibling of the engineer-lane carve-out at `skills/quo-execute/SKILL.md`; the two must land with consistent wording because they are the shared review-criteria contract Task 3's reviewers cross-check.

## What Needs to Change

Edit the do-not bullet at CONTRIBUTING.md `## Known limitations` → `### Model-initiated context clearing / compaction is unavailable` → `**Do not re-ship the instruction.**` list (the `measure its own token usage … gate a branch on one` bullet) to add a carve-out that:

- Keeps the self-introspection prohibition intact and unweakened: the orchestrator still cannot read *its own* context usage; nothing in the carve-out grants a self-measurement lever. State this explicitly so the ban is not softened.
- Distinguishes the forbidden action (the model introspecting its own token usage / computing its own remaining-context percentage) from the permitted action (reading the external context-usage gauge file that a status-line producer wrote, via the helper's `read` subcommand, and stopping at a unit boundary when the reading crosses the stop threshold). The permitted read is model-invocable because it is an ordinary file read / command run against a file another process wrote — the gauge value originates out-of-band from the status-line payload, not from the model measuring itself.
- Cross-references the gauge contract at `docs/doc-writing-guide.md` `## The context-gauge file contract` (where the file path, the `read`/`produce` subcommands, the fail-safe rules, and the `STOP_THRESHOLD_PERCENT` seam live) so the reader can find the mechanism rather than re-deriving it.
- Aligns the wording with the **executable-verb test** in CLAUDE.md `## Review criteria for skill changes`: the external-gauge read names an action the model can actually take with its tools, whereas self-introspection names a lever only the harness/API owns. Frame the carve-out in those terms.
- Leaves the surrounding `b.cj2` / `#34879` / `#27969` re-probe pointer intact — those still track the genuinely-unavailable self-introspection capability, which the carve-out does not resolve.

Do not add any shell snippet to this bullet (prose-only). Do NOT touch the cumulative PRD/SDD `### Feature:` subsections (Task 4 owns those) and do NOT edit `skills/quo-execute/SKILL.md` (engineer's lane).
