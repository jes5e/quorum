## Context

Epic 3 (t1.55r.h9) wires a context-window boundary guard that consumes an *externally produced* gauge reading — the context-usage gauge written by a status-line producer (the bundled `context_gauge.py` produce/read path shipped in Epics 1-2) — and stops the run at an Epic/Issue boundary when the reading crosses a stop threshold. That guard does NOT self-introspect: it reads a machine-written file rather than estimating its own token usage.

Before Task 3 wires that guard into the boundary sites, two engineer-lane prerequisites must land (this Subtask):

1. A **build-time precondition presence-check** confirming the b.ja9 honesty rewrite (state-externalization framing) is already in place, so the guard composes with it instead of conflicting with a pending rewrite or re-entrenching the removed "clear your working context" instruction.
2. A **self-introspection-vs-external-gauge carve-out** at the one execution-skill site in the engineer lane — `skills/quo-execute/SKILL.md`'s Epic-boundary state-externalization checkpoint. Today that site flatly forbids the orchestrator from reporting/gating on context usage; without a carve-out, Task 3's own guard diff would trip the repo's executable-verb review criterion (an external-gauge read is model-invocable and must not read as forbidden self-introspection).

The paired carve-out in `CONTRIBUTING.md` `## Known limitations` is DOC-WRITER lane, not engineer lane, and is tracked as a sibling Subtask; keep this Subtask's wording consistent with it since Task 3's reviewers cross-check both against the same review-criteria contract. ### 2. Self-introspection carve-out in `skills/quo-execute/SKILL.md`

Amend the **"What this checkpoint does not do."** paragraph inside the `##### Epic-boundary state-externalization checkpoint` sub-section. The load-bearing sentence today reads verbatim:

> The orchestrator cannot read its own token usage, so do not attempt to check remaining context, report a percentage, or gate any branch on one.

Rewrite this sentence (and add clarifying prose as needed) so it **distinguishes**:

- **Forbidden self-introspection** — the orchestrator inventing/estimating a number for its *own* token usage from memory, reporting a self-measured remaining-context percentage, or gating a branch on such a self-estimate. This prohibition stays fully intact and must not be weakened.
- **Permitted external-gauge read** — reading an out-of-band, machine-written gauge artifact (a context-usage reading produced by a separate status-line producer process and written to a file) via the `Read`/helper path, and stopping at a boundary on that reading. This is an external measurement the orchestrator consumes like any other on-disk carrier, and both the read and the boundary-stop are model-invocable actions — so they are permitted.

The carve-out must make clear that what stays forbidden is the model *pretending to know its own usage without an external source*; reading a gauge file a different process wrote is not that.

The "no model-invocable way to clear or compact its own context" framing is deliberately OUT of scope and stays as-is.
- Prose must be **project-neutral** (design rule 3): describe the gauge generically as an externally-produced/status-line-written context-usage reading.
