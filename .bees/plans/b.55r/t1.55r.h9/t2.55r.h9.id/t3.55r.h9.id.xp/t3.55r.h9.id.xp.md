## Context

LANDED DESIGN DECISION (2026-08-19, binding — Option A, window-bump). Live evidence during Epic 1's execution (SDD `## Deferred from /quo-execute run (2026-08-18 21:18)`) falsified SR-1.6's freshness rationale: the Claude Code status line does NOT refresh while a turn is in progress — tool calls within a turn trigger no refresh — so at any boundary reached more than the current 120s window into a turn, `read` returns `stale` even with a healthy producer and a valid reading. Under the shipped `stale → stop` routing (SR-2.3 / SR-2.5) that stops nearly every real Epic/Issue boundary crossing with a misleading "producer appears stalled" framing, rendering the guard unusable.

The user chose fix path (a) / Option A at breakdown: raise `FRESHNESS_WINDOW_SECONDS` from 120 to a turn-scale value and KEEP `read`'s four-value output and its `stale → stop` routing UNCHANGED. The monotonic-floor `stale:<n>` rework (Option B / fix path (b)) is explicitly REJECTED because it would reopen the protected `read` four-value contract. This bump preserves genuine dead-producer detection (a gauge older than the enlarged window still classifies `stale` and stops the run) while eliminating the observed false positive at normal boundaries.
