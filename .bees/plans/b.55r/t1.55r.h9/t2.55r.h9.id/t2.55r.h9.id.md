## Context

The boundary guard (Task 3) needs two things from the bundled helper `skills/quo-setup/scripts/context_gauge.py` that it cannot get today, plus a correction to a shipped constant. This Task establishes those helper seams and moves every lockstep carrier with them, so Task 3's consumer prose can be authored against a stable contract. Both changes are **additive or single-constant** — they do NOT reopen the protected `read` four-value output vocabulary or the gauge-file path/field contract.

## What Needs to Change

**1. Threshold-emitting seam (resolve the single-definition-site gap).** `STOP_THRESHOLD_PERCENT = 50` is the single tunable definition site (SDD SR-2.1), but no CLI path emits it, so a consumer would have to restate `50` in skill prose — quietly creating a second definition site. Add an additive, non-breaking way for the consumer to obtain the threshold from the helper (e.g. a new orthogonal subcommand or flag that prints the integer threshold, or emits the stop/continue decision). Do NOT change `read`'s existing four-value output contract to carry this. The consumer (Task 3) will call this seam once at each boundary and compare the reading against it, so no threshold literal appears in skill prose.

**2. Freshness-window bump (LANDED DESIGN DECISION — carry verbatim).** Live evidence (SDD deferred note, 2026-08-18) falsified SR-1.6's freshness rationale: the status line does NOT refresh while a turn is in progress, so at any boundary reached more than the current 120s window into a turn, `read` returns `stale` even with a healthy producer and a valid reading — which today routes to stop, stopping nearly every real boundary-crossing run with a misleading "producer stalled" message.

The user's decision at breakdown (2026-08-19) is **Option A (window-bump)**: raise `FRESHNESS_WINDOW_SECONDS` from 120 to a **turn-scale value (~15–20 minutes)** and KEEP the existing `stale → stop` routing and `read`'s four-value output contract unchanged. Do NOT implement the monotonic-floor `stale:<n>` rework (Option B) — it was explicitly rejected because it would reopen the protected `read` contract. This preserves genuine dead-producer detection (a gauge older than the enlarged window still stops the run) while eliminating the observed false-positive at normal boundaries. Note in the constant's comment that the window value is a post-first-use recalibration input (the RESEARCH-NEEDED owner the PRD/SDD already record).

**3. Move every lockstep carrier with the two changes above.** Update in lockstep:
- `tests/test_context_gauge.py` — add/adjust coverage for the threshold seam, and update the `stale` classification test to the new window value (the test ages a gauge with `os.utime`; the aging offset must move with the constant).
- The customer-facing README gauge-file contract section — reflect the enlarged freshness window and, if the threshold seam adds a user-observable surface, note it.
- The doc-writing guide's context-gauge file contract section — same lockstep.

## Why

Without the threshold seam, the guard's comparison prose restates 50 and defeats SR-2.1's single-definition-site intent. Without the window bump, the guard is unusable — it would stop nearly every long run with a false "producer stalled" framing. Both are prerequisites for a guard that fires only when it should.

## Cross-Task / cross-Epic contract

- **This Task locks the helper contract Task 3 consumes.** Task 3's boundary branch obtains the threshold from this Task's seam (never by restating 50) and relies on the enlarged freshness window's `stale → stop` semantics. Task 3 depends on this Task.
- The gauge-file path/field names and `read`'s four-value output vocabulary are the protected cross-skill contract (SDD `## Existing Behavior`) and MUST NOT change here — this Task only adds an orthogonal seam and bumps one internal constant.
- The freshness-window value and the threshold constant each remain a single definition site; any consumer or doc that mentions them must reference the helper, not re-hardcode them.
