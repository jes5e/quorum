## Context

`skills/quo-setup/scripts/context_gauge.py` defines the stop threshold as the single-definition-site constant `STOP_THRESHOLD_PERCENT = 50` (SDD SR-2.1), but NO CLI path emits it. The boundary guard being built in Task 3 (t1.55r.h9) must obtain the threshold from the helper at each boundary and compare it against `read`'s integer percentage. Without an emit path, the guard's comparison prose would have to restate `50`, quietly creating a second definition site and defeating SR-2.1's single-definition-site intent.

The fix is ADDITIVE: a new orthogonal subcommand. It MUST NOT change `read`'s existing four-value output vocabulary (`integer` / `no-reading` / `stale` / `missing`) or the gauge-file path/field names — those are the protected cross-skill contract. A flag on `read` is explicitly ruled out because it would alter `read`'s output surface. `STOP_THRESHOLD_PERCENT` stays the single definition site — the new subcommand reads the constant, never a fresh literal.

## What Needs to Change

In `skills/quo-setup/scripts/context_gauge.py`:

1. Add a `cmd_stop_threshold(args) -> int` function that prints exactly the integer value of `STOP_THRESHOLD_PERCENT` on stdout (a single decimal integer followed by a newline — use `print(STOP_THRESHOLD_PERCENT)`) and returns `0`. It reads nothing from stdin, writes no file, creates no directory, and emits nothing on stderr. It reads the module constant directly so `STOP_THRESHOLD_PERCENT` remains the one and only definition site.
2. Register a `stop-threshold` subparser in `main()` alongside the existing five subcommands (`produce`, `read`, `inspect-statusline`, `install-statusline`, `write-opt-out`). It takes no arguments. Give it a one-line `help=` string (e.g. "print the stop threshold percentage a consumer compares a reading against").
3. Wire the dispatch in `main()`: add a branch `if args.mode == "stop-threshold": return cmd_stop_threshold(args)` in the same style as the existing branches (match the surrounding branch style; note today the final subcommand is dispatched as a fallthrough — keep the dispatch unambiguous).
4. Add a `**Threshold mode:**` section to the module docstring (near the other mode sections, e.g. after the Reader-mode section), documenting the synopsis `context_gauge.py stop-threshold`, that it prints the integer stop threshold on stdout and exits `0`, that it is read-only (writes nothing, creates nothing), and that it exists so a consumer can obtain the threshold from the single-definition-site constant rather than restating it. State plainly that this subcommand does NOT touch `read`'s four-value output or the gauge-file contract.
5. If the docstring's `## Exit codes` section enumerates per-subcommand behavior, add a line noting `stop-threshold` returns `0` (its only non-zero exit being an argparse usage error, raised before the command runs), consistent with how `read`/`produce` are described.

Do NOT change `STOP_THRESHOLD_PERCENT`'s value (stays 50), `read`, `classify_reading`, the gauge-file path/field constants, or any other subcommand. Keep the file stdlib-only and importable on Python 3.9 (no PEP 604 unions; use `Optional[...]` if any annotation is needed — none should be for this change).

## Key Files

- `skills/quo-setup/scripts/context_gauge.py` — add `cmd_stop_threshold`, the `stop-threshold` subparser, the `main()` dispatch branch, and the docstring mode section. `STOP_THRESHOLD_PERCENT` is defined at the top of the module and is the value to emit; `main()`'s subparser/dispatch block is at the bottom.

- `read` still returns exactly its four values (`integer` / `no-reading` / `stale` / `missing`) with unchanged exit codes; the gauge-file path and JSON field names are unchanged. The new subcommand is purely additive.
- The module docstring documents the new `stop-threshold` mode alongside the existing modes.
