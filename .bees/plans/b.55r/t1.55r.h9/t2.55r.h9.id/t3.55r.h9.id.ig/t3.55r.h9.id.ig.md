## Context

Task 2 of Epic 3 raises `FRESHNESS_WINDOW_SECONDS` in `skills/quo-setup/scripts/context_gauge.py` from 120 to a turn-scale value (~15–20 min) while KEEPING `read`'s four-value output (integer / `no-reading` / `stale` / `missing`) and the `stale`→stop semantics unchanged. Several tests in `tests/test_context_gauge.py` encode the old 120-second window, and two of them will silently stop exercising staleness (rather than fail loudly) once the window grows, because they age a gauge by a hardcoded 300 seconds — which sits INSIDE a 15–20 min window. This Subtask updates the window-dependent tests so they move with the new constant and re-proves that the four reading values are unchanged. Follow the two-layer pattern and the fixtures documented in the Test writing guide (CLAUDE.md `## Documentation Locations` → `docs/test-writing-guide.md`) and mirrored in `docs/sdd.md` `## Test Fixtures`. Unit/CLI-contract test work only — no source or doc edits.

## What Needs to Change

All edits are in `tests/test_context_gauge.py`.

1. **Constant pin (`test_tunable_constants`).** The `assert mod.FRESHNESS_WINDOW_SECONDS == 120` line breaks by design (the test's own comment calls this a deliberate re-calibration that must be made explicit). Update it to the EXACT value the Engineer landed — read it from the helper's constant, do not guess. Add a second assertion that the value is turn-scale so an accidental revert to 120 fails loudly, e.g. `assert mod.FRESHNESS_WINDOW_SECONDS >= 900`. Leave `assert mod.STOP_THRESHOLD_PERCENT == 50` unchanged.

2. **Unit staleness via os.utime (`test_classify_reading_aged_via_os_utime_is_stale`).** The hardcoded `aged = time.time() - 300` no longer ages the gauge past the new window. Replace the offset so it references the helper constant and clears it with slack, e.g. `aged = time.time() - (mod.FRESHNESS_WINDOW_SECONDS + 60)`, then `os.utime(path, (aged, aged))` and assert `mod.classify_reading(path, now=time.time()) == mod.READING_STALE`.

3. **CLI staleness via os.utime (`test_cli_read_stale`).** Same fix at the CLI-contract layer: replace `aged = time.time() - 300` with `aged = time.time() - (mod.FRESHNESS_WINDOW_SECONDS + 60)` (the CLI test module already imports `mod`), keep `os.utime(path, (aged, aged))`, and keep the existing assertions `res.returncode == 0` and `res.stdout == "stale
"`.

4. **New positive test proving the enlargement's effect.** Add a unit-layer test that a reading aged WELL PAST the old 120-second window but comfortably inside the new one still classifies as the integer (not `stale`). Seed a gauge holding a valid integer, then assert `mod.classify_reading(path, now=mtime + 240) == "<that integer>"`. 240s is above the old 120s window and below a 15–20 min window, so this proves the window actually grew past 120. Use a literal comfortably between 120 and the new window (do NOT use `mod.FRESHNESS_WINDOW_SECONDS - N`, which would not prove the >120 boundary moved).

5. **Reprove the untouched paths (confirm green).** Confirm the symbolic-offset staleness tests still pass unchanged — `test_classify_reading_stale_wins_over_a_valid_low_integer`, `test_classify_reading_inside_freshness_window_returns_the_integer`, and `test_classify_reading_is_silent_across_the_four_normal_cases` (all age relative to `mod.FRESHNESS_WINDOW_SECONDS`, so they self-adjust). Confirm the other CLI read classifications remain green: `test_cli_read_fresh_integer`, `test_cli_read_no_reading`, `test_cli_read_creates_nothing_on_a_clean_temp_root` (`missing`), and the malformed/non-utf8 exit-2 tests. These prove read's four-value vocabulary and exit-code split are unchanged by this Task.
