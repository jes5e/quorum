## Context

Two requirements remain after the slow-path section lands. First, the Task requires an explicit, documented decision on whether the fast path offers this step — and the decision matters, because the fast path's scenario is "this repo is already set up, but this machine is not", which is precisely the machine where no status line is configured: `statusLine` lives in per-machine user settings that are never committed, structurally the same gap as the unregistered `~/.bees/config.json` the fast path exists to close. Second, the boundary guard's missing-reading hard-stop (a downstream consumer) dispatches `/quo-setup` inline via the Skill tool as its "configure now" action; on such a machine the repo is already registered, so fast-path detection reports ineligible and the operator would be walked through hive validation, Documentation Locations, and Build Commands to reach one status-line prompt. A named direct entry point is what makes "invokable that way" true rather than nominal.

Preconditions: the slow-path section from the sibling subtask exists and can be referenced by its heading.
