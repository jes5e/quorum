## Context

Task 2 (SR-3.6) makes `/quo-setup` write a persistent opt-out marker at `<tempdir>/.quorum/context-guard-opt-out` when the operator picks the "run unguarded" choice. That path is **deterministic** — no random suffix, no timestamp — and deliberately so: the writer (quo-setup, in one session) and the reader (Epic 3's boundary check, in a different session and process with no channel to the writer) must compute the same path independently, and a collision-resistant name would defeat the marker's whole purpose of recording a standing choice.

This collides with an existing repo rule. `CLAUDE.md` `## Scratch-file convention` requires collision-resistant filenames inside the `<tempdir>/.quorum/` namespace, carries exactly two "Documented exception —" paragraphs (the orchestrators' run-state manifest and the per-session context-usage gauge), and closes with: *"Treat a deterministic name as a defect anywhere else in the namespace."* `CLAUDE.md` `## Review criteria for skill changes` then makes the scratch-file convention a **mandatory review criterion** for every skill-prose change in this repo. So without this subtask, Task 2's own diff introduces a third deterministic name in the namespace with no documented exception, and the Engineer/Doc reviewers are obliged to flag it.

Second gap: the marker path is a cross-Epic string contract (Task 2 body, `## Cross-Task / cross-Epic contract`: "the marker path written here is read by Epic 3's consumer check; it is a protected string contract per the SDD — do not vary it"), but it is published nowhere in the repo's contributor-facing docs today. Grep confirms `context-guard-opt-out` appears only in ticket bodies (`.bees/specs/b.8sh/t1.8sh.cg/t1.8sh.cg.md` SR-2.8 and the Epic/Task bodies), never in `docs/`, `CLAUDE.md`, `CONTRIBUTING.md`, or `README.md`. The repo's convention for a cross-skill string of this kind is to publish it in `docs/doc-writing-guide.md` alongside its siblings (`## The lookup-key pattern`, `## The Scoped-marker contract`, `## The context-gauge file contract`), each of which carries an explicit rename-in-lockstep warning. Between Task 2 landing and Epic 3 landing, nothing else tells a contributor the string is protected.

Preconditions: the Engineer's Task 2 step prose has landed and the final marker path is settled (it must match SDD SR-2.8 verbatim — read the shipped prose, do not copy the path from this ticket). Task 1 (`t2.55r.9d.ds`) has already rewritten `docs/doc-writing-guide.md` `## The context-gauge file contract` to the post-fix wrap semantics (subtask `t3.55r.9d.ds.bo`); this subtask appends to that rewritten section rather than to its pre-Task-1 shape.

## What Needs to Change

**1. `CLAUDE.md` `## Scratch-file convention` — add a third documented exception.**

Add a `**Documented exception — the context-guard opt-out marker**` paragraph (naming `context-guard-opt-out`, written by `/quo-setup`'s optional statusline step) immediately after the existing per-session context-usage-gauge exception paragraph and before the closing `Treat a deterministic name as a defect anywhere else in the namespace.` line. Follow the shape the two existing exception paragraphs use — each states (i) why the filename is deterministic, (ii) why the discriminator (or lack of one) is re-derivable on both sides, and (iii) the collision case it knowingly accepts. For this marker:

- Deterministic because the writer (`/quo-setup`, one session) and the reader (a boundary consumer in a different session/process) must compute the same path with no channel between them — the same rationale the gauge-file exception already records.
- No discriminator at all (unlike the gauge's `session_id`) because the marker records an **environment-scoped standing choice**, not a per-session reading; keying it per-session would re-ask the operator every session, which is precisely what SR-3.6 exists to prevent.
- Accepted collision case: two operators sharing one `<tempdir>` share one opt-out. Accepted durability caveat: the marker is persistent only within the environment's tempdir lifetime (SDD SR-2.8 records this explicitly).
- State that the marker is written once and never deleted by skill prose, consistent with the convention's no-cleanup rule — and that deleting `<tempdir>/.quorum/` therefore clears the opt-out.

**Also cover the install self-check gauge file** (`context-usage-quo-setup-self-check.json`, left behind permanently by `install-statusline`'s post-write self-check — a second deterministic name arriving in the same diff). Extend the EXISTING per-session context-usage-gauge exception paragraph with a clause (preferred over a fourth exception paragraph — it IS a gauge file, just one whose id is a reserved literal rather than session-derived) stating: why the id is fixed (`quo-setup-self-check` — the installer needs a synthetic session to exercise the freshly-composed command once); that it can never collide with a real session id; and that the file is overwritten per install and never deleted.

Also check the convention's closing paragraph ("The customer-facing README documents the per-OS location and tells users the directory is safe to delete **between** runs, with the caveat that deleting it *during* a run destroys the run-state manifest…"). If that sentence now understates what deletion costs (the marker is a second non-regenerable resident), narrow it minimally — but do NOT author the user-facing README wording here: the convention itself forbids duplicating the user-level note, and Task 3 (`t2.55r.9d.rp`) owns the README surface. Keep this edit to the internal statement of fact.
