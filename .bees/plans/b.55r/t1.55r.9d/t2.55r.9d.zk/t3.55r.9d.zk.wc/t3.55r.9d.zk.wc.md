## Context

The inspection half of this Task (`t3.55r.9d.zk.qx`) adds five constants, eight pure functions, and a read-only `inspect-statusline` subcommand to `skills/quo-setup/scripts/context_gauge.py`. Nothing in `tests/test_context_gauge.py` covers any of it today. Two of its guarantees are what the whole quo-setup step rests on: inspection **writes nothing anywhere**, and it **never reports `absent` for a settings file it could not parse** (the install path branches on that state and would otherwise clobber a file it could not read).

This subtask is also where the suite's HOME/config-dir isolation is built, because it is the first test in this repo to touch the operator's Claude Code user settings at all. Every test added here and in the sibling subtask must be structurally incapable of reading or writing the developer's real `~/.claude/settings.json`. The mechanism is specified in full below; it is the criterion this subtask is most likely to be reviewed on.

Preconditions: `t3.55r.9d.zk.qx` has landed and is readable as a diff — verify every asserted shape against the landed code rather than against this ticket. Task 1's test subtasks (`t3.55r.9d.ds.8k`, `t3.55r.9d.ds.ow`) have already landed, so the line numbers cited below have shifted; locate helpers by name.

**All new tests go in `tests/test_context_gauge.py`**, appended as new sections. Do NOT start a second test module for this helper: the `no_real_tempdir_writes` autouse fixture (lines 123-145) is module-scoped, and a new module would silently drop leak detection from exactly the tests that spawn subprocesses. Reuse the module's existing helpers — `_patch_tempdir` (206), `_run` (851), `_stub` (861), `_env_with_tempdir` (837), `_gauge_files` (894), `TEST_SESSION_PREFIX` (72) — and honor `docs/test-writing-guide.md` `## The two-layer pattern` and `## Fixtures and isolation rules`.

## What Needs to Change

### 1. Isolation scaffolding (build this first)

**Module-level real-path constants, captured at import time, spelled literally rather than read from `mod`** (same rationale as `REAL_GAUGE_DIR` at line 65 — a mutated helper constant must not be able to relocate the directory the guard watches):

- `REAL_CONFIG_DIR` = `Path(os.environ["CLAUDE_CONFIG_DIR"])` when that variable is set and non-empty, else `Path.home() / ".claude"`. Computed at import, before any test can monkeypatch anything.
- `REAL_USER_SETTINGS` = `REAL_CONFIG_DIR / "settings.json"`.
- `REAL_SELF_CHECK_GAUGE` = `REAL_GAUGE_DIR / "context-usage-quo-setup-self-check.json"`. The self-check session id is NOT covered by `TEST_SESSION_PREFIX`, so the existing fixture does not watch it; the sibling subtask's self-check tests spawn a subprocess that writes under exactly this name, and a lost `env=` override would land there. Spell the id literally here and pin the constant separately (section 2).

**New autouse fixture `no_real_user_settings_writes`**, placed beside `no_real_tempdir_writes` and written as a delta assertion, not an emptiness assertion:

- A module-private `_stat_key(path)` returning `None` when the path is absent and `(st_size, st_mtime_ns)` otherwise — stat-keyed for the same reason `_real_prefixed_entries` is (an overwrite of an existing file must fire), and carrying the same honest scope note about coarse-granularity filesystems.
- Snapshot at setup and assert unchanged at teardown: `_stat_key(REAL_USER_SETTINGS)`, `REAL_CONFIG_DIR.exists()`, and `_stat_key(REAL_SELF_CHECK_GAUGE)`. Assertion messages must name the offending path.
- The fixture reads stat metadata only — it never reads the contents of the operator's settings file, never creates anything, and never deletes anything (CLAUDE.md `## Scratch-file convention`).
- Docstring must state the one accepted false positive: a genuine `/quo-setup` install running concurrently on the same machine would move `REAL_SELF_CHECK_GAUGE` and fire the delta.

**Unit-layer isolation helper `_isolate_settings_env(monkeypatch, tmp_path, config_dir=None)`**, returning the fake home it created:

- Calls the existing `_patch_tempdir(monkeypatch, tmp_path)` — `tempfile.gettempdir()` caches in-process, so the module-object patch stays the in-process mechanism.
- `monkeypatch.setenv("HOME", ...)` **and** `monkeypatch.setenv("USERPROFILE", ...)` pointing at `tmp_path / "home"`: `Path.home()` is `os.path.expanduser("~")`, which consults `HOME` on POSIX and `USERPROFILE` on Windows, so both are required for the helper's documented "`Path.home()` covers `%USERPROFILE%` without per-OS branching" claim to be tested on either platform. Also `monkeypatch.delenv("HOMEDRIVE"/"HOMEPATH", raising=False)` so the Windows fallback chain cannot reach a real profile.
- `monkeypatch.setenv` for `TMPDIR`/`TEMP`/`TMP` at `tmp_path` as well, so any child process an in-process call spawns inherits the redirect (the `mod.tempfile` patch does not cross a process boundary).
- `config_dir=None` → `monkeypatch.delenv("CLAUDE_CONFIG_DIR", raising=False)`; otherwise `monkeypatch.setenv(...)` to the given path.
- Always via `monkeypatch`, never bare assignment or `os.environ[...] = ...`.

**CLI-layer isolation helper `_isolated_cli_env(tmp_path, config_dir=None, home=None)`**, built on `_env_with_tempdir(tmp_path)`:

- Sets `HOME` and `USERPROFILE` to `home` (default `tmp_path / "home"`), and pops `HOMEDRIVE`/`HOMEPATH`.
- **`env.pop("CLAUDE_CONFIG_DIR", None)` when `config_dir` is None.** This is the single most important line in the file: `_env_with_tempdir` copies `os.environ`, and a developer or CI runner with `CLAUDE_CONFIG_DIR` exported would otherwise point every CLI test at their real config directory. A test asserting the default `~/.claude` derivation must pop it explicitly, never rely on it being unset.
- Sets `CLAUDE_CONFIG_DIR` when `config_dir` is given.

**`_run` gains one optional keyword, `cwd=None`, passed through to `subprocess.run`** (additive; the default preserves every existing call site byte-for-byte). Needed to exercise `inspect-statusline`'s default `--repo-root` of the current working directory without chdir'ing the test process.

**Module docstring (lines 1-41)** — extend the `Isolation` paragraph to state the HOME/`USERPROFILE`/`CLAUDE_CONFIG_DIR` override discipline and name the new fixture. Do not alter the existing session-id-equality or tempdir paragraphs.

### 3. Unit layer — the pure comparison and composition helpers

### 4. Unit layer — `classify_status_line_command`

One parametrized matrix plus named tests for the load-bearing cases. `script_path` argument is a `tmp_path`-based fake path unless stated.

- `direct`: `"<py>" "<script>" produce` → `("direct", None)`.
- `wrapped`, space spelling: `... produce --wrap-command 'my status --flag'` → `("wrapped", "my status --flag")` — payload returned **unquoted and byte-exact**.
- `wrapped`, `=` spelling: `... produce --wrap-command="my status --flag"` → same tuple. (Verified: `shlex.split` yields the single token `--wrap-command=my status --flag`, so the `=` branch is a real, separate code path.)
- `other-install`: a *different* directory whose basename is `context_gauge.py`, plus `produce` → `("other-install", None)`; and the same with `--wrap-command` → payload extracted.
- `foreign`: an unrelated command → `("foreign", None)`.
- `foreign` on unsplittable input: `"'unclosed` (raises `ValueError: No closing quotation` from `shlex.split`) → `("foreign", None)` **and the call does not raise**. Its own named test — this is the branch that keeps `inspect-statusline` from dying on an operator's exotic status line.
- `test_classify_status_line_command_matches_a_backslash_spelled_script_path` — command names the script with `\` separators (backslashes survive `shlex.split` inside double quotes) while `script_path` is the forward-slashed spelling → `"direct"`. Without this, a Windows re-run would fail to recognize its own prior install and double-configure.
- `test_classify_status_line_command_requires_the_produce_token` — the script path present but the command uses `read --session-id x` → `("foreign", None)`. Negative space that keeps the matcher from claiming any invocation of this helper.
- `test_classify_status_line_command_never_parses_a_foreign_payload` — a foreign command that *contains* the literal text `--wrap-command something` still returns `wrapped_command is None`. Pins the "never parse a `foreign` command for anything" rule.
- `test_classify_status_line_command_states_are_four_way_distinct` — the four state strings are distinct, all `str`, and the returned value is always a 2-tuple.
