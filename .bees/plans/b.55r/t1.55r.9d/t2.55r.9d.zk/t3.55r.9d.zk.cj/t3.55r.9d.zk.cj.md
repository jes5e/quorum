## What Needs to Change

### 1. Isolation rules specific to this surface (state them in a comment block above the new CLI section)

- **Every `install-statusline` invocation passes `--no-self-check` except the three tests whose subject IS the self-check.** The self-check spawns a shell subprocess; `--no-self-check` removes that variable from every other test.
- **The three self-check tests must use `_isolated_cli_env(tmp_path, config_dir=...)`**, whose `TMPDIR`/`TEMP`/`TMP` are inherited by the spawned shell, so the self-check gauge lands at `tmp_path/".quorum"/"context-usage-quo-setup-self-check.json"`. Each asserts that file's existence under `tmp_path` — which simultaneously proves the self-check worked and proves the redirect held.
- **No unit-layer test may call `cmd_install_statusline` with the self-check enabled unless it also monkeypatches `mod.subprocess.run`.** `_patch_tempdir` patches the in-process `mod.tempfile` object only; it does not cross a process boundary, so an in-process self-check with the real `TMPDIR` would write to the developer's real temp directory under a name the original fixture does not watch. In-process calls use `_isolate_settings_env` (which also sets `TMPDIR`/`TEMP`/`TMP`) **and** pass the no-self-check flag or stub the spawn.

### 2. Unit layer — `quote_for_shell`

- `test_quote_for_shell_sh_round_trips` — parametrized over a nasty-value list (`a b`, `it's`, `say "hi"`, `$HOME`, a backtick, `a;b`, `a
b`, `--wrap-command x`, `""`, a unicode string): `shlex.split(mod.quote_for_shell(v, "sh")) == [v]`. A real round-trip property, not a shape assertion.
- `test_quote_for_shell_git_bash_matches_sh` — for the same list, the `git-bash` branch returns exactly what the `sh` branch returns. Pins that Git Bash is not accidentally given a different quoting rule.
- `test_quote_for_shell_powershell_doubles_single_quotes` — `"it's"` → `"'it''s'"` exactly; `"a b"` → `"'a b'"`; a value with two single quotes doubles both; the result always starts and ends with `'`.
- `test_quote_for_shell_powershell_does_not_expand` — a value containing `$var` and a backtick is preserved character-for-character between the outer single quotes (strip the delimiters and compare).
- `test_quote_for_shell_empty_value` — `sh` yields `"''"` and the powershell branch yields `"''"`.
- Unknown `shell` argument: assert only what the landed docstring pins. If it pins nothing, leave it uncovered and say so rather than inventing a contract.

### 3. Unit layer — `compose_status_line_command`

- `test_compose_status_line_command_exact_shape` — build the expected string explicitly and assert `==`: `"<py-forward-slashed>" "<script-forward-slashed>" produce`. Not a substring check.
- `test_compose_status_line_command_has_no_backslash` — for paths built with `os.sep`, `"\\" not in result`.
- `test_compose_status_line_command_omits_the_flag_when_nothing_is_wrapped` — parametrized over `None` and `""`: `--wrap-command` does not appear, and `shlex.split(result)[-1] == "produce"`.
- `test_compose_status_line_command_wrap_payload_round_trips` — for each nasty value from section 2, `shlex.split(mod.compose_status_line_command(py, script, v, "sh"))[-1] == v` byte-exactly, including a payload that itself contains `--wrap-command` and one that contains embedded quotes. This is the property the anti-double-wrap CLI test depends on.
- `test_compose_status_line_command_has_exactly_one_produce_token` — token count of `"produce"` is 1 and of `"--wrap-command"` is at most 1, in both the wrapped and unwrapped forms.

### 4. CLI layer — `install-statusline`

All of these seed settings under `config_dir = tmp_path / "cfg"` via `_seed_settings` and run with `_isolated_cli_env(tmp_path, config_dir=config_dir)`.

- `test_cli_install_statusline_fresh_install` — no settings file → exit 0; the config directory is created; the settings file's top-level keys are exactly `["statusLine"]`; `statusLine == {"type": "command", "command": <cmd>}`; summary `action == "installed"`, `previous_command is None`, `preserved_status_line_keys == []`, `new_command` equals the on-disk command; the command contains no backslash, contains the forward-slashed `str(SCRIPT)`, and its last `shlex` token is `produce`.
- `test_cli_install_statusline_wraps_a_foreign_status_line` — settings carrying an unrelated top-level key (a nested object, so the preservation assertion has teeth), plus a `statusLine` with a foreign command and `padding`/`refreshInterval` → `action == "wrapped"`; the unrelated key deep-equals its seeded value; `padding` and `refreshInterval` survive inside the rewritten `statusLine`; `type == "command"`; `previous_command` equals the foreign command byte-exactly; `preserved_status_line_keys` contains `padding`; and `shlex.split(new_command)[-1]` equals that foreign command byte-exactly.
- `test_cli_install_statusline_is_idempotent` — run twice; second reports `action == "already-configured"`; the settings file's bytes are identical; **`st_mtime_ns` is unchanged** (the no-write proof); and the config directory contains exactly `settings.json` (no orphaned temp file).
- `test_cli_install_statusline_repoints_without_nesting` — seed a wrapped producer whose script path is a *different* `context_gauge.py` (a moved install) with wrap payload `orig-cmd --flag` → `action == "repointed"`; the resulting command's `shlex` token list contains `produce` exactly once and `--wrap-command` exactly once; the wrap payload is exactly `orig-cmd --flag`, **not** the whole previous command string. This is the single most important test in this subtask — a nesting regression is invisible to every other assertion here.
- `test_cli_install_statusline_repoints_a_direct_install_on_a_python_change` — seed the exact current direct command, then run with `--python <other path>` → assert `action == "repointed"` exactly (the pinned mapping: a `direct`/`wrapped` state whose recomposed command is not byte-identical reports `repointed`); `previous_command` is the old command; the new command names the `--python` value.
- `test_cli_install_statusline_wrap_payload_round_trips_through_shlex` — a foreign command containing single quotes and a `$` → after wrapping, `shlex.split(new_command)[-1]` reproduces it byte-exactly.
- `test_cli_install_statusline_unparseable_settings_exits_2` — exit 2; exactly one stderr line; the settings file byte-identical (`read_bytes()` before/after); no `statusLine` written; no temp file left in the config directory.

- `test_cli_install_statusline_leaves_no_temp_file` — after a successful install, the config directory's listing is exactly `["settings.json"]`.
- `test_cmd_install_statusline_replace_failure_leaves_the_original_intact` (unit layer) — `_isolate_settings_env`, seed a good settings file, `monkeypatch.setattr(mod.os, "replace", boom)`, call `mod.cmd_install_statusline(...)` with the self-check disabled, assert the original file is byte-identical and the config directory listing is exactly `["settings.json"]` (the `except` → unlink path ran). - `test_cli_install_statusline_no_self_check_performs_no_spawn` — with `--no-self-check`, `_gauge_files(tmp_path) == []` and `tmp_path/".quorum"` does not exist.
