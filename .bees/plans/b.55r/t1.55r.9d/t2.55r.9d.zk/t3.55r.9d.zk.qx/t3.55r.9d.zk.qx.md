## Context

The quo-setup step this Task adds must, before it prompts anything, know four things it cannot learn from prose: where the operator's user settings file is, whether a `statusLine` is already configured (and by whom), whether the SR-2.8 opt-out marker already exists, and whether a higher-precedence settings source will outrank a user-settings write. This subtask adds the read-only half — detection only, no writes — so the mutating half (sibling subtask) and the skill prose both build on one authoritative inspector.

It also introduces the opt-out marker path as a named constant. That path is a protected cross-Epic string contract: SDD SR-2.8 fixes it at `<tempdir>/.quorum/context-guard-opt-out`, and Epic 3's consumer reads it before the missing-reading hard-stop. Defining it once, next to the existing gauge-path constants, is what keeps the two Epics naming the same file.

Preconditions: the helper as shipped by Epic 1, with Task 1's `produce` control-flow fix landed (`produce` now exits 0 on every input shape and reports a malformed payload as a single stderr line). This subtask does not touch `produce`, `read`, `write_gauge`, `classify_reading`, or any existing constant.

Verified external facts this subtask encodes (Claude Code documentation, fetched 2026-08-18):
- User settings live at `~/.claude/settings.json`; "On Windows, paths shown as `~/.claude` resolve to `%USERPROFILE%\.claude`."
- `CLAUDE_CONFIG_DIR` overrides the configuration directory (default `~/.claude`); when set, settings live under it.
- The `statusLine` object shape is `{"type": "command", "command": "..."}` with optional `padding`, `refreshInterval`, and `hideVimModeIndicator` fields.
- Precedence: Managed (highest) > command-line arguments > Local (`.claude/settings.local.json`) > Project (`.claude/settings.json`) > User (lowest).
- File-based managed settings live at `/Library/Application Support/ClaudeCode/` (macOS), `/etc/claude-code/` (Linux and WSL), `C:\Program Files\ClaudeCode\` (Windows), each also supporting a `managed-settings.d/` drop-in directory.
- Managed `disableAllHooks`, or `allowManagedHooksOnly`, narrows `statusLine` to managed settings only: "otherwise it skips your value without warning, the status line is disabled."
- On Windows, status-line commands run through Git Bash when Git Bash is installed, or through PowerShell when it is absent; Git Bash consumes unquoted backslashes in the command string, so paths must be written with forward slashes.

## What Needs to Change

**`skills/quo-setup/scripts/context_gauge.py`**

1. **New constants**, in the existing constants block alongside `GAUGE_DIR_NAME` / `GAUGE_FILENAME_TEMPLATE` (~lines 140-164), each with the same comment style that explains why the value is what it is:
   - `OPT_OUT_MARKER_FILENAME = "context-guard-opt-out"` — with a comment stating this is a cross-skill contract read by the boundary guard, and that its mere existence is the signal (contents are advisory).
   - `CONFIG_DIR_ENV_VAR = "CLAUDE_CONFIG_DIR"`, `DEFAULT_CONFIG_DIR_NAME = ".claude"`, `SETTINGS_FILENAME = "settings.json"`.
   - `SELF_CHECK_SESSION_ID = "quo-setup-self-check"` — reserved by this subtask, consumed by the sibling install subtask; it must satisfy `SESSION_ID_RE`.

2. **New pure functions** (no printing, no `sys.exit`, no writes — same discipline as `classify_reading`, so the unit test layer can call them directly):
   - `opt_out_marker_path() -> Path` — `gauge_dir() / OPT_OUT_MARKER_FILENAME`. Resolves the tempdir at call time, exactly like `gauge_dir()`, so a redirected tempdir is honored.
   - `config_dir() -> Path` — the value of `CLAUDE_CONFIG_DIR` when set and non-empty, else `Path.home() / DEFAULT_CONFIG_DIR_NAME`. `Path.home()` covers `%USERPROFILE%` on Windows without per-OS branching.
   - `user_settings_path() -> Path` — `config_dir() / SETTINGS_FILENAME`.
   - `normalize_path_for_compare(value: str) -> str` — `os.path.normcase(os.path.normpath(...))` with backslashes folded to forward slashes, used for all script-path comparisons.
   - `to_command_path(path) -> str` — absolute path with `\` replaced by `/`, for embedding in a command string. Comment must cite the Git Bash backslash-consumption fact.
   - `classify_status_line_command(command, script_path) -> tuple` — returns `(state, wrapped_command)` where `state` is one of `"direct"`, `"wrapped"`, `"other-install"`, `"foreign"`. Implementation: `shlex.split(command, posix=True)` inside a `try`; on `ValueError` return `("foreign", None)` without guessing. Then: if some token normalizes equal to `script_path` and `"produce"` is among the tokens → `direct` or `wrapped` depending on whether a `--wrap-command` value is present (accept both `--wrap-command X` and `--wrap-command=X`); else if some token's basename is `context_gauge.py` and `"produce"` is present → `other-install`, still extracting any `--wrap-command` value; else → `foreign` with `wrapped_command` `None`. **Never parse a `foreign` command for anything** — it is carried as an opaque string.
   - `status_line_shell() -> str` — `"sh"` on POSIX; on Windows `"git-bash"` when `shutil.which("bash")` finds one, else `"powershell"`. Comment cites the docs sentence.
   - `quote_for_shell(value, shell)` and `compose_status_line_command(python_exe, script_path, wrap_command, shell)` — the pure command-composition pair specified in full in the sibling install subtask (t3.55r.9d.zk.1b item 1). They **land in this subtask** (which precedes the install subtask) because `inspect-statusline` needs them to compute `producer_current` below; implement them to the sibling's spec verbatim, and the sibling consumes them rather than re-implementing.
   - `detect_higher_precedence_sources(repo_root) -> list` — best-effort, never raises: each entry `{"scope": ..., "path": ..., "reason": ...}`. Checks `<repo_root>/.claude/settings.json` (scope `project`) and `<repo_root>/.claude/settings.local.json` (scope `local`) for a `statusLine` key; checks the per-OS managed file plus every `*.json` in the sibling `managed-settings.d/` for a `statusLine` key (scope `managed`), for `allowManagedHooksOnly` truthy, and for `disableAllHooks` truthy. Any file that is absent, unreadable, or unparseable is skipped silently — a malformed file belonging to someone else must not fail our inspection. **Testability requirement (test-lane pinned):** expose the per-OS managed-settings locations (the managed file paths and the `managed-settings.d/` sibling) as module-level constants or an injectable argument rather than hardcoding them inline — tests may never write to the real system paths, so this is the only way the managed-scope branches can be covered.

3. **New `inspect-statusline` subcommand**, registered in `main()` alongside `produce` and `read` (~lines 520-556). Signature: `inspect-statusline [--repo-root <path>]` (default: current working directory). Prints one compact JSON object on stdout and exits 0:

   ```json
   {"settings_path": "...", "settings_exists": true, "status_line_present": true,
    "status_line_command": "...", "status_line_extra_keys": {"padding": 2},
    "producer_state": "foreign", "wrapped_command": null,
    "producer_current": false,
    "script_path": "...", "python_executable": "...",
    "opt_out_marker_path": "...", "opt_out_marker_present": false,
    "higher_precedence_sources": [], "status_line_shell": "sh"}
   ```

   - `producer_state` is `"absent"` when there is no `statusLine` key, when it is not an object, or when its `command` is missing or not a non-empty string; otherwise the `classify_status_line_command` result.
   - `producer_current` is true only when `producer_state` is `direct` or `wrapped` AND the existing command string is byte-identical to the command that would be composed now (via `compose_status_line_command` with `sys.executable`, this script's resolved path, the extracted wrap payload, and `status_line_shell()` as the quoting-shell argument) — the same predicate the install subcommand's no-op check uses when no `--python` override is supplied; false in every other state. This is what lets the skill prose skip its gate only when nothing needs refreshing: an interpreter or path change flips it false even though the state is still `direct`/`wrapped`.
   - `status_line_extra_keys` carries every key of the existing `statusLine` object other than `type` and `command`, so the install subtask can preserve them.
   - `script_path` is `str(Path(__file__).resolve())` — the helper names itself; nothing is passed in (SR-3.5 own-skill resolution).
   - `python_executable` is `sys.executable`.
   - **A user settings file that exists but does not parse as a JSON object is the one hard failure:** return `fail(...)` (exit 2) with a single stderr line naming the path. Never report `absent` for an unparseable file — the install path keys off this state and would otherwise clobber a file it could not read.

4. **Module docstring.** Add an `inspect-statusline` block to the CLI-contract section describing the subcommand, its JSON keys, the five `producer_state` values, and the exit-0 / exit-2 split. Pin, explicitly, the value of `status_line_present` for degenerate `statusLine` shapes (non-object; missing, empty, or non-string `command`) — the test lane asserts against that pinned statement rather than encoding an unstated behavior. Add the opt-out marker path and its semantics (existence is the signal; the guard it suppresses is the missing-reading stop, not a genuine over-threshold stop) to the contract section next to the gauge-file path. State plainly which higher-precedence sources are detectable and which (`--settings` launch flag, server-managed settings, MDM plist/registry) are not.

5. **Do not change**: the `produce` or `read` subcommand names, `--wrap-command`, `--session-id`, the gauge path or field names, `STOP_THRESHOLD_PERCENT`, `FRESHNESS_WINDOW_SECONDS`, or any existing function's behavior.

**Portability constraints (mandatory).** Stdlib only. No PEP 604 unions anywhere in the file — the documented Python 3.9 floor (see the `classify_reading` docstring) governs, because this file runs under whatever interpreter the operator's status line resolves. New imports (`shlex`, `shutil`) are stdlib and cheap, but keep all new work inside functions: nothing new at module import time, since `produce` pays import cost on every status-line refresh. The file is a shipped artifact — no ticket ids, no Epic/Task references, no paths into this repo, no references to repo-only docs.

## Acceptance Criteria

- `opt_out_marker_path()` returns `<tempdir>/.quorum/context-guard-opt-out`, resolves the tempdir at call time (a monkeypatched `tempfile.gettempdir` is honored), and creates nothing.
- `user_settings_path()` returns `<CLAUDE_CONFIG_DIR>/settings.json` when that variable is set and non-empty, and `<home>/.claude/settings.json` otherwise.
- `classify_status_line_command` returns `direct` for a command naming this script's resolved path plus `produce` with no wrap flag; `wrapped` plus the exact wrapped payload string for one with `--wrap-command <x>`; `other-install` for a command naming a *different* path whose basename is `context_gauge.py` plus `produce`; and `foreign` with `None` for anything else, including a command string that `shlex.split` rejects.
- `classify_status_line_command` handles both `--wrap-command X` and `--wrap-command=X` spellings and returns the payload unquoted.
- `to_command_path` output contains no backslash on any platform.
- `inspect-statusline` exits 0 and prints one parseable JSON object when the settings file is absent, reporting `settings_exists` false and `producer_state` `"absent"`.
- `inspect-statusline` exits 2 with exactly one stderr line, and prints nothing on stdout, when the settings file exists but is not parseable JSON or is not a JSON object.
- `inspect-statusline` reports `status_line_extra_keys` containing `padding`, `refreshInterval`, and `hideVimModeIndicator` when the existing `statusLine` object carries them, and `{}` when it does not.
- `inspect-statusline` reports `opt_out_marker_present` true iff a file exists at `opt_out_marker_path()`, and it does not create the gauge directory as a side effect of looking.
- `producer_current` is reported true for a settings command byte-identical to the currently-composed command, false for a `direct`/`wrapped` command whose interpreter or path token differs, and false for every `absent`/`other-install`/`foreign` state.
- `quote_for_shell` and `compose_status_line_command` exist in this subtask's diff and satisfy the sibling install subtask's spec (round-trip and shape properties are pinned by the test lane).
- `higher_precedence_sources` contains an entry with scope `project` when `<repo-root>/.claude/settings.json` sets `statusLine`, and an entry with scope `local` when `.claude/settings.local.json` does; an absent, unreadable, or unparseable file at either path yields no entry and no failure.
- `inspect-statusline` writes nothing anywhere: after a run against a temp HOME with no settings file, no file and no directory has been created.
- `produce` and `read` are entirely unregressed: same subcommand names, same flags, same four `read` values, same exit codes, same gauge path and field names.
- The module docstring documents `inspect-statusline`, the opt-out marker path and what it does and does not suppress, and the detectable-vs-undetectable precedence sources.
- The project Lint command passes on the changed file, and the file remains free of PEP 604 union syntax.
