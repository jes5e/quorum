## Context

With detection in place (sibling subtask), this subtask adds the two mutating operations the quo-setup step invokes: writing or updating the user-settings `statusLine` so it runs the gauge producer (SR-3.1/SR-3.2/SR-3.5), and writing the persistent opt-out marker for an operator who chooses to run unguarded (SR-3.6). Both are single literal commands, because the skill prose that calls them is bound by CLAUDE.md `## Bash etiquette` and SDD SR-4.1.

The wrap-don't-replace rule is the delicate part: an operator's existing status line must survive, and a re-run must never nest one wrapper inside another. Task 1's post-fix `produce` is what makes wrapping safe to install at all — it now exits 0 on every input shape and re-emits the wrapped command's stdout on all of them, so the wrapper cannot be the cause of a blank display.

Preconditions: the sibling inspection subtask has landed, so `user_settings_path()`, `opt_out_marker_path()`, `classify_status_line_command()`, `to_command_path()`, `status_line_shell()`, and `SELF_CHECK_SESSION_ID` all exist.

## What Needs to Change

**`skills/quo-setup/scripts/context_gauge.py`**

1. **Command composition helpers** (pure, unit-testable). **These two helpers LAND with the sibling inspection subtask** (t3.55r.9d.zk.qx, which precedes this one and needs them for `producer_current`); this subtask CONSUMES them — verify they exist and match this spec rather than re-implementing. This spec is authoritative for their behavior:
   - `quote_for_shell(value: str, shell: str) -> str` — for `sh` and `git-bash`, `shlex.quote`; for `powershell`, wrap in single quotes with every inner `'` doubled. Comment must state which shell each branch targets and why the choice is made at install time (Claude Code runs the status-line command through Git Bash when present on Windows, PowerShell otherwise).
   - `compose_status_line_command(python_exe, script_path, wrap_command, shell) -> str` — returns `"<python>" "<script>" produce` with both paths passed through `to_command_path` and wrapped in **double** quotes, appending ` --wrap-command <quoted>` when `wrap_command` is non-empty. Double quotes on our own two tokens are deliberate: they are safe in `sh`, Git Bash, PowerShell, and `cmd.exe`, and with forward-slashed paths there is no backslash for Git Bash to consume.

2. **New `install-statusline` subcommand.** Signature: `install-statusline [--repo-root <path>] [--python <path>] [--no-self-check]`. Algorithm, in this order:
   1. Run the same inspection the sibling subtask implemented. If the settings file exists but does not parse, `fail(...)` (exit 2) and **write nothing** — never clobber a settings file we could not read.
   2. Determine the wrap payload: `producer_state` `foreign` → the entire existing command string, opaque; `wrapped` or `other-install` → the payload already extracted by `classify_status_line_command` (this is the anti-double-wrap step: the payload is reused, never re-wrapped); `direct` or `absent` → none.
   3. Compose the new command with `--python` (when given) or `sys.executable`, this script's resolved path, the payload, and `status_line_shell()`.
   4. If `producer_state` is `direct` or `wrapped` **and** the composed command equals the existing command byte for byte, take no action: print the summary with `"action": "already-configured"` and exit 0 without touching the file.
   5. Otherwise read-modify-write the settings file: `json.load` the existing object (or start from `{}` when the file is absent), set `statusLine` to `{"type": "command", "command": <composed>}` **merged over the existing `statusLine` object's other keys** so `padding`, `refreshInterval`, and `hideVimModeIndicator` survive, and leave every unrelated top-level key untouched. Create the config directory if absent. Write atomically: `tempfile.mkstemp` in the settings file's own directory, `json.dump(..., indent=2)`, a trailing newline, `os.replace`, and unlink the temp file on any exception — the same shape CONTRIBUTING.md `## Skill conventions` > *Structured file edits* prescribes and the `## Skill Paths` migration in the quo-setup prose already uses.
   6. Self-check, unless `--no-self-check`: run the composed command string through the platform shell (reuse the `run_wrapped` pattern — `shell=True`, `WRAPPED_COMMAND_TIMEOUT_SECONDS`) feeding it a synthetic payload `{"session_id": SELF_CHECK_SESSION_ID, "context_window": {"used_percentage": 0}, "workspace": {"current_dir": "<cwd>"}}`, then check that `gauge_path(SELF_CHECK_SESSION_ID)` exists and was written within the last few seconds. Record the outcome; **never fail the install on a failed self-check** — the settings write already happened and reverting it would be worse than reporting it.
   7. Print one compact JSON summary on stdout and exit 0:

      ```json
      {"action": "installed"|"wrapped"|"repointed"|"already-configured",
       "settings_path": "...", "previous_command": "..."|null, "new_command": "...",
       "preserved_status_line_keys": ["padding"],
       "self_check": {"verified": true, "detail": "..."},
       "higher_precedence_sources": [], "status_line_shell": "sh"}
      ```

      `previous_command` is load-bearing: it is the only record of what the operator had before, and the skill prose surfaces it so a manual restore is possible. There is deliberately no backup file — atomic replace plus key preservation plus this echo is the recovery story, and writing an undeletable backup into the operator's config directory is not.

      **`action` selection mapping (explicit contract — record it in the module-docstring contract block):** `producer_state` `absent` → `installed`; `foreign` → `wrapped`; `other-install` → `repointed`; `direct` or `wrapped` whose recomposed command is NOT byte-identical to the existing one → `repointed`; byte-identical → `already-configured`. The test lane asserts these values concretely; do not leave any state's action implicit.

3. **New `write-opt-out` subcommand.** No arguments. Creates `<tempdir>/.quorum/` if absent (reuse `ensure_gauge_dir()`), then truncate-writes `opt_out_marker_path()` with a short human-readable body stating what the marker suppresses (the missing-reading stop only — never a genuine over-threshold stop) and that deleting this file re-enables the guard. Idempotent: a second run rewrites the same content and reports the same result. Prints the marker path and exits 0. **No removal path exists and none may be added** — the file's standing invariant is that this helper never deletes anything.

4. **Module docstring.** Add `install-statusline` and `write-opt-out` blocks to the CLI-contract section: flags, the four `action` values, the anti-double-wrap rule, the never-clobber-an-unparseable-settings-file rule, the self-check's advisory (non-fatal) status, and the fact that the opt-out marker has no removal command by design. Pin, explicitly, the exact shape of the summary's `self_check` field when `--no-self-check` is used — the test lane asserts against that pinned statement rather than encoding an unstated behavior. Add a short decision record covering: why the interpreter is `sys.executable` rather than a bare `python3`/`python` token; why every path in the composed command is forward-slashed; and why quoting style is chosen from the detected status-line shell.

5. **Do not change**: `produce`, `read`, `write_gauge`, `classify_reading`, `run_wrapped`'s existing behavior, the gauge path or field names, or any existing flag or subcommand name.

**Portability constraints (mandatory).** Stdlib only; no PEP 604 unions; no new module-import-time work. Shipped artifact — no ticket ids, no Epic/Task references, no paths into this repo, no references to repo-only docs.

## Acceptance Criteria

- On a temp HOME with no settings file, `install-statusline` creates the config directory and a settings file whose only key is `statusLine`, set to `{"type": "command", "command": ...}`, and reports `"action": "installed"` with `previous_command` `null`.
- The composed `command` contains no backslash on any platform, names `sys.executable` (or `--python`'s value) and this script's resolved path, and ends with the `produce` token when nothing is being wrapped.
- Against a settings file carrying an unrelated top-level key and an existing foreign `statusLine` with `padding` set, `install-statusline` reports `"action": "wrapped"`, preserves the unrelated top-level key byte for byte, preserves `padding` inside the rewritten `statusLine` object, echoes the foreign command as `previous_command`, and produces a command whose `--wrap-command` value round-trips through `shlex.split` back to that exact foreign command string.
- Running `install-statusline` twice in a row leaves an identical settings file, and the second run reports `"action": "already-configured"` and performs no write (verified by an unchanged file modification time).
- Running `install-statusline` against a settings file already carrying a wrapped producer whose script path differs (simulating a moved install) reports `"action": "repointed"`, and the resulting command contains exactly one `produce` token and exactly one `--wrap-command` flag — the previously wrapped payload is reused, not nested.
- `install-statusline` against a settings file containing invalid JSON exits 2 with one stderr line and leaves that file byte-identical.
- `install-statusline` writes settings atomically: no partial file is observable, and a temp file left in the settings directory after a successful run is absent.
- `install-statusline --no-self-check` performs no subprocess spawn; without the flag, the summary's `self_check.verified` is true when the composed command genuinely writes a gauge for `SELF_CHECK_SESSION_ID`, and false with a non-empty `detail` when it does not — and in the false case the settings write still stands and the exit code is still 0.
- The module docstring records the explicit `producer_state` → `action` mapping (absent→installed, foreign→wrapped, other-install→repointed, direct/wrapped-non-identical→repointed, byte-identical→already-configured).
- `write-opt-out` creates `<tempdir>/.quorum/` when absent, writes `context-guard-opt-out` there, exits 0, prints the path, and is idempotent across repeated runs.
- The opt-out marker's contents state that it suppresses only the missing-reading stop and that deleting the file re-enables the guard.
- No new code path in the file deletes any file or directory.
- `produce` and `read` are entirely unregressed, including `produce`'s post-Task-1 always-exit-0 behavior and `read`'s four-value vocabulary.
- The project Lint command passes and the file remains free of PEP 604 union syntax.
