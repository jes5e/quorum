## Context

Wires the Epic 1 producer into the operator's environment via `/quo-setup`, so ordinary machines get the gauge without manual configuration, and operators with an existing status line keep their display. Depends on Epic 1 (the helper must exist to point the status line at it).

Authoritative spec: Spec Bee **b.8sh** → SDD `## Requirements` SR-3, and the quo-setup structure notes in `## Codebase exploration findings` (the optional PRD/SDD-bootstrap section is the precedent for an optional, AskUserQuestion-gated setup step; quo-setup writes no `settings.json` today).

## What Needs to Change

- Add a new OPTIONAL, `AskUserQuestion`-gated step to `skills/quo-setup/SKILL.md` (modeled on the optional Bootstrap-PRD/SDD section, slotted in the slow path near `### Build Commands` / `### Next Steps`) that offers to configure the producer by writing/updating the user-settings `statusLine` command to point at `context_gauge.py produce` (own-skill path resolution).
- **Wrap-don't-replace**: when a `statusLine` command already exists, configure `produce --wrap-command "<existing command>"` so the operator's current display is preserved.
- **Pinned-environment caveat**: recognize that where a higher-precedence settings source pins `statusLine` (e.g. a `--settings` wrapper), a user-settings write cannot win; say so and point at the published file contract rather than writing an ineffective setting.
- **Activation caveat**: state that status-line config loads at session start, so the producer activates from the next session (mirror the existing "restart / run `/agents`" subagents caveat).
- Decide and document whether the fast path (`### Fast-path detection`) offers this step or only the slow path.
- Fold the setup-facing documentation for this step into this Epic (the how-to-enable and the caveats).

## Deferred from /quo-execute run (2026-08-18 21:18)

From Epic 1's PM review (t2.55r.ec.wa): under `--wrap-command`, `produce` blanks the operator's wrapped status line on two input shapes — non-empty unparseable stdin (exit 2, wrapped command never runs, no display) and empty stdin (exit 0, no display). Spec-conformant today, but in tension with the wrap-don't-replace promise (SR-1.4) and the helper's own "a blank status line beats a broken one" philosophy: a harness payload-schema change would silently blank every wrapped operator's display. Fix paths surfaced: (a) trivial-tweak [PM-preferred] — emit the wrapped display (feeding the captured stdin bytes) before returning the exit-2 failure; (b) refactor-locally — treat unparseable stdin as a no-op exit 0, matching the empty-stdin path. This Epic's end-to-end status-line validation is the right place to decide and implement. Note the current behavior is documented in the README (`### The context-usage gauge file`) and `docs/doc-writing-guide.md` (`## The context-gauge file contract`), and pinned by `tests/test_context_gauge.py` — a behavior change must update all three in lockstep.
