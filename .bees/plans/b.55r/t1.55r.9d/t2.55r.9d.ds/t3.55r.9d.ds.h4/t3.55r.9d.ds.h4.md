## Context

`context_gauge.py`'s 107-line module docstring is the source-of-truth CLI contract that the customer-facing docs and the doc-writing guide's contract section mirror. Three of its blocks describe behavior that the control-flow change invalidates, and the file also carries inline comments that will read as stale or contradictory afterward. Because the helper is a shipped artifact that lands in unrelated projects on install, this documentation is the ONLY place a downstream operator can read the wrap semantics from the code itself.

The Task additionally requires a decision record — which fix path was taken and why — to live in the diff rather than only in the conversation. The module docstring is the source-lane home for it; the customer-facing docs and the doc-writing guide are the doc-writer lane's, and this subtask must not edit those.

Preconditions: the control-flow change from the sibling subtask is in place, so the described behavior is real rather than aspirational.

## What Needs to Change

**`skills/quo-setup/scripts/context_gauge.py` — module docstring**

1. **Producer-mode block (`context_gauge.py:20-32`).** The `--wrap-command` bullet currently promises only that the captured payload is fed to `<cmd>` on the success path. Extend it to state the transparency rule plainly: when `--wrap-command` is given, the wrapped command is invoked on EVERY refresh with exactly the bytes that arrived on stdin — including empty bytes and bytes that did not parse — and its stdout is re-emitted verbatim. State the honest limit of the promise: `produce` cannot guarantee a non-blank display, because the wrapped command may print nothing for a given input; what it guarantees is that `produce` itself never causes the blank. State the second limit as well: the always-emit guarantee is about the wrap path — without `--wrap-command`, an empty or unparseable payload yields an empty default display (there is no payload to derive one from) and the harness will blank the line on empty output; that display is `produce`'s own and is legitimately empty.

2. **Exit codes block (`context_gauge.py:85-91`).** It currently says exit `2` covers "an unreadable or non-conforming gauge file, or an argparse usage error". Rewrite so the split is stated per subcommand: `produce` returns `0` on every input shape (its only non-zero exit is an argparse usage error, raised before `cmd_produce` runs); `read` keeps the existing exit-0-for-all-four-values / exit-2-on-malformed-gauge contract unchanged. Add the diagnostic note: an unparseable stdin payload writes one line to stderr and still exits `0`.

3. **Invariants block (`context_gauge.py:93-106`).** Add a new invariant bullet for display transparency: under `--wrap-command`, no input-parse outcome may skip invoking the wrapped command or skip emitting its stdout, and `produce` must never return non-zero on the wrap path. Include the reason, which is the load-bearing external fact: the harness blanks the status line when a status-line command exits non-zero OR produces no output (Claude Code status-line documentation, Troubleshooting > "Script errors or hangs", https://code.claude.com/docs/en/statusline). Without that sentence the single-exit shape looks like a style choice and a future edit will undo it.

4. **Decision record.** Add a short block (in the Invariants area or immediately after the Producer-mode block) recording: the two input shapes that previously blanked a wrapped display; that the alternative of emitting the display while still exiting non-zero was rejected because the harness blanks on the exit code regardless (with the doc citation); that the malformation signal is retained as a stderr line rather than an exit code; and that the compensating detection for a genuinely stopped or drifting producer rests on `read`'s `missing`/`stale` routing — phrase it as resting on that routing (a dependency), not as an unconditional guarantee; on a mid-session payload drift the gauge file already exists, so the surviving classification is `stale`. Keep it to a paragraph or a few bullets — this is a rationale note, not a changelog. Depth ownership: the module docstring carries exactly what this Subtask's own criteria require — the invariant, the harness fact with its URL, both previously-blanking input shapes, the retained stderr signal, a one-line rejection rationale, and the read-routing dependency; the fuller rejected-alternative and accepted-tradeoff discussion is reserved to the contributor guide (doc lane). Neither surface cross-references the other.

**`skills/quo-setup/scripts/context_gauge.py` — inline comments**

5. **`cmd_produce` body.** The old comment at `context_gauge.py:371-373` ("Nothing arrived on stdin. Not an error, and nothing to display.") is now wrong on its second clause and must go. Replace the comment set so it explains: why the `except ValueError` branch warns instead of returning; why the display tail is unconditional; and why the function has a single exit. Keep the existing ordering comment (`context_gauge.py:377-379`) and the no-usable-session-id comment (`context_gauge.py:381-383`) — the latter is the principle the change generalizes, so tie the new tail comment back to it rather than duplicating it.

6. **`run_wrapped` docstring (`context_gauge.py:313-334`).** Its closing line, "a blank status line beats a broken one" (`context_gauge.py:330`), is about a wrapped command that fails on its own and stays correct — but it now sits next to a rule that says `produce` must not blank the line itself. Add a clause distinguishing the two: `produce` never blanks the display of its own accord; a blank that originates in the wrapped command's own failure or silence is passed through as-is.

7. **`read_stdin_once` docstring (`context_gauge.py:214-231`).** Its warning that a second read "would come back empty and silently blank out a wrapped operator status line" stays true and stays valuable — leave the rule intact, and check only that its wording does not contradict the new empty-stdin disposition (empty captured bytes are now replayed to the wrapped command rather than short-circuiting).

**Portability constraint (mandatory).** This file ships to unrelated projects on install. The new prose must be project-neutral: no ticket identifiers, no Epic or Task references, no paths into this repo, no reference to this repo's docs or `CLAUDE.md` sections. Cite the external Claude Code documentation URL and describe behavior in terms of the helper itself. Do not add any shell snippet to the docstring; if an example is unavoidable it must ship as paired POSIX + PowerShell blocks.

**Out of scope for this subtask (other lanes):** the customer-facing docs' gauge-contract section and the doc-writing guide's `produce` paragraph — the latter's current text ("emits no display at all, so the harness sees a non-zero exit and a blank status line") is the sentence that most directly describes the removed behavior, but it belongs to the doc-writer lane. Likewise `tests/test_context_gauge.py`.

- `run_wrapped`'s docstring distinguishes a blank originating in the wrapped command (passed through) from a blank originating in `produce` (must never happen).
- No added prose references a ticket id, an Epic/Task, this repo's paths, or a repo-only document; no bash-only shell snippet is introduced.
