## Context

Epic 1 (t1.55r.ec, done) shipped the bundled gauge helper with a `produce` subcommand whose `--wrap-command <cmd>` option preserves an operator's existing status-line display (wrap-don't-replace, SDD SR-1.4). Epic 1's PM review surfaced a defect-in-tension, encoded as a deferral on this Epic's body: under `--wrap-command`, `produce` blanks the operator's wrapped status line on two input shapes — (i) non-empty unparseable stdin (exit 2; the wrapped command never runs, so no display is emitted) and (ii) empty stdin (exit 0, no display). This is spec-conformant today but violates the wrap-don't-replace promise in spirit and the helper's own "a blank status line beats a broken one" philosophy: a harness payload-schema change would silently blank every wrapped operator's display.

This Task decides and implements the fix. It runs first in this Epic so the wrap semantics are stable before Task 2 writes the quo-setup step prose that describes them and Task 3 documents them.

## What Needs to Change

- Decide between the two fix paths surfaced by the Epic 1 PM review:
  - (a) trivial-tweak [PM-preferred at the time of that review] — on unparseable non-empty stdin, emit the wrapped display (feeding the captured stdin bytes to the wrapped command) before returning the exit-2 failure;
  - (b) refactor-locally — treat unparseable stdin as a no-op exit 0, matching the empty-stdin path.
- Whichever path is chosen, both blanking shapes must be explicitly dispositioned: state what the empty-stdin case does to the wrapped display as well, not only the unparseable case. The decision record (choice + why) belongs in the diff's documentation updates, not only in the conversation.
- The gauge-write semantics, the four `read` classifications, and all non-wrap behavior of the helper must be unchanged.
- Lockstep rule (stated in the deferral): the behavior change must update the helper, its test file, the customer-facing docs' gauge-file contract section, and the doc-writing guide's contract section together — the current behavior is documented in all of them and pinned by the existing tests.

## Why

A producer whose failure mode is "blank the operator's own display" converts any upstream payload-schema drift into a silent, environment-wide status-line outage for wrapped operators. Fixing it before the quo-setup step ships (Task 2) means the step never installs a wrapper with the known-bad failure mode.

## Cross-Task / cross-Epic contract

- Task 2 (the quo-setup step) describes the wrap behavior in its step prose and installs `--wrap-command` wrappers; it depends on this Task and must match the post-fix semantics. Reviewers should cross-check Task 2's prose against this Task's implemented behavior.
- The gauge-file contract (path + field names) is a protected cross-skill string contract consumed by Epic 3 (t1.55r.h9) — this Task must not rename or reshape it.

## Success Criteria

- Under `--wrap-command`, no producer-side input-parse failure blanks the wrapped display: the two previously-blanking shapes (non-empty unparseable stdin; empty stdin) each have an explicit, tested disposition consistent with the chosen fix path.
- Gauge-write semantics (overwrite-per-refresh, session-keyed filename, no-op on absent session_id, never delete) and the `read` subcommand's four-value vocabulary are unchanged.
- The test suite covers both former blanking shapes and passes under the project Full test command; Lint is clean.
- The customer-facing docs' gauge-contract section and the doc-writing guide's contract section describe the post-fix behavior; no doc still describes the blanking behavior.
