**Fix-path resolution (orchestrator note, 2026-08-18):** the implementation subtask for this Task implements refined path (b) — `produce` exits `0` on every input shape, always emits the display, and downgrades the unparseable-stdin `fail()` to a stderr-only `warn()`. Path (a) (emit-then-exit-2) was rejected because the harness blanks the status line on any non-zero exit regardless of stdout (verified against https://code.claude.com/docs/en/statusline: "Scripts that exit with non-zero codes or produce no output cause the status line to go blank"). Wherever the body below states per-path expectations, the path-(b) expectation applies; still verify against the landed diff rather than assuming.

## Context

The Task's path-independent invariant is: **under `--wrap-command`, both former blanking shapes emit the wrapped command's display output.** Today nothing in `tests/test_context_gauge.py` exercises `--wrap-command` together with either shape — every existing wrap test (`test_cli_produce_wrap_command_passthrough_is_byte_exact` at 1016, `test_cli_produce_wrap_command_receives_the_captured_stdin` at 1039, `test_cli_produce_broken_wrap_command_still_writes_the_gauge` at 1063) feeds a well-formed payload. So the defect this Task fixes could regress with the whole suite green. This Subtask adds the coverage in both layers required by `docs/test-writing-guide.md` `## The two-layer pattern`.

Preconditions: the implementation Subtask has landed and the chosen fix path ((a) display-then-exit-2, or (b) no-op-exit-0) is known; the sibling Subtask has already updated the existing pins, so this Subtask only adds tests. Path (b) is the implemented path (see the orchestrator note above); path-(a) values below are SUPERSEDED and retained for history only — assert the path-(b) value exactly, never a loose `in (0, 2)`.

## What Needs to Change

Add to `tests/test_context_gauge.py`. Reuse the module's existing helpers — `_run` (851), `_stub` (861), `_env_with_tempdir` (837), `_gauge_files` (894), `TEST_SESSION_PREFIX` (72) — and honor `docs/test-writing-guide.md` `## Fixtures and isolation rules`: `tmp_path` for all I/O, copied env for subprocesses, Python stubs invoked via `sys.executable` (never system `echo`), no sleeps, `monkeypatch` for anything on `mod.*`. None of these tests writes a gauge file, so no session-id prefix is needed for them, but any payload they do carry a `session_id` in must still use `TEST_SESSION_PREFIX`.

**CLI-contract layer (new section under `# --- produce: the display ---`).**

1. `test_cli_produce_unparseable_stdin_with_wrap_emits_the_wrapped_display` — `stdin="{not json"`, `--wrap-command` pointing at a marker stub (`_stub`, writing a marker with no trailing newline, as at 1016-1022). Assert `res.stdout == marker` byte-exactly; assert exit code `0` (path (b) is implemented; the path-(a) value 2 is superseded); assert `_gauge_files(tmp_path) == []` and `not (tmp_path / ".quorum").exists()`. This is the single most important new test in the Task — it is the direct inverse of the shipped defect.
2. `test_cli_produce_unparseable_stdin_with_wrap_replays_the_captured_bytes` — same shape, but with the echo-stdin stub from 1041-1045. Assert the stub's stdout is byte-identical to the exact non-JSON bytes fed in (`res.stdout == "{not json"`). This proves the failure path replays the once-captured bytes rather than re-reading a drained pipe — the failure mode `read_stdin_once`'s docstring (helper lines 214-231) warns about, and the one a naive fix reintroduces.
3. `test_cli_produce_non_object_json_with_wrap_emits_the_wrapped_display` — parametrized over `["[1, 2]", "42", '"a string"', "null", "true"]` with ids matching the existing `test_parse_payload_non_object_top_level_raises` (354-360). These take the same `ValueError` branch as case 1 and must get the identical disposition; without this, a fix that special-cases only `json.JSONDecodeError` and not the `not isinstance(payload, dict)` raise would leave half the shape blanking.
4. `test_cli_produce_empty_stdin_with_wrap_emits_the_wrapped_display` — `stdin=""`, marker stub. Assert `res.stdout == marker`, `returncode == 0` (both paths), `res.stderr == ""`, `_gauge_files(tmp_path) == []`, `not (tmp_path / ".quorum").exists()`. This is the shape the Task body requires be explicitly dispositioned rather than left implicit.
5. `test_cli_produce_whitespace_only_stdin_with_wrap_emits_the_wrapped_display` — parametrized over `["   ", "
", " 	\r
 "]`. `parse_payload` classifies whitespace-only input as empty (helper lines 243-245), so these must follow case 4, not case 1. Assert the same tuple as case 4.
6. `test_cli_produce_broken_wrap_command_on_a_blanking_shape_does_not_crash` — parametrized over `kind in ("nonzero", "missing")` crossed with `stdin in ("{not json", "")`, reusing the fail-stub / nonexistent-path construction at 1067-1069. Assert `res.stdout == ""`, the implemented path's exit code, and that stderr contains no `Traceback`. This guards the fix against routing the failure path around `run_wrapped`'s tolerance (helper lines 335-348) and turning a broken operator command into a producer crash on every refresh.

**Unit layer (new section under `# --- run_wrapped failure tolerance ---`).** Call `mod.cmd_produce` in-process with `types.SimpleNamespace(wrap_command=...)`, `monkeypatch.setattr(mod.sys, "stdin", <stub with a .buffer.read()>)` (the `_Stdin` / `_Buffer` idiom at 409-433), `_patch_tempdir(monkeypatch, tmp_path)`, and `monkeypatch.setattr(mod, "run_wrapped", recorder)` where `recorder` appends `(command, stdin_bytes)` and returns a sentinel display. Capture stdout with `capsys`.

7. `test_cmd_produce_unparseable_stdin_runs_the_wrapped_command_with_the_captured_bytes` — stdin buffer returns `b"{not json"`. Assert the recorder was called exactly once, `recorded == [("the-cmd", b"{not json")]` (byte-exact), `capsys.readouterr().out == sentinel`, and `cmd_produce`'s return value equals the implemented path's exit code.
8. `test_cmd_produce_empty_stdin_runs_the_wrapped_command` — stdin buffer returns `b""`; same assertions with `recorded == [("the-cmd", b"")]` and return value `0`.
9. `test_cmd_produce_blanking_shapes_drain_stdin_exactly_once` — parametrized over `b"{not json"` and `b""`, with a counting buffer whose `read()` returns the payload on the first call and `b""` afterwards. Assert the call count is exactly 1. A second drain returns nothing and would silently blank the wrapped display — the exact regression `read_stdin_once` exists to prevent.
10. `test_cmd_produce_blanking_shapes_without_wrap_do_not_run_a_wrapped_command` — parametrized over the same two payloads with `wrap_command=None`. Assert the recorder was never called and `capsys` stdout is `""`. This is the contrast case that keeps tests 7-9 from passing vacuously and pins that the unwrapped disposition is unchanged.
11. `test_cmd_produce_blanking_shapes_write_no_gauge` — parametrized over both payloads, with and without `wrap_command`; assert `not (tmp_path / ".quorum").exists()` after the call. Pins the Success Criterion that gauge-write semantics are unchanged by the fix.

## Acceptance Criteria

- A CLI test exists in which `produce --wrap-command <stub>` is fed `"{not json"` and asserts `res.stdout` equals the stub's marker byte-exactly; it fails if the wrapped command is skipped.
- A CLI test exists in which `produce --wrap-command <stub>` is fed empty stdin and asserts `res.stdout` equals the stub's marker byte-exactly.
- A CLI test asserts the wrapped command receives the raw non-JSON stdin bytes verbatim (`res.stdout == "{not json"` via the echo-stdin stub).
- Non-object top-level JSON (`[1, 2]`, `42`, `"a string"`, `null`, `true`) is covered by a parametrized test with the same disposition as `"{not json"`.
- Whitespace-only stdin is covered and dispositioned with the empty-stdin case, not the unparseable case.
- Every new test asserts an exact exit code matching the implemented fix path — no `in (0, 2)`, no unasserted `returncode`.
- Every new test asserts no gauge file is produced (`_gauge_files(tmp_path) == []` at the CLI layer, `not (tmp_path / ".quorum").exists()` at both layers).
- Unit-layer tests assert `run_wrapped` is called exactly once with the byte-exact captured stdin on both shapes when `wrap_command` is set, and never called when it is not.
- A unit-layer test proves stdin is drained exactly once on both shapes.
- A broken wrap command (non-zero exit and missing binary) on both shapes yields empty stdout, the implemented path's exit code, and no `Traceback` in stderr.
- All existing `read`, `classify_reading`, `write_gauge`, and safety-fixture tests are unmodified and still pass.
- `python -m pytest tests/test_context_gauge.py` passes while iterating, and `python -m pyflakes tests/test_context_gauge.py` is clean.
