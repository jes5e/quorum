## Context

Under `--wrap-command`, `produce` currently blanks the operator's wrapped status line on two input shapes, because two of `cmd_produce`'s three exits return before the display block is ever reached:

- `context_gauge.py:366-369` — non-empty unparseable stdin returns `fail(...)` (exit 2).
- `context_gauge.py:371-373` — empty/whitespace stdin returns `0` with no display.
- `context_gauge.py:385-388` — the display block, reached only on the success path.

The third no-payload case is already handled correctly and is the precedent this subtask generalizes: a payload with no usable `session_id` writes no gauge but deliberately falls through to the display block, with the rationale stated inline at `context_gauge.py:381-383` ("the operator's status line does not get to go blank just because this refresh had no session context").

The decisive external fact, which the fix path must respect: Claude Code's status-line documentation states under Troubleshooting > "Script errors or hangs" that "Scripts that exit with non-zero codes or produce no output cause the status line to go blank" (https://code.claude.com/docs/en/statusline). Emitting the wrapped display while still returning exit 2 therefore does NOT preserve the display — the harness blanks it on the exit code alone. The chosen fix must exit 0 whenever a display is emitted. (Verified by the orchestrator against the live docs page, 2026-08-18: the quoted sentence appears verbatim. This falsifies fix path (a) from the Epic-body deferral; this Task implements the refined path (b) below.)

Preconditions: the helper as shipped by Epic 1. This subtask changes ONLY `cmd_produce`'s control flow and adds one small stderr helper; it does not touch `write_gauge`, `extract_gauge_record`, `classify_reading`, `cmd_read`, or `main`'s argparse wiring.

## What Needs to Change

**`skills/quo-setup/scripts/context_gauge.py`**

1. **Add a `warn(message: str) -> None` helper next to `fail()` (`context_gauge.py:179-181`).** It prints one human-readable line to `sys.stderr` and returns nothing — deliberately distinct from `fail()`, which prints the same shape and returns exit code 2. Do not modify `fail()`; `cmd_read` still uses it and its exit-2 contract is unchanged.

2. **Restructure `cmd_produce` (`context_gauge.py:361-389`) so that display emission is a single unconditional tail step reached by every path.** Target shape:

   ```python
   def cmd_produce(args) -> int:
       captured = read_stdin_once()

       try:
           payload = parse_payload(captured)
       except ValueError as error:
           warn(f"unreadable status-line payload on stdin: {error}")
           payload = None

       if payload is not None:
           record = extract_gauge_record(payload)
           if record is not None:
               write_gauge(record)

       if args.wrap_command:
           emit_display(run_wrapped(args.wrap_command, captured))
       else:
           emit_display(default_display(payload))
       return 0
   ```

   Load-bearing details:
   - The `except ValueError` branch no longer returns. It records the diagnostic via `warn(...)` and normalizes `payload` to `None`, so an unparseable payload joins the empty-stdin path rather than short-circuiting.
   - `cmd_produce` now has exactly ONE `return` statement, and it returns `0`. That single-exit shape is the structural guarantee that no future edit can reintroduce a path that skips the display; keep it that way rather than adding early returns back.
   - The gauge-write block must stay ABOVE the display tail. The existing ordering comment at `context_gauge.py:377-379` ("publish the gauge BEFORE running the wrapped command, so a slow or failing wrapped command cannot cost this refresh its reading") remains correct and must survive the restructure.
   - `default_display(None)` already returns `""` — its `isinstance(payload, dict)` guard at `context_gauge.py:300-301` handles `None` without a new branch. Do not add a `None` special case; the existing guard is what keeps the non-wrapped paths byte-identical to today.

3. **Do not change** the `--wrap-command` flag name, the `produce`/`read` subcommand names, the gauge path, the JSON field names, `WRAPPED_COMMAND_TIMEOUT_SECONDS`, or any `read`-side behavior. These are the protected cross-skill string contract.

**Resulting behavior matrix** (this is the explicit disposition of both former blanking shapes, and it is what the test and doc lanes will pin):

| stdin | `--wrap-command` | exit | stdout | stderr | gauge write |
|---|---|---|---|---|---|
| valid payload | given | 0 | wrapped cmd's stdout, verbatim | empty | yes (if usable `session_id`) |
| valid payload | omitted | 0 | default display | empty | yes (if usable `session_id`) |
| empty / whitespace | given | 0 | wrapped cmd's stdout given the captured (empty) bytes | empty | none |
| empty / whitespace | omitted | 0 | `""` | empty | none |
| non-empty unparseable | given | 0 | wrapped cmd's stdout given the captured bytes | one line | none |
| non-empty unparseable | omitted | 0 | `""` | one line | none |

Note what shape (ii) does and does not promise: on empty stdin the wrapped command is invoked and its stdout re-emitted, so the display may still come out blank if the operator's own command prints nothing on empty input. That is the correct outcome — it is exactly what the harness would have shown without the wrapper. `produce` guarantees only that it never causes the blank itself.

Every non-wrapped cell above is byte-identical to today's behavior (same exit code, same empty stdout), so the blast radius is confined to the `--wrap-command` path plus the exit code on unparseable stdin.

## Key Files

- `skills/quo-setup/scripts/context_gauge.py` — add `warn()` beside `fail()` (~line 179); restructure `cmd_produce` (lines 361-389) to a single-exit, always-emit shape returning 0.

## Acceptance Criteria

- `cmd_produce` contains exactly one `return` statement and it returns `0`; no call to `fail()` remains anywhere in the produce path.
- A `warn(message)` function exists, prints exactly one line to `sys.stderr`, and returns `None`. `fail()` is unmodified and still returns `2`.
- `produce --wrap-command <cmd>` with non-empty unparseable stdin (e.g. `{not json`) exits `0`, prints the wrapped command's stdout verbatim on stdout, prints exactly one line on stderr, and writes no gauge file.
- `produce --wrap-command <cmd>` with empty stdin exits `0`, invokes the wrapped command with empty stdin bytes, prints that command's stdout verbatim, prints nothing on stderr, and writes no gauge file.
- `produce` with no `--wrap-command` is unchanged on both shapes: empty stdin exits `0` with empty stdout and empty stderr; unparseable stdin exits `0` with empty stdout and exactly one stderr line (the exit code is the only observable delta from today).
- `produce --wrap-command <cmd>` with a valid payload still writes the gauge file with the payload's `context_window` carried through verbatim, and still re-emits the wrapped command's stdout byte for byte (no added or stripped trailing newline).
- A wrapped command that exits non-zero, cannot spawn, or times out still yields exit `0` from `produce` and still leaves the gauge written — `run_wrapped`'s failure tolerance is unregressed.
- The gauge write still happens before the wrapped command runs.
- `read` is entirely unregressed: its four-value vocabulary (integer / `no-reading` / `stale` / `missing`), its exit-0-for-all-four rule, and its exit-2-on-malformed-gauge rule all behave as before.
- The project Lint command passes on the changed file, and the file remains free of PEP 604 union syntax (the Python 3.9 interpreter floor documented at `context_gauge.py:408-414`).
