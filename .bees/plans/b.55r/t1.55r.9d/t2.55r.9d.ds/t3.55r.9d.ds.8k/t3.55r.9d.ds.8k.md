**Fix-path resolution (orchestrator note, 2026-08-18):** the implementation subtask for this Task implements refined path (b) — `produce` exits `0` on every input shape, always emits the display, and downgrades the unparseable-stdin `fail()` to a stderr-only `warn()`. Path (a) (emit-then-exit-2) was rejected because the harness blanks the status line on any non-zero exit regardless of stdout (verified against https://code.claude.com/docs/en/statusline: "Scripts that exit with non-zero codes or produce no output cause the status line to go blank"). Wherever the body below states per-path expectations, the path-(b) expectation applies; still verify against the landed diff rather than assuming.

## Context

Epic 1 shipped `skills/quo-setup/scripts/context_gauge.py` with two branches in `cmd_produce` (lines 361-389) that blank a wrapped operator's status line: the `except ValueError` branch at lines 366-369 (non-empty unparseable stdin -> `fail(...)`, exit 2, wrapped command never runs) and the `if payload is None` branch at lines 371-373 (empty stdin -> `return 0` with no display). Three tests in `tests/test_context_gauge.py` currently pin that behavior and will either fail or keep the old contract alive once this Task's implementation Subtask lands. They must be updated in the same change (the Task body's lockstep rule).

Preconditions: the implementation Subtask for this Task has landed and the chosen fix path is known — **(a)** emit the wrapped display, then still return exit 2, or **(b)** treat unparseable stdin as a no-op exit 0 matching the empty-stdin path. Expected exit codes below are stated per path; do not guess.

This Subtask only touches tests that ALREADY exist. New coverage for the wrapped shapes is the sibling Subtask's job.

## What Needs to Change

**`tests/test_context_gauge.py:994-998` — `test_cli_produce_unparseable_stdin_exits_2` (CLI layer).** This is the primary pin of blanking shape (i). It runs `produce` with `stdin="{not json"` and **no** `--wrap-command`, asserting `returncode == 2`, a single stderr line, and `_gauge_files(tmp_path) == []`.
- Under path (a) — SUPERSEDED (path (b) shipped; retained for history only, do not implement): the exit code and the single-stderr-line assertion stay as they are. Add an explicit `assert res.stdout == ""` so the test states the unwrapped disposition rather than leaving stdout unasserted, and add a docstring naming the wrapped counterpart (the sibling Subtask's test) so a reader knows where the non-blanking guarantee is pinned.
- Under path (b) — the implemented path: rename to `test_cli_produce_unparseable_stdin_without_wrap_exits_0_and_warns` (the current name encodes `exits_2` and would lie; the new name keeps the `_without_wrap` scoping used for the empty-stdin sibling and reflects that the case is not a full no-op — the implementation retains the malformation diagnostic). Change to `assert res.returncode == 0` and assert the retained diagnostic exactly: exactly one line on stderr — not empty, and not loosely matched.
- Under BOTH paths: keep `_gauge_files(tmp_path) == []` and additionally assert `not (tmp_path / ".quorum").exists()` — `ensure_gauge_dir()` is only reached from `write_gauge`, so a failure path that starts creating the directory is a behavior change worth catching.

**`tests/test_context_gauge.py:986-991` — `test_cli_produce_empty_stdin_is_a_silent_noop` (CLI layer).** This pins blanking shape (ii), but only for the **unwrapped** invocation (it passes no `--wrap-command`). Its assertions (`returncode == 0`, `stdout == ""`, `stderr == ""`, no gauge file) remain correct after the fix under both paths — an unwrapped `produce` has nothing to display. Rename it to `test_cli_produce_empty_stdin_without_wrap_is_a_silent_noop` and add a docstring stating that the empty-stdin case is explicitly dispositioned two ways — silent when nothing is being wrapped, wrapped-command-display when `--wrap-command` is given — with a pointer to the wrapped test in the sibling Subtask. Without this scoping the name reads as an unconditional "empty stdin displays nothing", which is exactly the claim the fix retires.

**`tests/test_context_gauge.py:343-351` — `test_parse_payload_unparseable_is_distinguishable_from_empty` (unit layer).** If the fix lands in `cmd_produce` (the expected shape under both paths), `parse_payload` is untouched and this test stays green unmodified — leave it alone and verify it still passes. If the implementation instead collapsed `parse_payload`'s `ValueError` into a `None` return (making unparseable indistinguishable from empty inside the pure function), this test must be updated to the new mechanism AND the distinguishability must be re-pinned at whatever layer still carries it; flag that shape to the Engineer before rewriting it, because collapsing the two inside `parse_payload` removes the only in-process signal separating them. `test_parse_payload_empty_or_whitespace_is_none` (lines 332-336) and `test_parse_payload_non_object_top_level_raises` (lines 354-360) need no change under the expected shape — re-run them to confirm.

**Module docstring (lines 1-41).** No structural change required; if the chosen path makes exit 2 no longer reachable from `produce`, do not silently leave stale prose about it anywhere in this module's comments.

Do not modify any `read`-subcommand test, any `classify_reading` test, any `write_gauge` test, or the `no_real_tempdir_writes` fixture and its two `test_snapshot_helper_*` pins — those cover behavior this Task must leave unchanged.
