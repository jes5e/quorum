Document all four *behaviors* while describing the gate as three options. Do not invent a fourth option; that would contradict the shipped prose.

1. **What it is.** `/quo-setup` offers, optionally, to configure the producer that publishes the reading described in the section above. Declining changes nothing else about setup.
2. **How to enable it.** Three entry points: running `/quo-setup` normally (the step comes near the end of the walk-through); the fast path on a machine that is new to an already-set-up repo (where the status line is unconfigured because that setting is per-machine and never committed); and the direct path `/quo-setup <argument>` — **take the argument token from the trigger the shipped `### Direct invocation: producer configuration only` section keys on, not from the frontmatter `argument-hint`, which is hint text and may carry optionality brackets; do not invent or paraphrase it** — which runs only this step, needs neither the bees CLI nor a configured repo, and skips the rest of setup.
3. **The choices.** The gate offers three: configure it, not now (re-offered on a future run), and run unguarded (don't ask again). State plainly that there is no separate "wrap it" choice: when a status line already exists, configuring wraps and preserves it rather than replacing it, and re-running never nests one wrapper inside another. For the display-preservation guarantee itself, cross-reference Task 1's `**Wrapping an existing status line.**` paragraph — do not restate or extend it. Form of the cross-reference: link to `#the-context-usage-gauge-file` and name the paragraph by its bolded lead-in in prose (a bolded lead-in has no markdown anchor of its own).
4. **Caveat — activation.** Status-line configuration is picked up when a session starts, so treat the producer as active from the *next* session; the run in progress must not be assumed guarded. Mirror the register of the existing restart/`/agents` caveat under `### After install`.
5. **Caveat — pinned or restricted environments.** A user-level settings write can be outranked (a session launched against an explicit settings file, organization settings delivered at sign-in, MDM policy, managed-hook restrictions). Setup names the sources it can detect before asking and warns about the ones it cannot detect at all. In those environments, point the reader at the published file contract (`#the-context-usage-gauge-file`) in one clause as the route for the environment owner — not as instructions restated here. This paragraph's role is what SETUP does and says about these environments (detected vs undetectable sources, and how the gate's first option changes when a source is detected); leave the satisfy-the-contract-yourself instructions to the linked contract section rather than restating them.
6. **The opt-out.** "Run unguarded — don't ask again" writes a persistent marker; give its per-OS path in the paired form the two neighbouring sections already use (`/tmp/.quorum/context-guard-opt-out` on POSIX, `%TEMP%\.quorum\context-guard-opt-out` on Windows — **verify byte-for-byte against the shipped step prose**). State what it suppresses (only the stop that fires when no reading is being published) and what it does not (a genuine over-threshold stop when a reading *is* present). State that removing the file re-enables the offer, and name the no-deletion route back as well: invoking the direct path re-offers the step even when the marker is present (the shipped direct-invocation section reports the marker and still fires the gate — an explicit request to configure is itself the change of mind; the automatic slow-path and fast-path offers are the ones the marker silences). Name the file; do **not** prescribe a `rm` / `Remove-Item` command.
7. **Required, one sentence:** re-running setup repairs a producer configuration that has gone stale (moved or upgraded interpreter) without re-asking — an unprompted settings rewrite the customer-facing surface must disclose — and an existing opt-out marker suppresses even that silent repair. **Optional, one clause, include only if it does not bloat the section:** accepting the step exercises the newly-composed command once, which runs any wrapped command once.
