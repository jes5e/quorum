The change is purely additive: do not renumber, retitle, reorder, or reword any existing heading or paragraph (existing anchors must keep resolving). Line numbers advisory — re-resolve by heading at execute time.

The new subsection covers three of the section's four required elements (the fourth, the restricted-environments note, is a sibling Subtask that appends to this same subsection — leave room for it and do not author it here):

1. **Location.** State the per-OS path in the same two-bullet style the `### Scratch files` subsection already uses for the `.quorum` namespace (README.md:195-196): `/tmp/.quorum/context-usage-<session_id>.json` on POSIX (macOS, Linux, WSL) and `%TEMP%\.quorum\context-usage-<session_id>.json` on Windows. Say that `<session_id>` is the Claude Code session id, and that the tempdir resolution is the same one the scratch namespace uses.
2. **Required fields.** Show the file shape as a short fenced `json` block: a top-level `session_id` and a `context_window` object, with `context_window.used_percentage` called out as the field consumers threshold on. State that the write is the whole `context_window` object as received from the status-line payload (extra keys inside it are preserved, not filtered).
3. **Overwrite-per-session and freshness semantics.** One file per session id, so concurrent quorum sessions never collide and never consume each other's reading. Truncate-and-overwrite on every status-line refresh — a live gauge, not a log; nothing appends and nothing rotates. The workflow never deletes it. Freshness is judged from the file's modification time (there is no timestamp field inside the file), so a producer that stops refreshing goes stale on its own; name the helper's freshness-window default by reading the constant's actual value out of the shipped `context_gauge.py` rather than restating a number from the spec, and frame it as "refresh at least this often" guidance for a producer author.
