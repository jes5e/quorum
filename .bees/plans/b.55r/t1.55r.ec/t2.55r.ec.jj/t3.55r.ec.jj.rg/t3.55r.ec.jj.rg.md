## Context

The README's `### Scratch files` subsection (README.md:191-198) is the customer-facing inventory of what lives under `<tempdir>/.quorum/`. Today it enumerates two classes: regenerable `--body-file` payloads, and the run-state manifest that holds values nothing recreates. Task 1 adds a third resident — the per-session context-usage gauge — so the inventory and its delete-safety guidance are now incomplete. A prior doc-writer research pass flagged this as belonging to this Task's README lane.

Precondition: the two sibling Subtasks that author the gauge-contract subsection and its restricted-environments note have landed, so this Subtask can cross-link to a section that exists. It is sequenced last deliberately — all three Subtasks edit `README.md`, and serializing them avoids concurrent-edit conflicts on the same file.

## What Needs to Change

Make a minimal edit to the `### Scratch files` subsection in `README.md` (README.md:191-198; line numbers advisory — re-resolve by heading at execute time):

- **Extend the inventory.** The opening sentence (README.md:193) describes the directory's contents as transient scratch files exemplified by `bees create-ticket --body-file` / `bees update-ticket --body-file` payloads. Add the per-session context-usage gauge file as a named resident, with a cross-link (markdown anchor link) to the `### The context-usage gauge file` subsection (exact heading pinned by the first Subtask of this Task) so a reader can jump to the full contract instead of having it restated here.
- **Extend the delete-safety guidance without weakening it.** The existing paragraph (README.md:198) says the directory is safe to delete *between* runs and warns against deleting it *during* a run because the run-state manifest is not recreated on demand. That claim stays exactly as it is. Add only the gauge's own delete behavior: it is rewritten on the next status-line refresh, so it self-heals rather than being lost like the manifest — while a deleted gauge leaves no reading until that next refresh happens. Attribution caution: the paragraph's existing justification clause ("skills recreate it on demand") is true of the `--body-file` payloads but NOT of the gauge, which is recreated by the status-line producer, not by any skill — the added clause must attribute the gauge's self-heal to the status-line refresh explicitly rather than letting the existing clause be read as covering it.
- **Name the helper in the bundled-scripts example list.** README.md:189 (`### Where bundled helper scripts live`) lists the bundled Python helpers by example (`detect_fast_path.py`, `scoped_marker_resolver.py`). `context_gauge.py` is the first bundled helper an operator is expected to invoke directly (the conformance check) or point a status line at, so add it to that example list — a name plus a short parenthetical only (context-usage gauge producer/reader); no restatement of the contract, no `/quo-setup` install prose.
- **Preserve the rest verbatim.** The per-OS path bullets (README.md:195-196), the no-cleanup-by-design rationale, the footprint sentence, and the POSIX `/tmp` cleanup / Windows `%TEMP%` note all stay as-is. Do not restate delete-safety as an unqualified "safe to delete anytime" — CLAUDE.md `## Scratch-file convention` explicitly forbids that framing.

Scope guards:

- Do NOT describe what happens to a run when the reading is absent — Epic 3 (t1.55r.h9) owns the guard's missing-reading behavior. "No reading until the next refresh" is a statement about the file; "the run stops and prompts" is not this Epic's to make.
- Do NOT document `/quo-setup` configuring the producer (Epic 2, t1.55r.9d). If a conditional is needed, phrase it around the file's existence ("when a producer is configured for your environment") rather than around a setup step.
- Do NOT restate the gauge's path, fields, or freshness semantics here — link to the contract subsection instead.
