## Context

Consumer half of the gauge helper (SDD SR-2.2, with the fail-safe rationale in SR-1.6 and the PRD's fail-safe-direction NFR). Epic 3 (t1.55r.h9) will call this subcommand once per Epic/Issue boundary and branch on its single-line stdout. The four-way output is the load-bearing part: `stale` and `no-reading` are deliberately distinct because the consumer routes `stale` -> stop but `no-reading` -> continue. Collapsing them re-opens the banned fail-safe direction — context grows monotonically within a session, so a stale reading biases LOW, and low routes to "continue".

## What Needs to Change

In `skills/quo-setup/scripts/context_gauge.py`:

1. Add a module-level exception `class MalformedGauge(Exception):` (or equivalent) so the pure classifier can signal genuine malformation without printing, keeping it directly unit-testable per the SDD `## Test Fixtures` unit layer.

2. Add the string constants for the three non-numeric outputs, defined once each: `READING_NO_READING = "no-reading"`, `READING_STALE = "stale"`, `READING_MISSING = "missing"`. These are contract strings Epic 3 branches on.

3. `def classify_reading(path, now=None, freshness_seconds=FRESHNESS_WINDOW_SECONDS):` — the pure classifier, with `now` injectable (a float epoch-seconds value, defaulting to the current time when `None`) so tests need not sleep. If annotating, use `Optional[float]` via `from typing import Optional` — do NOT use PEP 604 `float | None` union syntax. Rationale: this repo's documented toolchain floor is Python 3.10+, and other bundled helpers do use PEP 604 — but this helper is unique in being invoked by the harness's status line under whatever `python3` resolves on the operator's PATH (which can be a system 3.9, not the interpreter the toolchain floor governs), and PEP 604 unions raise at definition time on 3.9. This deliberately narrower floor is recorded durably in the doc-writing guide's contract section (see the sibling doc Subtask). Evaluation order is load-bearing and must be commented as such:
   a. Path does not exist (or `stat` raises `FileNotFoundError`) -> return `READING_MISSING`.
   b. `now - path.stat().st_mtime > freshness_seconds` -> return `READING_STALE`. The staleness check precedes parsing on purpose: a stalled producer's last write is untrustworthy regardless of its content, and `stale` already routes to a stop. Comment that this means a file that is BOTH aged and malformed classifies as `stale` (exit 0, stop) rather than exit 2 — the fail-safe outcome either way.
   c. Read and `json.loads` the file. Unreadable (`OSError` other than not-found), undecodable, non-object top level, or a `context_window` that is present but not an object -> raise `MalformedGauge` with a short reason.
   d. `context_window.get("used_percentage")` absent or `None` -> return `READING_NO_READING` (transient early-session / post-compaction state; the producer is alive, the value just is not populated yet).
   e. Value is a `bool` -> `MalformedGauge` (guard before the numeric check, since `bool` is an `int` subclass). Value is an `int` or `float` -> return `str(int(round(value)))`. Any other type (including numeric strings) -> `MalformedGauge`. Do not clamp to 0-100; report what was measured.
   The function must never return `"0"` for an absent, null, or stale reading — the only path to a `0` output is a genuinely measured `used_percentage` that rounds to 0.

4. Replace `cmd_read(args) -> int` with: validate `args.session_id` via `is_valid_session_id` and `return fail("invalid --session-id ...")` (exit 2) when it fails — a malformed identifier is a caller bug, not a normal state, and must not be silently mapped onto one of the four values; then `classify_reading(gauge_path(args.session_id))`, `print(...)` the single line, `return 0`; catching `MalformedGauge` and returning `fail("<one human-readable line naming the file and the reason>")` (exit 2).

`read` performs no writes and no directory creation whatsoever — it must not call `ensure_gauge_dir()`.

## Acceptance Criteria

- `read --session-id <id>` against a gauge file containing `{"session_id": "<id>", "context_window": {"used_percentage": 37}}` written moments ago prints exactly `37` (single line) and exits 0.
- A float `used_percentage` of `37.6` prints `38`; `0.4` prints `0`; a value of `0` prints `0` — and those are the only ways `0` can ever be printed.
- A fresh gauge whose `used_percentage` is `null`, absent, or whose `context_window` is `{}` prints exactly `no-reading` and exits 0.
- A gauge file whose mtime is aged past `FRESHNESS_WINDOW_SECONDS` (e.g. via `os.utime` to now-300s) prints exactly `stale` and exits 0 — even when its `used_percentage` is a valid low integer. A file aged to exactly the boundary minus one second still prints its integer.
- An absent gauge file prints exactly `missing` and exits 0; no file or directory is created as a side effect (the `.quorum` directory does not spring into existence).
- A fresh gauge file containing invalid JSON, a JSON array/scalar top level, a non-object `context_window`, or a `used_percentage` of `"37"` / `true` / `[]` exits 2 with exactly one human-readable stderr line and prints nothing on stdout.
- `read --session-id ../escape` and `read --session-id ""` exit 2 with one stderr line and print none of the four values.
- `classify_reading` is callable in-process with an injected `now`, returning `str` for all four normal cases and raising `MalformedGauge` for malformed input — no printing, no `sys.exit` inside it.
- No PEP 604 union annotation (`X | None`) appears in the file (Python 3.9 compatibility for the on-PATH interpreter the status line uses).
- Two different `--session-id` values read two distinct files under the same temp root (no cross-session leakage).
- The module docstring is unchanged by this Subtask.
- `python -m pyflakes skills/*/scripts/*.py` is clean; no test or documentation file is touched.
