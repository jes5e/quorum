## Context

Producer half of the gauge helper (SDD SR-1.1 through SR-1.5, SR-1.7). `produce` is invoked by a Claude Code `statusLine` command on every status-line refresh (wired by Epic 2, t1.55r.9d — not by this Task). It must write the measured per-session context-usage reading to the published gauge path AND emit a status-line display, without ever clobbering an operator's pre-existing status line.

Assumes the scaffold Subtask has landed: `skills/quo-setup/scripts/context_gauge.py` exists with `fail()`, `gauge_dir()` / `ensure_gauge_dir()` / `is_valid_session_id()` / `gauge_path()`, the named constants, and an argparse skeleton whose `produce` subparser already declares `--wrap-command`. This Subtask only replaces the placeholder `cmd_produce`, adding whatever module-level helpers it needs, plus the imports it introduces (`json`, `os`, `subprocess`). It runs in parallel with the sibling `read` Subtask, which also adds `json` — if `import json` is already present when this Subtask edits the file, do not duplicate it; add only the imports not yet in the block, keeping the block sorted. The same append-don't-rewrite rule applies to the module-constant block (add this Subtask's wrapped-command timeout constant; do not reorder or rewrite constants the sibling added); the module docstring's CLI-contract block is owned by the scaffold Subtask — do NOT edit the module docstring here (function-level docstrings on the new functions are fine and expected).

The stdin-once discipline is load-bearing and was proven by a live producer: stdin is a pipe that can be drained exactly once, so the bytes must be captured into a variable and REUSED for the wrapped command — re-reading `sys.stdin` after the first read yields empty and silently breaks the wrapped display (SR-1.4).

Test code for this behavior belongs to sibling Task 2 (t2.55r.ec.y1); do not author tests here.

## What Needs to Change

In `skills/quo-setup/scripts/context_gauge.py`:

1. `def read_stdin_once() -> bytes:` — read `sys.stdin.buffer.read()` exactly once and return the raw bytes. Guard the case where `sys.stdin` is None or unreadable by returning `b""`. Every downstream use (JSON parse, wrapped-command input) consumes this single captured value; there must be exactly one `sys.stdin` read site in the file.

2. `def parse_payload(raw: bytes):` — decode UTF-8 (errors replaced) and `json.loads`. Return the dict on success. Return `None` for empty/whitespace-only input (a refresh with no payload). Raise/propagate a distinguishable condition for non-empty-but-unparseable input or a non-dict top level so `cmd_produce` can route it to `fail()`.

3. `def extract_gauge_record(payload: dict):` — return `{"session_id": <id>, "context_window": <obj>}` where `<id>` is `payload.get("session_id")` and `<obj>` is `payload.get("context_window")` when it is a dict, else `{}` (an absent/non-dict `context_window` is written as an empty object so the reader classifies it `no-reading`, never `0`). Return `None` when `session_id` is absent, empty, non-`str`, or fails `is_valid_session_id` — the no-op signal.

4. `def write_gauge(record: dict) -> Path:` — `ensure_gauge_dir()`, then truncate-and-write `json.dumps(record)` to `gauge_path(record["session_id"])` using an explicit `"w"` open with `encoding="utf-8"` (never `"a"`). Overwrite-per-refresh, in place, same path for the same session id. No temp-file-plus-rename dance is required, but the write must not leave the file absent on failure paths. Return the written Path. Never write anywhere but under `gauge_dir()`.

5. `def default_display(payload) -> str:` — the minimal display used when `--wrap-command` is absent: `os.path.basename` of `payload["workspace"]["current_dir"]` when present, else of `payload["cwd"]`, else the empty string. Defensive against non-dict `workspace`. Must not invent decorative text and must not print the usage percentage (the status line's content is the operator's, not the guard's).

6. `def run_wrapped(command: str, stdin_bytes: bytes) -> str:` — invoke the operator's existing status-line command with `subprocess.run(command, shell=True, input=stdin_bytes, capture_output=True, timeout=<short named constant, e.g. 10s>)` and return its stdout decoded UTF-8 (errors replaced). `shell=True` is deliberate and must be commented as such: the wrapped value is a settings-file `statusLine` command *string* (`/bin/sh` on POSIX, `cmd.exe` on Windows), exactly how the harness itself runs it, and it is operator-authored configuration rather than untrusted input. A wrapped command that fails to spawn, exits non-zero, or times out (`subprocess.TimeoutExpired`) must NOT break the producer: return whatever stdout was captured (possibly empty) and still exit 0 — the gauge write has already happened and a broken status line is worse than a blank one. The timeout exists because the status line invokes `produce` on every refresh: an operator command that hangs would otherwise hang the harness's status line indefinitely, once per refresh. Note in a comment that this is one extra short-lived, time-bounded spawn per refresh, accepted as bounded.

7. Replace `cmd_produce(args) -> int` with the ordered flow: capture stdin once -> parse -> if payload is `None` (empty stdin) print nothing and `return 0` -> if unparseable/non-dict `return fail("<one line>")` -> `extract_gauge_record` -> if `None`, write nothing (no-op) but STILL emit the display and `return 0` (SR-1.3: a refresh with no session context is a no-op, not an error) -> otherwise `write_gauge` -> then emit the display: `run_wrapped(args.wrap_command, captured)` verbatim when `--wrap-command` was given, else `default_display(payload)` -> `return 0`. When re-emitting wrapped stdout, print it verbatim (use `sys.stdout.write` so a trailing newline is neither added nor stripped).

Ordering is load-bearing: the gauge write happens BEFORE the wrapped command runs, so a hanging or failing wrapped command cannot cost the guard its reading.

## Acceptance Criteria

- Piping a payload containing `session_id` and a `context_window` object into `produce` creates `<tempdir>/.quorum/context-usage-<session_id>.json` whose parsed content is exactly `{"session_id": <that id>, "context_window": <that object verbatim>}` — no extra top-level keys, no dropped `context_window` fields.
- Running `produce` twice with two different `session_id` values under one temp root yields two distinct files; running it twice with the SAME id leaves exactly one file whose content is the second payload (truncate-and-overwrite, not appended — the file parses as a single JSON object, and its byte length shrinks when the second payload is smaller).
- A payload with no `session_id` key writes no file at all (the `.quorum` directory contains no new entry) and exits 0; the same holds for `session_id` values `""`, `null`, non-string, and `"../escape"`.
- A payload whose `context_window` is absent yields a written file with `"context_window": {}` — never a fabricated percentage, never `0`.
- With `--wrap-command <cmd>`, the process stdout equals the wrapped command's stdout byte-for-byte AND the gauge file is written; the wrapped command receives the same JSON bytes on ITS stdin (verifiable with a stub that echoes back its own stdin).
- With `--wrap-command` pointing at a command that exits non-zero, does not exist, or exceeds the wrapped-command timeout, `produce` still exits 0 and the gauge file is still present.
- Without `--wrap-command`, stdout is the basename of `workspace.current_dir` when present, else the basename of `cwd`, else empty; exit 0 in all three cases.
- Empty stdin produces no file, no stderr, and exit 0. Non-empty unparseable stdin exits 2 with exactly one human-readable stderr line and writes no file.
- `sys.stdin` is read in exactly one place in the file (grep confirms a single read site); nothing in the file deletes a file or writes outside `gauge_dir()`.
- The module docstring is unchanged by this Subtask.
- `python -m pyflakes skills/*/scripts/*.py` is clean.
