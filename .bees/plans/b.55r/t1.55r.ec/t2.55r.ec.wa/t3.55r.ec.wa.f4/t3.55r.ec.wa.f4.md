## What Needs to Change

No new source file. Exercise the assembled helper by hand and fix any defect found in `skills/quo-setup/scripts/context_gauge.py` (do not work around a defect in the verification steps — fix the helper):

1. Round-trip: write a sample status-line payload to a scratch file under `<tempdir>/.quorum/` per this repo's CLAUDE.md `## Scratch-file convention` (create the directory if absent; never delete it afterward), pipe it into `produce`, then run `read --session-id <same id>` and confirm the integer comes back. Use a distinctive synthetic session id so the run is self-identifying and cannot collide with a real session's gauge — and it MUST NOT start with `quorum-pytest-`, which is reserved for the automated test suite's leak-detection fixture (sibling Task 2); a smoke artifact inside that prefix would trip the suite on this machine forever, since scratch files are never deleted. Something like `quorum-smoke-<suffix>` is fine.
2. Overwrite and isolation: re-run `produce` with the same id and a different percentage, confirm `read` reflects the new value and exactly one file exists for that id; run with a second id and confirm two distinct files and two independent `read` results.
3. No-op: pipe a payload with no `session_id`, confirm exit 0, no new file, and that the display still prints.
4. Wrap-don't-replace: run `produce --wrap-command` against a trivial interpreter-based stub that echoes a fixed marker, confirm stdout is the marker verbatim and the gauge was still written.
5. Classifier states: age one gauge with `os.utime` past the freshness window and confirm `stale`; null out `used_percentage` in a fresh file and confirm `no-reading`; `read` a never-written id and confirm `missing`; corrupt a fresh file and confirm exit 2 with one stderr line.
6. Constant audit: confirm `STOP_THRESHOLD_PERCENT` reads 50 (not 55) and `FRESHNESS_WINDOW_SECONDS` reads 120, each assigned in exactly one place.
7. Convention audit: confirm the file is stdlib-only, single-file, has the shebang and `sys.exit(main())` entry, contains no delete call and no write path outside the gauge directory, and that its prose/comments are project-neutral (no reference to this repo's ticket ids, spec-document section identifiers, branch names, or machine-specific paths).
8. Run the repo **Lint** command from CLAUDE.md `## Build Commands` and leave it clean.

Any multi-step verification logic must be written to a scratch script file and run with one command rather than composed inline, per this repo's bash-etiquette rule. Verification scratch files live under `<tempdir>/.quorum/` and are never committed and never deleted.
