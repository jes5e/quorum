## Context

Foundational Task of Epic 1 (t1.55r.ec, context-window guard). Nothing in the workflow reads or writes context usage today — this Task creates the single bundled helper that both halves of the guard share: the producer (`produce`, invoked by a Claude Code status-line command on every refresh) and the reader (`read`, invoked by the execution skills at Epic/Issue boundaries in Epic 3).

Authoritative spec: Spec Bee b.8sh → SDD child (t1.8sh.cg) `## Requirements` SR-1 (producer, SR-1.1 through SR-1.7) and SR-2.1/SR-2.2 (threshold constant + read subcommand), plus the `## Codebase exploration findings` bundled-helper conventions. The PRD child (t1.8sh.c4) supplies the fail-safe-direction rationale (a missing/null/stale reading must never read as "plenty of headroom").

## What Needs to Change

Add a new bundled cross-platform Python helper at the location the SDD proposes under the quo-setup skill's scripts directory (`context_gauge.py`), stdlib-only, matching the existing bundled-helper conventions (argparse subcommands, the exit-2 `fail()` convention, `sys.exit(main())` entry). It exposes two subcommands:

- `produce [--wrap-command <cmd>]` — read the Claude Code status-line JSON from stdin exactly once; extract `session_id` and the `context_window` object; write `{"session_id": ..., "context_window": {...}}` to `<tempdir>/.quorum/context-usage-<session_id>.json` (tempdir via `tempfile.gettempdir()`, create `.quorum` if absent). Overwrite-per-refresh (truncate-and-write, a live gauge — never append), filename keyed by `session_id` so concurrent sessions never collide. When `session_id` is absent from the payload, write nothing and exit 0 (no-op, not an error). Without `--wrap-command`, print a minimal default display line derived from the payload's `workspace.current_dir`/`cwd` basename; with `--wrap-command`, after writing the gauge, invoke the wrapped command feeding it the same captured stdin bytes and re-emit its stdout verbatim as the display (wrap-don't-replace — the stdin-once capture-and-reuse is mandatory). Never write outside `<tempdir>/.quorum/`; never delete files.
- `read --session-id <id>` — read `<tempdir>/.quorum/context-usage-<id>.json` and print exactly one of FOUR values: the integer `used_percentage`; `no-reading` (file present, fresh, but `context_window.used_percentage` null/absent — transient early-session or post-compaction state); `stale` (file present but its modification time is older than the freshness window — a stalled producer); or `missing` (file absent). Exit 0 for all four (they are normal states); exit 2 only on a genuinely malformed file per the `fail()` convention. Never print or imply `0` for an absent/null/stale reading.

Two named constants, single definition site each, deliberately tunable in one place:

- **Stop threshold: 50%** (SDD SR-2.1 — do NOT implement 55%; that initial value was superseded in plan review because its arithmetic did not survive a ~30% unit against the ~83% compaction point).
- **Freshness window: ~120 seconds** (SDD SR-1.6/SR-2.2), judged against the gauge file's mtime — no embedded timestamp field; the overwrite-per-refresh write is what keeps mtime current.

## Why

The model cannot observe its own context usage natively; an out-of-band status-line producer writing a measured value to a well-known file is what gives the boundary guard (Epic 3) a real reading to threshold against. `stale` is distinct from `no-reading` on purpose: context grows monotonically within a session, so a stale reading biases LOW, and low routes to "continue" — the banned fail-safe direction. The consumer routes `stale` → stop but `no-reading` → continue; collapsing them would drop the stalled-producer fix.

## Success Criteria

- `produce` piped a sample status-line JSON writes the gauge file with the specified shape; running twice with two session ids yields two distinct files; re-running with the same id overwrites in place; a payload without `session_id` is a 0-exit no-op that writes nothing.
- `produce --wrap-command` re-emits the wrapped command's stdout as the display while still writing the gauge; without it, the minimal default display prints.
- `read` returns the integer for a present-numeric gauge, `no-reading` for present-fresh-null, `stale` for an mtime-aged file, `missing` for an absent file — all exit 0; a malformed file exits 2 with one human-readable stderr line.
- The threshold constant reads 50 and the freshness-window constant ~120s, each defined exactly once.
- Helper is a single stdlib-only Python file following the repo's bundled-helper conventions; Lint (pyflakes) is clean; prose/comments stay project-neutral; no cleanup/deletion of scratch files anywhere.
- The contributor-facing docs are updated: the doc-writing guide gains a `## The context-gauge file contract` section, and the SDD's tech-stack helper list and `## Key components` catalog name the new helper — with no `### Feature:` subsection added (Epic 3 owns that) and no customer-facing README change (Task 3 owns that).
