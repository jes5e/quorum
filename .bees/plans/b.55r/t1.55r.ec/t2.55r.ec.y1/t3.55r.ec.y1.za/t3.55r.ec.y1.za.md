## What Needs to Change

Create `tests/test_context_gauge.py`, stdlib + pytest only, following the two-layer shape of `tests/test_hive_commit.py`.

**Module header.**

1. Module docstring stating the two layers, and — mandatory per SDD SR-4.4 — an explicit **assumed-equality note**: these tests inject a synthetic `session_id` on BOTH the produce side (stdin payload) and the read side (`--session-id`), so they cannot catch an upstream divergence between the harness status-line payload's `session_id` and the `CLAUDE_CODE_SESSION_ID` environment variable the consumer reads. State that the equality was live-verified when the feature was designed and that its re-probe is tracked by upstream Issue **b.cj2**.
2. `from conftest import CONTEXT_GAUGE, load_script, script_path`; `mod = load_script(CONTEXT_GAUGE)`; `SCRIPT = script_path(CONTEXT_GAUGE)` (mirrors test_hive_commit.py:13-16).
3. `REAL_TEMP_ROOT = Path(tempfile.gettempdir())` captured at **import time**, before any test can monkeypatch `tempfile.gettempdir`.
4. `TEST_SESSION_PREFIX = "quorum-pytest-"`; every synthetic session id used by a test that WRITES a gauge file starts with it (pure-derivation calls like `gauge_path("abc-123")` create nothing and are exempt). The `quorum-pytest-` prefix is a pytest-reserved token: Task 1's smoke-verify Subtask (t3.55r.ec.wa.f4) is required to pick its manual real-tempdir session id OUTSIDE this prefix, so its never-deleted artifact cannot collide with this suite's safety fixture.

**Safety fixture (enforces the "never touch the real tempdir" criterion).** An `autouse` function-scoped fixture that snapshots the set of filenames matching `context-usage-quorum-pytest-*` under `REAL_TEMP_ROOT / ".quorum"` at SETUP and asserts on teardown that the set gained no new entries (a delta assertion scoped to the reserved prefix — collision-proof against pre-existing artifacts AND against genuinely-new non-prefixed entries a live status-line producer may write mid-run once one is installed on the machine; detection power is preserved because every test that writes a gauge file must use `TEST_SESSION_PREFIX`, so a test missing its `monkeypatch`/`env=` override still leaks under the reserved prefix and is caught). Never delete anything in that directory (repo CLAUDE.md `## Scratch-file convention`).

**Layer 1 — unit (in-process, `mod.*` called directly).** Redirect the tempdir with `monkeypatch.setattr(mod.tempfile, "gettempdir", lambda: str(tmp_path))`. Use `monkeypatch` and never a bare assignment: `mod.tempfile` IS the shared stdlib module object, so the patch is process-global and must be auto-undone. Cases:

- Path derivation: `mod.gauge_path("abc-123") == tmp_path / ".quorum" / "context-usage-abc-123.json"`; and the same call BEFORE and AFTER patching yields different roots, proving the tempdir is resolved at call time, not captured at import.
- `mod.is_valid_session_id`: True for a UUID-shaped id; False for `""`, `"../escape"`, `"a/b"`, `"a\b"`, `None`, `123`.
- `mod.ensure_gauge_dir()` creates the dir when absent and is idempotent when called twice.
- Tunable constants: `mod.STOP_THRESHOLD_PERCENT == 50` and `mod.FRESHNESS_WINDOW_SECONDS == 120`, with a comment that these are the single definition sites and a change here is a deliberate re-calibration, not an incidental edit.
- `mod.extract_gauge_record`: full payload -> `{"session_id": id, "context_window": <object verbatim, all fields preserved>}` and nothing else; absent or non-dict `context_window` -> `"context_window": {}` (never a fabricated percentage, never `0`); returns `None` for absent / `""` / `None` / non-str / `"../escape"` session ids.
- `mod.parse_payload`: empty and whitespace-only input -> `None`; a valid JSON object -> the dict. For non-empty-unparseable input and a non-dict top level, Task 1's body only requires "a distinguishable condition" and does not pin the mechanism — read the landed source and assert the mechanism it actually shipped (exception type or sentinel), and assert positively that it is distinguishable from the empty-stdin `None`. Do not change the helper to fit a guessed mechanism.
- `mod.write_gauge`: writes to `gauge_path(...)`; a second call with the same id leaves exactly one file whose parsed content is the second record and whose byte length shrank when the second payload is smaller (proves truncate-and-write, not append); two different ids under one root produce two distinct files with independent contents (parallel-session isolation).
- `mod.default_display`: basename of `workspace.current_dir` when present; basename of `cwd` as fallback; `""` when neither; does not raise on a non-dict `workspace`; never contains a percentage.
- `mod.run_wrapped` timeout tolerance: `monkeypatch.setattr(mod.subprocess, "run", ...)` to raise `subprocess.TimeoutExpired`, and separately `FileNotFoundError` — assert `run_wrapped` returns a `str` and does not raise. (Doing the timeout case here rather than at the CLI layer keeps the suite fast; the real wrapped-command timeout constant is ~10s.)
- `mod.classify_reading(path, now=...)` — always pass an injected `now` so no test sleeps:
  - `used_percentage` `37` -> `"37"`; `37.6` -> `"38"`; `0.4` -> `"0"`; `0` -> `"0"` (comment: these are the ONLY ways `"0"` can be produced).
  - `null`, absent, and `context_window: {}` -> `mod.READING_NO_READING`.
  - File aged with `os.utime` and read with `now = mtime + FRESHNESS_WINDOW_SECONDS + 1` -> `mod.READING_STALE`, **even when `used_percentage` is a valid low integer** (this is the anti-collapse regression test). With `now = mtime + FRESHNESS_WINDOW_SECONDS - 1` the same file still returns its integer. Do not assert the exact-equality boundary — neither the SDD nor Task 1 pins whether `== window` is fresh or stale.
  - Absent file -> `mod.READING_MISSING`, **and** the gauge directory does not spring into existence as a side effect (`not (tmp_path / ".quorum").exists()` afterwards).
  - Four-way distinctness: assert `READING_NO_READING`, `READING_STALE`, `READING_MISSING` are three distinct strings, none equal to `"0"` or `""` — so collapsing any pair fails the suite.
  - `mod.MalformedGauge` raised for: invalid JSON, a JSON array top level, a JSON scalar top level, a non-object `context_window`, and `used_percentage` values `"37"` (string), `[]`, and `True` / `False` (bool rejected before the int check — `bool` is an `int` subclass, so this is a real regression risk and gets its own named test).
  - `classify_reading` prints nothing and never calls `sys.exit` (assert via `capsys` that stdout/stderr are empty across the four normal cases).

**Layer 2 — CLI contract (subprocess).** Local helpers mirroring test_hive_commit.py:123-136:

- `_env_with_tempdir(tmp_path)`: `env = dict(os.environ)` then set `TMPDIR`, `TEMP`, and `TMP` all to `str(tmp_path)` — all three, because `tempfile.gettempdir()` consults `TMPDIR`/`TEMP`/`TMP` differently across platforms. Each subprocess is fresh, so no `tempfile` cache concern.
- `_run(args, stdin=None, env=None)`: `subprocess.run([sys.executable, str(SCRIPT), *args], input=stdin, capture_output=True, text=True, env=env)`.
- `_stub(tmp_path, name, source)`: write a small Python file under `tmp_path` and return a shell-quotable command string `f'"{sys.executable}" "{stub}"'` — double-quoted paths are accepted by both `/bin/sh` and `cmd.exe`, which is what `--wrap-command` runs under (`shell=True`). This is the cross-platform analogue of test_hive_commit.py's `_write_stub_bees` technique; a written stub file plus `sys.executable` avoids depending on a system `echo`.

CLI cases (assert `returncode` and exact stdout):

- `produce` with a full payload: exit 0; `<tmp_path>/.quorum/context-usage-<id>.json` exists and parses to exactly `{"session_id": ..., "context_window": <verbatim>}`.
- `produce` twice, same id, second payload smaller: exactly one file for that id, content is the second payload (overwrite-per-refresh).
- `produce` twice, two different ids: two distinct files, each with its own content (parallel isolation at the CLI layer).
- `produce` with no `session_id` key: exit 0, the temp root gains no `context-usage-*` file at all, AND stdout still carries the default display (basename of `workspace.current_dir`) — the no-op path must not silently drop the display; same no-file/exit-0 assertions for `""`, `null`, non-string, and `"../escape"` ids.
- `produce` with empty stdin: exit 0, empty stderr, empty stdout, no file. `produce` with non-empty unparseable stdin: exit 2, exactly one stderr line, no file.
- `produce` without `--wrap-command`: stdout is the basename of `workspace.current_dir`.
- `produce --wrap-command <marker stub>`: stdout equals the marker byte-for-byte (stub writes with `sys.stdout.write` and no trailing newline, so this also proves the passthrough neither adds nor strips a newline) AND the gauge file is written.
- `produce --wrap-command <echo-my-stdin stub>`: the stub's captured stdin, round-tripped to stdout, parses to the same payload — proving the stdin-once capture is reused rather than re-read.
- `produce --wrap-command` pointing at a command that exits non-zero, and one that does not exist: exit 0 in both cases and the gauge file is still present (a broken status line must not cost the guard its reading).
- `read --session-id <id>` over a fresh gauge: stdout is exactly the single integer line, exit 0. Over a fresh null-percentage gauge: `no-reading`, exit 0. Over a gauge aged with `os.utime` to `time.time() - 300`: `stale`, exit 0. Over an absent file: `missing`, exit 0.
- `read` on a clean temp root creates nothing: `<tmp_path>/.quorum` does not exist afterwards.
- `read` over a malformed gauge: exit 2, empty stdout, exactly one stderr line.
- `read --session-id ../escape` and `read --session-id ""`: exit 2, and stdout contains none of the four reading values.
- argparse contract: `--help` exits 0 and names both `produce` and `read`; no subcommand exits 2; an unknown subcommand exits 2.

Every CLI invocation that could write MUST pass `env=_env_with_tempdir(tmp_path)`. Iterate with the repo **Narrow test** command scoped to this file (`python -m pytest tests/test_context_gauge.py`); the workspace-wide run belongs to the final Subtask of this Task.
