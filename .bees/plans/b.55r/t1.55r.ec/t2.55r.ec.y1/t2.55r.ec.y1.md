## Context

Test Task of Epic 1 (t1.55r.ec, context-window guard). Task 1 adds the `context_gauge.py` producer/reader helper; this Task adds its test coverage following the repo's established two-layer test pattern (in-process unit layer via the conftest `load_script` loader; CLI-contract layer via `script_path` + subprocess runs), and registers the helper's relpath constant in the shared conftest alongside the existing helper constants.

Authoritative spec: Spec Bee b.8sh → SDD child (t1.8sh.cg) `## Test Fixtures` (the section prescribes the layers, fixtures, and cases for this exact file) and `## Requirements` SR-1/SR-2.2 for the behaviors under test.

## What Needs to Change

- Add a new test module for the gauge helper (`tests/test_context_gauge.py`) with both layers:
  - **Unit layer**: load the helper in-process and exercise pure functions directly — gauge-path derivation (`<tempdir>/.quorum/context-usage-<id>.json`), `context_window` extraction, and the `read` classifier's four-way classification. Use `tmp_path` plus `monkeypatch` so writes land under the test's temp root, never the real tempdir; use `os.utime` to age a gauge file past the freshness window for the `stale` case.
  - **CLI-contract layer**: run the script via subprocess with controlled stdin and a copied env whose tempdir variables point at `tmp_path`. Assert on returncode and stdout.
- Add a `CONTEXT_GAUGE` relpath constant to `tests/conftest.py` alongside the existing helper constants (`HIVE_COMMIT`, `DETECT_FAST_PATH`, `SCOPED_MARKER_RESOLVER`).
- Coverage (per the SDD Test Fixtures section):
  - `produce` writes the expected file; overwrite-per-refresh semantics (second write truncates/replaces, same path).
  - Session-keyed parallel isolation: two different session ids write/read two distinct files under the same temp root.
  - Missing `session_id` in the stdin payload → 0-exit no-op, nothing written.
  - `--wrap-command` passthrough: the wrapped command's stdout is re-emitted AND the gauge is still written (stub the wrapped command with a trivial interpreter-based echo, mirroring the existing stub-executable technique in the hive-commit tests).
  - All four `read` classifications: integer, `no-reading` (present, fresh, null percentage), `stale` (present, mtime aged past the freshness window), `missing` (absent file) — all exit 0.
  - Malformed gauge file → exit 2 with a stderr diagnostic.

## Why

The helper is the single shared artifact both halves of the guard depend on (Epic 2 installs its `produce`; Epic 3 branches on its `read` output). Its four-way `read` contract is load-bearing for the fail-safe direction — in particular `stale` vs `no-reading` routing — so each classification needs an explicit, observable test before downstream Epics build on it.

## Cross-Task / cross-Epic contract

- Depends on Task 1 (the helper must exist). Tests assert the contract Task 1 defines — path shape, field names, the four `read` outputs, exit-code semantics, the 50% threshold and ~120s freshness-window constants. If a test seems to require changing the helper, that is a Task 1 defect to surface, not something to patch here — this Task changes test code only.
- **Assumed-equality note (SDD SR-4.4)**: the test module must carry an explicit comment/docstring noting that the tests inject a synthetic `session_id` on both the produce and read sides, so they cannot catch an upstream divergence between the status-line payload's `session_id` and the session-id environment variable; that equality was live-verified and its re-probe is tracked upstream (b.cj2).
- The conftest change is additive (one constant); the existing helper test modules and constants are untouched.

## Success Criteria

- `tests/test_context_gauge.py` passes under the project Full test command (`python -m pytest tests/`), and the pre-existing test modules still pass unmodified.
- `tests/conftest.py` gains the `CONTEXT_GAUGE` constant; no other conftest change.
- Every coverage bullet above has at least one test that fails if the behavior regresses (e.g., collapsing `stale` into `no-reading` fails the suite; implying `0` for a missing reading fails the suite).
- No test touches the real tempdir or leaves artifacts outside pytest-managed temp roots; Lint (pyflakes) is clean on any helper-script edits (none expected) and the tests follow the repo's existing test idioms.
- The assumed-equality note is present in the test module.
