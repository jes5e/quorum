## Current behavior

`**Severity bounds the loop**` treats the reviewer's severity tag as the verdict: any `blocker` or `suggestion`, or any `nit` deeper than `trivial-tweak`, holds the lane open for another cold round. The orchestrator has no judgment over whether a round is still worth running. The b.zi3 and b.pkn validation runs each showed reviewers tagging pure wording fixes as `suggestion`, each costing a fresh ~100k-token reviewer; b.pkn reported five extra doc rounds and two extra test rounds from one ambiguity.

## Expected behavior (sketch)

Reviewer tags become evidence, not verdict. Per round the orchestrator judges: does any remaining finding describe a behavior defect or a false claim, or would fixing it change what ships? If yes, another cold round. If no, apply the trivial fixes, close the lane, and render every applied item on the summary's **Reviews** line so the post-completion sweep re-reads them cold. Guards: the judgment is written to the manifest before the lane closes (manifest-write-then-act, the gate shape); a `blocker` is never closable this way; the post-completion sweep stays the backstop. Fold in b.7wb's per-lane round recording (earned / late / variance) and b.pkn report item 5 (a post-completion `suggestion` owes a reviewer pass — state it). Coverage is unchanged: every round still re-reads the whole diff; what stops is paying a full round for reviewer-to-reviewer wording variance.

## Addendum (2026-09-15) — redefine the severity scale by consequence so the exit decision reads it instead of re-grading it

The exit rule above splits two judgments: the reviewer classifies findings; the orchestrator decides whether a lane needs another round. Today's `blocker` / `suggestion` / `nit` scale is defined as "importance", which conflates "wrong as it stands" with "worth doing", so reviewers tag wording fixes as `suggestion` (three times in the b.pkn run alone) and every real finding lands in a level that holds the lane open. Redefine the levels by consequence, each with a one-line test:

- `blocker` — the code or text is wrong, or something ships broken. Test: a user or a downstream agent acting on the current state would be misled or fail.
- `suggestion` — not wrong today, but a reader or the code will do the wrong thing without this. Test: the fix changes what the text asserts or what the code does.
- `nit` — true and complete as it stands; this makes it better. Test: neither what is asserted nor what happens changes. Includes behavior-preserving refactors and wording.

Depth stays where it is, on each fix path. With consequence-defined levels the orchestrator's exit decision is near-mechanical: another round while any `blocker` remains or any `suggestion` remains outstanding; `nit`s are applied in the final implementer pass and recorded on the **Reviews** line, whatever their depth. The residual orchestrator judgment is the one the hand-edit exit rule already names: a `suggestion` whose fix is wording on text an earlier cold pass accepted closes the lane with the residual recorded. Each review skill carries worked examples per level (the current examples are where the 2026-09-11 calibration sentence was found to contradict the skill).

Scope: the three review skills' severity paragraphs and examples, the `**Severity bounds the loop**` paragraph in both bodies, the exit-decision manifest write. One designed change, not three appended sentences.

### A. The rule, stated once

**A1. Severity is consequence.** Three levels, each with a one-line test, applied in order with first match winning (the same evaluation shape as the routing table):

- `blocker` — what is there is wrong: a false statement, a failing or broken behavior, a violated contract. Test: someone acting on the current state is misled or fails.
- `suggestion` — true and working as far as it goes, but a reader or the code will go wrong in a case it does not cover. Test: the fix changes what the text asserts or what the code does.
- `nit` — true and complete; the fix makes it better. Test: the fix changes neither what is asserted nor what happens. Behavior-preserving refactors and wording are nits, at any depth.

Depth (`trivial-tweak` / `refactor-locally` / `re-architect`) stays on each fix path, untouched. The routing table rows 1–6, gates (c)/(d), Trigger C's exactly-one-`trivial-tweak` exception, and the depth shims (e)/(f) are untouched.

**A2. The loop bound.** A lane is held open by `blocker` and `suggestion` findings and by any `nit` whose chosen fix path is deeper than `trivial-tweak` — the existing b.bix bound, kept verbatim. A `nit` whose chosen path is a `trivial-tweak` never holds a lane: it rides along in an implementer round some lane-holding finding already forces, or, when only such nits remain, is applied in one final implementer pass with no further reviewer round. The nit count goes to `## Rounds` and the **Reviews** line as today. A deeper nit holds the lane until a cold pass reads the restructure, exactly as a `suggestion` does; the severity scale changes what the tag means, not depth's one routing role.

**A3. The residual clause** — the only place the orchestrator overrides a reviewer's tag, and the shipped form of the hand-edit exit rule in CLAUDE.md `## Working on the orchestrator skills`. A `suggestion` closes with the lane, applied in the final pass and recorded as a residual, only when BOTH hold: (i) its chosen fix path meets the `nit` test, judged over the reviewer's own path description; (ii) the text it targets was read by a prior cold pass at this lane that did not flag it, and no implementer pass at this lane since was dispatched to change it. The orchestrator judges (i) over the finding text and (ii) over its own dispatch prompts and the prior returns — never over file contents. When either input is unreadable the clause does not fire and the `suggestion` holds the lane. It cannot fire at a lane's first round (no prior pass at that lane). It applies to `suggestion`s only: never to a `blocker`, and not to a `nit` held by depth, whose hold is about reading the restructure, which the `nit` test does not address. The orchestrator never re-grades in the other direction: a `nit` is never promoted; a mis-tagged `nit` whose fix changes behavior is the post-completion sweep's to catch.

**A4. Gate-shipped paths keep today's guard, verbatim.** A `nit` whose chosen fix path fires a gate still routes through the table. When the gate's answer ships anything other than the enumerated `trivial-tweak` path (`Fix properly now` on a row-2, -3, or -4 fire; a deferral's soft fix or narrowing), what ships is lane-holding again and a cold pass reads it; part (g)'s elision does not apply. Unchanged from the shipped text.

**A5. The per-round exit decision is written before it is acted on.** At the moment a round's findings are routed, rewrite the lane's `## Rounds` row (shape in C) — classification, decision, counts — before the action the decision names: the re-dispatch, the final implementer pass, or marking the reviewer lane `closed`. This is manifest-write-then-act, the gate shape, without a gate. The decision values and the round classes are enumerated in B and C.

**A6. The post-completion sweep is the backstop, stated.** Its diff includes every `trivial-tweak` nit and every residual applied without re-review; that sweep is the cold pass those items receive. No change to Section 11's scope.

**A7. Post-completion fixes owe exactly one reviewer pass (b.pkn item 5).** Under `Fix in this session`, a `blocker` or `suggestion` post-completion finding's fix — and a `nit`'s when its chosen path is deeper than `trivial-tweak` — is read by the reviewer lane its implementer maps to — Engineer → Code Reviewer, Test Writer → Test Reviewer, Doc Writer → Doc Reviewer — at scope `postcomp-<n>`, under A2–A5 with its own `## Rounds` row. A `trivial-tweak` `nit` post-completion finding gets its implementer pass and no reviewer. The post-completion close-out prints one `**Reviews**` line over the `postcomp-*` rows in Section 8's slot format, so the round data has a rendering target and the boundary prune rule keeps its meaning.

**A8. b.7wb's round classification is folded in** as the `classification` column of `## Rounds` and the `N rounds (earned/late/variance/unavailable = a/b/c/d)` rendering on the **Reviews** line. b.7wb's phase timings are not in scope here; b.7wb stays open for those.

### B. Case enumeration for the exit decision

Inputs, and where each lives: (1) this round's reviewer return — findings with severity tag, enumerated paths, the Step-1 pick — transcript; (2) dispositions already reached this tick — tracker entries, `defer-*` obligations, gate answers — tracker and manifest; (3) the lane's `## Rounds` row — manifest, survives compaction; (4) the prior returns at this lane and the implementer dispatch prompts issued at this lane since — transcript, may not survive compaction; (5) the lane's dispatch count — `## Lanes` `round`.

"Lane-holding" below means: a `blocker`, a `suggestion` the residual clause does not close, or a `nit` whose chosen path is deeper than `trivial-tweak`.

- **B1 Clean return.** No numbered findings. Decision `close — clean`; class (round > 1) `clean`; no implementer pass; mark the lane `closed`. A non-empty `### Second-order effects` beside a clean list does not change this (existing rule).
- **B2 `trivial-tweak` nits only.** Every finding is a `nit` whose chosen path is a `trivial-tweak`. Route each through the table (a gate may fire under A4). Decision `close — nits only`; nit count = the nits shipped as picked; one final implementer pass; part (g)'s code-review rung elided; class `clean` (nothing lane-holding was found).
- **B3 Lane-holding finding present, no residual.** At least one lane-holding finding that A3 does not close. Decision `another round`; route per the table; `trivial-tweak` nits ride along. Class `earned` when any such finding targets the previous round's fix (the location is one the previous implementer dispatch at this lane named), else `late` (older text no prior pass flagged).
- **B4 Every lane-holding-tagged finding is a residual.** A3 holds for each `suggestion`; no `blocker` and no deep `nit` is present. Decision `close — residual`; residual count = those suggestions; they ship in the final implementer pass with the `trivial-tweak` nits; class `variance`. This is the case the b.pkn run paid five doc rounds and two test rounds for.
- **B5 Mixed.** Some residuals, at least one non-residual lane-holding finding. Decision `another round`; the residuals ride along and the next cold pass reads them, so they are NOT counted as residuals — only a residual closed without re-review is counted. Class by B3.
- **B6 Blocker present.** Decision `another round`, always, unless the blocker reached a no-fix-lands disposition this tick (`Cancel`; a `Defer` that ships nothing is impossible for a blocker, whose `Defer` is paired with a narrowing). A blocker's narrowing ships, so it is lane-holding and the lane stays open. A3 never applies. Class `earned` or `late` per B3.
- **B7 First round at a lane.** A3 cannot fire; only B1, B2, B3, B6 apply; the row's `classification` gets no entry for round 1.
- **B8 Compaction.** (a) This round's return unreadable → re-dispatch the reviewer at the same round number; never decide from a summary (Section 3). (b) Prior returns or dispatch prompts unreadable → A3(ii) fails, every `suggestion` holds the lane, and the round's class is `unavailable post-compaction`. (c) The `## Rounds` row is the durable record of decisions already made; a missing row for a lane that ran renders `count unavailable post-compaction` (existing literal).
- **B9 Empty lane.** A reviewer never dispatched (Phase A empty; no Test Writer ran; no Doc Writer at a scope) has no `## Rounds` row; its slot renders `None needed` as today.
- **B10 Gate outcomes on a lane-holding finding.** `Accept the limitation`, `Cancel`, or a `Defer` that ships nothing → settled, no longer holds. `Fix properly now`, a soft fix, or a narrowing → still holds until a cold pass reads what shipped (existing rule, A4).
- **B11 The PM's in-flight review site** (`/quo-execute` per-Task). Same decision; `close` means no PM re-dispatch for that lane; one `## Rounds` row per in-flight review, keyed by the `review` column (the reason the column was renamed from `role` after b.zi3).
- **B12 Disagreement on A3(i) alone.** The orchestrator believes a `suggestion`'s path meets the `nit` test but A3(ii) fails → the suggestion holds. (i) alone never closes anything; that is what keeps the clause a reading of evidence rather than a re-grade.
- **B13 Post-completion lanes.** A7's reviewer lane at `postcomp-<n>` starts at round 1, so A3 cannot fire on its first pass; the post-completion sweep is a different lane and is not "a prior cold pass at this lane".

### C. The `## Rounds` shape (both bodies, Section 2)

```markdown
## Rounds
| scope | review | classification | decision | nits applied without re-review | residuals applied without re-review |
|---|---|---|---|---|---|
```

- `scope` and `review` as today (the scope and the **Reviews**-line slot).
- `classification`: one word per round after the first, in round order — `earned`, `late`, `variance`, `clean`, or `unavailable post-compaction`; empty until a second round is dispositioned.
- `decision`: the latest exit decision — `another round`, or `close — clean` / `close — nits only` / `close — residual` (`residual` wins over `nits only` when both apply).
- The two counts: `trivial-tweak` nits, and residual suggestions, applied in the lane's final implementer pass without a further reviewer round.
- Write rule: rewrite the row when a round's findings are routed, before the action the decision names (A5). Prune rule unchanged: at the boundary checkpoint, prune rows already rendered on a summary line.
- Manifest discipline holds: the row carries decisions and counts, never the findings' text; residual descriptions on the **Reviews** line come from the reviewer's return in the transcript, and when that is gone the line renders the count with `descriptions unavailable post-compaction`.

**Reviews**-line slot format (Section 8 template in both bodies; `/quo-execute`'s `## Bee Execution Complete`; the new post-completion line): `<slot>: X issues found/None needed`, then when the lane ran more than once `N rounds (earned/late/variance/unavailable = a/b/c/d)` (`d` counts rounds classified `unavailable post-compaction`, never rendered as `clean`; the remainder is the first round plus the `clean` rounds — operator decision 2026-09-16, closing the rendering gap round three of the implementation surfaced), then `N nits applied without re-review` and `N residuals applied without re-review — <each residual's description, one line>` when any; `count unavailable post-compaction` when the manifest carries no row; attributed by review site where a slot has more than one.

**Proposed Section 7 text** (both bodies, verbatim, replacing the single paragraph; each bullet is one rule and under 120 words):

> **Severity bounds the loop.** A review lane's loop — the Engineer → code-review loop at any review site, and each writer → reviewer pair — is held open by `blocker` and `suggestion` findings and by any `nit` whose chosen fix path is deeper than `trivial-tweak`; it closes when no such finding remains outstanding. Severity is consequence, orthogonal to depth; the levels and their one-line tests live in the routing reference (Section 3) and in the review skills.
>
> - A lane-holding finding stays outstanding until a later cold pass no longer raises it, or it reaches a disposition under which **no fix lands against it**: accepted into the compromise tracker, recorded as a `defer-*` obligation, or closed by `Accept the limitation`, `Cancel`, or a `Defer to follow-up Issue` that ships nothing this round. A dispatch settles nothing — ungated at row 6, chosen at a gate, or the soft fix or narrowing a deferral ships alongside itself — until a later cold pass has read its result.
> - **A `nit` whose chosen path is a `trivial-tweak` never reopens a lane on its own.** When a lane-holding finding forces another implementer round, such nits ride along and the next cold pass reads them. When only such nits remain, apply them in **one** final implementer pass for that lane and dispatch **no** further reviewer round — at a site where the review runs inside the PM's in-flight passes, do not re-dispatch the PM for that lane.
> - **Residual clause.** A `suggestion` closes with the lane, applied in that final pass, only when both hold: its chosen fix path changes neither what the text asserts nor what the code does (the `nit` test, judged over the reviewer's own path description); and the text it targets was read by a prior cold pass at this lane that did not flag it, and no implementer pass at this lane since was dispatched to change it. Judge the second condition over your own dispatch prompts and the prior returns, never over file contents; when either is unreadable the clause does not fire. It cannot fire at a lane's first round. It never applies to a `blocker` or to a `nit` held by depth.
> - **Exit decision per round.** When a round's findings are routed, rewrite the lane's `## Rounds` row (Section 2) — classification, decision, counts — before the action the decision names: the re-dispatch, the final implementer pass, or marking the lane `closed`. Classify a round after the first as `earned` (a lane-holding finding on the previous round's fix), else `late` (a lane-holding finding on older text no prior pass flagged), else `variance` (every lane-holding-tagged finding closed as a residual), else `clean`; `unavailable post-compaction` when the prior returns are gone. A return that is itself unreadable is re-dispatched at the same round, never decided from a summary.
> - Render per lane, in its slot on the **Reviews** line of the summary for the scope that dispatched the review: `N rounds (earned/late/variance/unavailable = a/b/c/d)` when the lane ran more than once; `N nits applied without re-review`; `N residuals applied without re-review` followed by each residual's description on one line. When the manifest carries no row for the lane render `count unavailable post-compaction` rather than guessing. Applied nits and residuals are finished work: never ignored feedback, never `defer-*` obligations.
> - A `nit` whose chosen fix path would fire a gate under part (a) still routes through the table, and **the bound keys on what ships**: when the gate's answer ships anything other than the enumerated `trivial-tweak` path (`Fix properly now` on a row-2, -3, or -4 fire, or the soft fix or narrowing a `Defer` ships alongside itself), the finding is lane-holding again, a cold pass must read that fix, and part (g)'s elision does not apply. When the final pass ships only such `trivial-tweak` paths and residuals and changes source, part (g) applies with its code-review rung elided — the one round this rule suppresses.
> - The post-completion review (Section 11) reads the whole diff, nit fixes and residuals included; it is the cold pass those items receive, and the run's backstop.
