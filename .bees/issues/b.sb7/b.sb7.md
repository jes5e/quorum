## Description

The Doc Writer is instructed to describe "what was actually built" from the Engineer's diff and to append or rewrite a `### Feature: <title>` subsection in the project PRD and SDD on every run, in both execute and fix mode. The Doc Reviewer is instructed to grade the result as a current-state cheat sheet with no design decisions and no history, and to hunt for completeness gaps and duplication. The two contracts contradict each other, and neither assigns any kind of fact a single owning document. The result across every repo using quorum is an SDD that restates mechanism already in the code, carries ticket-keyed history, and duplicates facts across three to six carriers, so every fix pays a doc tax and every doc-review round finds something.

live_edit's SDD was 547 KB when first committed on 2026-07-23 and is 1,958 KB today: 72 percent of it is post-plan accretion written by the Doc Writer, not the original seed. Its per-feature bullets contain "superseded later in this same unreleased set by Issue b.7td, retained here as the record of what b.d6b shipped", against the repo's own doc-writing guide, which routes ticket attribution to the changelog and says to remove outdated text rather than annotate it. Its b.is1 entry records that resizing one re-auth interval was declined partly because it meant "eight doc sites". event_consumer_service and quorum show the other shape: the same defect as a per-feature ledger that is 88 percent of the document.

Five independent agent sessions across these repos agreed on what earned its keep: recorded invariants, decisions with rejected alternatives, and verified facts about the outside world with their source (the Contour readiness-selection fact, the WatchGuard slot-pinning rule, the b.f1v log-level lesson). All agreed the PRD contributed nothing after planning and that the cost was concentrated in doc-review rounds spent on descriptive prose.

## Expected behavior

### Ownership

Every kind of fact has exactly one owning carrier, and the Doc Writer routes facts to owners instead of updating every doc the diff touches:

| Kind of fact | Owner | Never in |
|---|---|---|
| Mechanism: what the code does, internal constants, enum arms, field and metric names, step-by-step algorithms | the code and its doc comments | the SDD |
| Rules: current-state invariants, the contracts the code honors, decisions with rejected alternatives, verified external facts with their source | the SDD register, stated as the rule with its why, a code pointer, and a test pointer when one pins it | changelogs, per-feature narrative, CLAUDE.md beyond a one-line pointer |
| Structure: component boundaries, interactions, data flow, where schemas and API surfaces live, and the path of any archived design doc | the SDD map | duplicated elsewhere |
| History: what changed, when, why, ticket ids, superseded claims | the commit message and the bees ticket (already written, never re-reviewed); a project changelog only if the target CLAUDE.md names one | SDD, README, CLAUDE.md |
| Behavior: what operators and users see — install, commands, configuration surface, user-visible defaults | README or the configured customer docs | duplicated tables elsewhere |
| Requirements (pre-implementation): product scope, non-goals, acceptance criteria | Spec Bee `t1=Doc` children and Issue bodies; whatever the `Project requirements doc (PRD)` key names is background, never authority, never a write target | per-Issue entries |

Engineering, test, and doc conventions belong to the four guides named in `## Documentation Locations` and never enter the register. A CLAUDE.md may state a rule in one line as a pointer to its register entry; the rationale lives only in the register. A Spec Bee SDD child and an Analyst proposal section are ratified **sources**, not owners, so "no fact in two owners" is never read against them. The table lives in exactly one shipped place, `agents/doc-writer.md` `## Fact ownership`; the review skill, the setup skill's generated guide, README, and CONTRIBUTING carry the principle in one sentence and a pointer, never a second copy of the rows.

### The SDD

The maintained SDD is two parts under a size cap. The **map** is the bootstrap skeleton's sections plus one line per archived design document — its path and "historical record, not maintained, verify against code". The **register** is a single `## Register` section with one `### <subsystem>` subsection per owning subsystem; the Doc Writer creates `## Register` at the end of the document when absent and creates a subsystem subsection when absent, the same create-if-absent rule the retired fold-in had. Entry shape: `- **<rule>** Why: <one to three sentences>. Code: <path>. Test: <test>` (Test omitted when nothing pins it). The cap is 500 lines unless the project's doc-writing guide carries a line of the form `SDD size cap: <N> lines`. The admission test for a line: would an agent that skipped it make a worse design decision or reintroduce a fixed bug?

### Relays

Register entries are transcribed from ratified sources the orchestrator relays verbatim, not inferred from the diff:

- **`## Ratified decisions`** carries exactly one section, verbatim, on every Doc Writer dispatch in both modes, to Doc Writer, Doc Reviewer, and PM — the PM because it invokes the per-Task doc review through the Skill tool in execute mode, and a reviewer without the list cannot check transcription. Fix-mode source: the approved directive's `### Policy decisions this change implies` plus any light-revision clarification the Approve carried, mirroring the Engineer's directive text, so a flipped recommended answer relays the ratified answer. Execute-mode source: the `## Decisions and rejected alternatives` section of the spec source's SDD, resolved by the walk `agents/pm.md` already documents — Grandparent Bee `reference_materials` → `bees` resolver → Spec Bee child titled `SDD` → that heading; `file-path` resolver → that heading in the named file; null → the Plan Bee body's decisions section if present. Whatever sits under the heading travels verbatim, its own explicit-none placeholder included. One fixed line for both modes, used only when the source has no such section: `None — the source carries no decisions section.` Relaying to every Doc Writer dispatch is uniform by design: `/quo-breakdown-epic` creates one doc Subtask per code-changing Task without an internal-versus-customer distinction, so routing by Subtask kind would be an orchestrator judgment over ticket bodies.
- **`## Blast radius`** (fix mode only; execute has no such row) gains the Doc Writer and the Doc Reviewer as recipients of the existing verbatim relay, alongside Engineer, PM, Code Reviewer. The Doc Writer reads the invariant lines itself and the Doc Reviewer checks them; no orchestrator extracts anything. Its contract stays "invariants the change adds, removes, or weakens".
- The Analyst promotes a load-bearing rule or verified external fact it finds in the code or in an archived doc **only** through `### Policy decisions this change implies`, framed as "should this rule enter the register?" with a recommended answer — never through `### Blast radius`. The archive directory the map names is excluded from the blast-radius sweep's internal-docs group as a path rule. The Analyst opens an archived doc when the register lacks a rule the Issue implicates; it does not read the archive on every dispatch.

### Doc Writer duties

Three duties per dispatch: customer-facing docs reviewed against the diff; register transcription; map update when a boundary moved. **Implements** means the rule the decision states is true of the code at this diff. The Doc Writer records an entry for each relayed decision the diff implements; a relayed decision the diff does not implement is listed in the return as not-yet-landed, an observation the orchestrator does not route (at Subtask 1 of 6 most decisions are pending by design). The Doc Writer MAY add an entry the diff plainly establishes on its own when it passes the admission test — the entry is the rule with a pointer to the pinning test or the code comment that records the external fact, never a copy of either; no return marker, the reviewer derives such entries. The Issue body's `## Doc divergence noted` items are ratified by the Validate-Issue gate and route to their owners inside the first two duties; an item that points at a PRD is reported as "background document, no owner, no action". The Doc Writer always writes; it carries no over-cap report, because a free-form return has no consumer.

### Doc Reviewer checks

Every check is scoped to the register, map, and README regions the diff touched plus the relayed lists; pre-existing misplaced facts, pre-existing duplicates, and a pre-existing over-cap SDD are not findings (each repo's migration is tracked separately, item 10). Five checks:

1. README claims in the touched regions are true against the diff.
2. Each relayed decision and invariant the diff implements has a normative register entry with a code pointer, and a test pointer when one pins it, and no ticket id; a removed or weakened invariant on the `## Blast radius` list has no surviving entry; a relayed decision the diff **contradicts** is a `blocker` whose fix path changes source, which routes through part (g) in fix mode and through the PM's in-flight review in execute mode. Any register entry the diff touched that is not on the relayed lists is checked against the code and its test. When the caller supplied no `## Ratified decisions` heading (standalone or pre-relay invocation), the transcription half is skipped and the return says so.
3. The map reflects every component, boundary, data-flow, external-dependency, and schema or API-surface change the diff made — today's architecture check restated against the map.
4. The diff did not take the SDD over its cap.
5. No fact the diff wrote appears in two owners.

Severity follows ownership: a false claim is a `blocker`; a fact in the wrong owner or in two owners is a `suggestion` with a move-and-pointer fix path; wording inside the right owner is a `nit` unless false.

## Impact

Wall-clock and token cost on every `/quo-fix-issue` and `/quo-execute` run in every downstream repo: five to eight doc-review rounds per Issue were reported, most spent on descriptive prose and multi-carrier drift. Correctness risk: descriptive SDD claims drift and are then trusted by cold agents (§17.2 "OMPF parse failures log at ERROR" was never true; the "Delete refused pre-MULTI" claim was unreachable). A frozen-but-consulted doc would make that permanent, which is why the PRD is archived and taken out of the agents' authoritative read set rather than frozen in place.

## Background and rationale

Three truths, and code owns only one. Code is the truth for what the system does; tests are the truth for what it must keep doing; specs are the truth for what it should do for users. A doc sentence describing what the code does is a second copy and drifts. A doc sentence stating what the code must do is normative: when it disagrees with the code, the code is wrong. That is the line between the register and everything that leaves.

The churn decomposes into four kinds: drift corrections on descriptive claims (eliminated when mechanism leaves the docs), multi-carrier edits (eliminated by single ownership), wording rounds (shrunk by a convergent reviewer criterion), and genuine README defects (kept; they are product defects). Round caps, delta-only rounds, and skipped lanes were rejected as speed levers on 2026-09-04 and are not proposed here; this change shrinks what there is to review, not how hard it is reviewed.

The live_edit CLAUDE.md invariant section (one-line rules with SDD section pointers) is already register-shaped and was grown by hand because agents needed it; the SDD behind it is the encyclopedia nobody can read whole. Both downstream repos already carry an IMPLEMENTATION_CHANGELOG (155k and 18k words); moving history there would relocate the churn, since the Doc Reviewer reviews it too, so history's owner is the commit and the ticket.

## Decisions and rejected alternatives

- **Retire the per-feature fold-in entirely** rather than narrow the Doc Writer's question. Rejected because live_edit proves the fold-in is not the only growth surface; the topical sections grew the same way. The ownership table addresses both shapes.
- **Archive the PRD, do not freeze it in place, and key nothing on a header.** A frozen doc still on the agents' read list is read as authority. The signal that a document is background is that the PRD key names it; a starting-point header is human-facing text only.
- **Keep bootstrapping a starting-point PRD; make the empty key a steady state.** The bootstrap's four user questions (purpose, why, non-goals, an acceptance criterion) capture background nothing else in the workflow asks for, and `/quo-plan` reads it. Stopping the bootstrap was rejected on that ground; making the key permanently skippable and keying the re-run bootstrap on the SDD alone removes the re-prompt.
- **Transcribe register entries from ratified sources; allow one bounded, reviewer-checked exception.** Transcription removes the judgment call that inflated the old SDDs. The unrelayed entry for a rule the diff plainly establishes is kept deliberately and derived by the reviewer rather than marked by the writer.
- **Relay `## Ratified decisions` to every Doc Writer dispatch; not-yet-landed is an unrouted observation.** Routing by Subtask kind was rejected because the breakdown does not distinguish doc Subtasks by kind. Moving transcription to the per-Task PM boundary was rejected because the PM does not write docs.
- **Contradiction is a reviewer blocker, not a writer report.** A Doc Writer return is untagged and unrouted; §4 has no rung for it. As Doc Reviewer check 2 it is a `blocker` with a source-changing fix path, which the existing routing already carries.
- **One relayed section per heading, one fixed none-line for both modes; the Doc Writer and Doc Reviewer read Blast radius themselves.** "The invariant lines of Blast radius" would be an orchestrator extraction over free-form prose, which the rewrite forbids; adding both doc roles to the existing verbatim `## Blast radius` relay is b.ag8's design and dissolves the heading collision. Two mode-specific none literals were rejected as two strings every consumer and test must recognize.
- **Promote rules through `### Policy decisions this change implies`, not `### Blast radius`.** Blast radius feeds the Code Reviewer's sweep verification; a relied-upon-but-unchanged invariant listed there would produce a finding against the Engineer at every unchanged site.
- **PM and Doc Reviewer both receive both relays.** In execute mode the per-Task doc review is the PM's Skill invocation; the doc-reviewer subagent runs only at Bee scope. Without the Blast radius list a removed invariant whose entry survived is undetectable, since the unrelayed-entry rule sees only entries the diff touched.
- **Every reviewer check is diff-scoped; pre-existing over-cap is silence.** "Over cap is a defect regardless" and a whole-document two-owners hunt both strand every unmigrated repo with out-of-scope findings per round. "Note it once" was rejected because a cold reviewer cannot do "once", the review skill has no narrative subsection, and an untagged item routes as re-architect to a gate; migration is tracked per repo in item 10 instead.
- **The register is one `## Register` section with per-subsystem `###` subsections, create-if-absent.** Two stated shapes left the Doc Writer without a rule in an unmigrated SDD.
- **The archive is reachable through the map, excluded from the sweep by path.** One map line per archived doc; the Analyst opens it on demand, never on every dispatch (live_edit's archive is 276k words); the sweep exclusion is the directory the map names, so it is mechanical.
- **CLAUDE.md is a pointer surface for Rules, not an owner.** live_edit's own guide already says one-line rule plus SDD pointer, rationale in the SDD; the migration keeps that shape and moves rationale into the register rather than relitigating a large CLAUDE.md.
- **The ownership table has one shipped carrier.** The first cold review found two mirrors diverged on day one. Every other artifact states the principle in a sentence and points at `agents/doc-writer.md`.
- **Size cap as a review criterion**, project-overridable through a named guide phrase, default 500 lines. Rules without a bound erode; precedent: the orchestrator bodies' line budget.
- **History to commit plus ticket, not to a reviewed changelog.**
- **Archive-and-rebuild for every downstream repo**, resumable via the heading-walk ledger.
- **Leave the `### Feature:` scoping machinery in place in this change and retire it in a follow-up**, including its two remaining advertising sites. The README stops advertising it now.
- **Discard the first worktree and restart from main after the validation-fix batch commits.** The first diff predates seven design changes and rewrites §5 sentences that batch is rewriting concurrently.
- **Cap rounds / batch nits / skip the PRD check by Issue shape.** Rejected: the first two by the 2026-09-04 decision; the third because `agents/pm.md` rejects shape-based short-circuits for good reason.
