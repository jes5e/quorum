## Description

The Doc Writer is instructed to describe "what was actually built" from the Engineer's diff and to append or rewrite a `### Feature: <title>` subsection in the project PRD and SDD on every run, in both execute and fix mode. The Doc Reviewer is instructed to grade the result as a current-state cheat sheet with no design decisions and no history, and to hunt for completeness gaps and duplication. The two contracts contradict each other, and neither assigns any kind of fact a single owning document. The result across every repo using quorum is an SDD that restates mechanism already in the code, carries ticket-keyed history, and duplicates facts across three to six carriers, so every fix pays a doc tax and every doc-review round finds something.

## Expected behavior

### Ownership

Every kind of fact has exactly one owning carrier, and the Doc Writer routes facts to owners instead of updating every doc the diff touches:

| Kind of fact | Owner | Never in |
|---|---|---|
| Mechanism: what the code does, internal constants, enum arms, field and metric names, step-by-step algorithms | the code and its doc comments | the SDD |
| Rules: current-state invariants, the contracts the code honors, decisions with rejected alternatives, verified external facts with their source | the SDD register, stated as the rule with its why, a code pointer, and a test pointer when one pins it | changelogs, per-feature narrative, CLAUDE.md beyond a one-line pointer |
| Structure: component boundaries, interactions, data flow, where schemas and API surfaces live, and the path of any archived design doc | the SDD map | duplicated elsewhere |
| History: what changed, when, why, ticket ids, superseded claims, deferred work | the commit message and the bees ticket (already written, never re-reviewed); a project changelog only if the target CLAUDE.md names one | SDD, README, CLAUDE.md |
| Behavior: what operators and users see — install, commands, configuration surface, user-visible defaults | README or the configured customer docs | duplicated tables elsewhere |
| Requirements (pre-implementation): product scope, non-goals, acceptance criteria | Spec Bee `t1=Doc` children and Issue bodies; whatever the `Project requirements doc (PRD)` key names is background, never authority, never a write target | per-Issue entries |

Engineering, test, and doc conventions belong to the four guides named in `## Documentation Locations` and never enter the register. A CLAUDE.md may state a rule in one line as a pointer to its register entry; the rationale lives only in the register; those pointer lines are hand-maintained by the operator and are never a Doc Writer target. A Spec Bee SDD child and an Analyst proposal section are ratified **sources**, not owners, so "no fact in two owners" is never read against them. The table lives in exactly one shipped place, `agents/doc-writer.md` `## Fact ownership`; the review skill, the setup skill's generated guide, README, and CONTRIBUTING carry the principle in one sentence and a pointer, never a second copy of the rows.

### The SDD

The maintained SDD is two parts under a size cap. The **map** is the bootstrap skeleton's sections plus one line per archived design document — its path and "historical record, not maintained, verify against code"; pre-migration, the map is whatever architecture sections the SDD carries. The **register** is a single `## Register` section with one `### <subsystem>` subsection per owning subsystem, where subsystem names are the map's `## Key components` bullet names (pre-migration, the SDD's top-level architecture section titles) and a rule spanning components goes under `### Cross-cutting`; the Doc Writer creates `## Register` at the end of the document when absent and creates a subsystem subsection when absent, the same create-if-absent rule the retired fold-in had. Entry shape: `- **<rule>** Why: <one to three sentences>. Code: <path>. Test: <test>` (Test omitted when nothing pins it). The cap is 500 lines unless the project's doc-writing guide carries a line of the form `SDD size cap: <N> lines`. The admission test for a line: would an agent that skipped it make a worse design decision or reintroduce a fixed bug?

### Relays

Register entries are transcribed from ratified sources the orchestrator relays verbatim, not inferred from the diff:

- **`## Ratified decisions`** carries one section plus, in fix mode, the light-revision clarification the Engineer's directive block already carries, verbatim, on every Doc Writer dispatch in both modes, to Doc Writer, Doc Reviewer, and PM — the PM because it invokes the per-Task doc review through the Skill tool in execute mode, and a reviewer without the list cannot check transcription. Fix-mode source: the approved directive's `### Policy decisions this change implies` plus that clarification, so a flipped recommended answer relays the ratified answer; the Analyst's section is unconditional with its own none-line, so the row's fixed line is unreachable in fix mode and no fix-mode branch is built for it. Execute-mode source: the `## Decisions and rejected alternatives` section of the spec source's SDD, resolved by the walk `agents/pm.md` already documents — Grandparent Bee `reference_materials` → `bees` resolver → Spec Bee child titled `SDD` → that heading; `file-path` resolver → that heading in the named file; null → the Plan Bee body's section under that literal heading. Whatever sits under the heading travels verbatim, its own explicit-none placeholder included. Fixed line, used only when the source has no such heading: `None — the source carries no decisions section.` The fixed line never substitutes for a lost proposal: after a compaction between Phase A and Phase B the proposal is re-derived before the dispatch that needs it, the same clause the `## Blast radius` row carries. Relaying to every Doc Writer dispatch is uniform by design: `/quo-breakdown-epic` creates one doc Subtask per code-changing Task without an internal-versus-customer distinction, so routing by Subtask kind would be an orchestrator judgment over ticket bodies.
- **`## Blast radius`** (fix mode only) gains the Doc Writer and the Doc Reviewer as recipients of the existing verbatim relay, alongside Engineer, PM, Code Reviewer. The Doc Writer reads the invariant lines itself and dispositions each customer-docs and internal-docs site the list names; the Doc Reviewer checks both; no orchestrator extracts anything. Its contract stays "invariants the change adds, removes, or weakens". Execute mode has no such row, so the removed-invariant hole this closes in fix mode stays open in execute mode by construction; b.eid (plan-path up-front enumeration) is where that closes.
- The Analyst promotes a load-bearing rule or verified external fact it finds in the code or in an archived doc **only** through `### Policy decisions this change implies`, framed as "should this rule enter the register?" with a recommended answer — never through `### Blast radius`. The archive directory the map names is excluded from the blast-radius sweep's internal-docs group as a path rule. The Analyst opens an archived doc when the register lacks a rule the Issue implicates; it does not read the archive on every dispatch.

### Doc Writer duties

Three duties per dispatch:

1. **Customer-facing docs, and every SDD sentence the Engineer's diff makes false.** Correct the false sentence in its owner, or delete it when it is mechanism or history. In fix mode, disposition each customer-docs and internal-docs site on the `## Blast radius` list in the return as `fixed`, `deleted as mechanism`, or `not a hit`. This is what keeps a false `### Feature:` sentence in an unmigrated SDD from being nobody's duty for as long as a migration takes.
2. **Register transcription.** An entry for each relayed decision the diff implements, and for each `## Blast radius` added invariant that passes the admission test; delete the entry of a removed invariant; amend the entry of a weakened one. **Implements** means the rule the decision states is true of the code at this diff; a relayed decision the diff does not implement gets no entry and no report. The Doc Writer MAY add an entry the diff plainly establishes on its own when it passes the admission test — the entry is the rule with a pointer to the pinning test or the code comment that records the external fact, never a copy of either; no return marker, the reviewer derives such entries. The Issue body's `## Doc divergence noted` items are ratified by the Validate-Issue gate and route to their owners inside duties 1 and 2; an item that points at a PRD is left alone with no report, since `/quo-file-issue` no longer records such items.
3. **Map update** when the diff moved a component boundary, interaction, data flow, external dependency, or schema or API surface.

The Doc Writer's return carries the duty-1 disposition list and nothing else the orchestrator would have to route: no not-yet-landed list, no over-cap report, no no-owner report.

### Doc Reviewer checks

Scope: every claim in the README or SDD about code the Engineer's diff changed, plus every region the Doc Writer's diff edited, plus the relayed lists. Pre-existing misplaced facts, pre-existing duplicates, and a pre-existing over-cap SDD outside that scope are not findings (each repo's migration is tracked separately, item 10). The Doc Reviewer reads source and tests to verify register claims and to detect a contradicting diff; it does not review source quality, which is the Code Reviewer's lane. Five checks:

1. Claims in scope are true against the diff; in fix mode, each `## Blast radius` doc site is dispositioned in the Doc Writer's return and the disposition is correct.
2. Each relayed decision the diff implements, and each added invariant, has a normative register entry with a code pointer, a test pointer when one pins it, and no ticket id — or the reviewer states why the item fails the admission test when it lacks one; a removed invariant has no surviving entry and a weakened one is amended; a relayed decision the diff **contradicts** is a `blocker` whose fix path changes source, routed through part (g) in fix mode and the PM's in-flight review in execute mode, with a second fix path in execute mode — revise the Spec SDD child — for the case where the breakdown deliberately refined the spec. **Contradicts** means the diff makes the rule false where the pre-diff code honored it, or the Subtask body or directive calls for the rule and the diff violates it; otherwise the decision is pending and not a finding. Any register entry the diff touched that is not on the relayed lists is checked against the code and its test. When the caller supplied no `## Ratified decisions` heading (standalone or pre-relay invocation), the transcription half is skipped and the return says so.
3. The map reflects every component, boundary, data-flow, external-dependency, and schema or API-surface change the diff made — today's architecture check restated against the map.
4. The diff did not take the SDD over its cap. Severity `suggestion`; fix paths (a) compact the subsystem subsections the diff touched by the admission test, (b) if still over, `defer-to-new-Issue` naming the repo's migration.
5. No fact the diff wrote appears in two owners.

Severity follows ownership: a false claim is a `blocker`; a fact in the wrong owner or in two owners is a `suggestion` with a move-and-pointer fix path; wording inside the right owner is a `nit` unless false.

## Impact

## Background and rationale

Three truths, and code owns only one. Code is the truth for what the system does; tests are the truth for what it must keep doing; specs are the truth for what it should do for users. A doc sentence describing what the code does is a second copy and drifts. A doc sentence stating what the code must do is normative: when it disagrees with the code, the code is wrong. That is the line between the register and everything that leaves.

The churn decomposes into four kinds: drift corrections on descriptive claims (eliminated when mechanism leaves the docs), multi-carrier edits (eliminated by single ownership), wording rounds (shrunk by a convergent reviewer criterion), and genuine README defects (kept; they are product defects). Round caps, delta-only rounds, and skipped lanes were rejected as speed levers on 2026-09-04 and are not proposed here; this change shrinks what there is to review, not how hard it is reviewed.

The live_edit CLAUDE.md invariant section (one-line rules with SDD section pointers) is already register-shaped and was grown by hand because agents needed it; the SDD behind it is the encyclopedia nobody can read whole. Both downstream repos already carry an IMPLEMENTATION_CHANGELOG (155k and 18k words); moving history there would relocate the churn, since the Doc Reviewer reviews it too, so history's owner is the commit and the ticket.

## Decisions and rejected alternatives

- **Retire the per-feature fold-in entirely** rather than narrow the Doc Writer's question. Rejected because live_edit proves the fold-in is not the only growth surface; the topical sections grew the same way. The ownership table addresses both shapes.
- **Archive the PRD, do not freeze it in place, and key nothing on a header.** A frozen doc still on the agents' read list is read as authority. The signal that a document is background is that the PRD key names it.
- **Keep bootstrapping a starting-point PRD; make the empty key a steady state.** The bootstrap's four user questions (purpose, why, non-goals, an acceptance criterion) capture background nothing else in the workflow asks for; the Analyst reads what the key names as background and the human reader gets a one-page statement of purpose. `/quo-plan` does not read it. Stopping the bootstrap was rejected on the first ground; present-but-empty means skipped so the walkthrough stops re-asking.
- **Transcribe register entries from ratified sources; allow one bounded, reviewer-checked exception.** Transcription removes the judgment call that inflated the old SDDs. The unrelayed entry for a rule the diff plainly establishes is kept deliberately and derived by the reviewer rather than marked by the writer.
- **Duty 1 covers every SDD sentence the Engineer's diff makes false, and the Doc Reviewer's scope is the Engineer's diff plus the Doc Writer's.** Scoping to the doc diff alone would let a changed CLI flag with no README edit pass with zero findings, a coverage regression against today's steps 3 and 4, and would leave a false sentence in an unmigrated SDD nobody's duty until migration.
- **Invariants enter the register through the admission test; removed ones are deleted, weakened ones amended.** Blast radius enumerates at mechanism grain, one line per site; transcribing every line regrows the SDD, and a reviewer demanding every line raises a perpetual finding. The admission test is the filter on both sides.
- **Relay `## Ratified decisions` to every Doc Writer dispatch; a decision the diff does not implement gets no entry and no report.** Routing by Subtask kind was rejected because the breakdown does not distinguish doc Subtasks by kind. Moving transcription to the per-Task PM boundary was rejected because the PM does not write docs. A not-yet-landed list was deleted because a free-form return has no consumer.
- **Contradiction is a reviewer blocker with a defined meaning, not a writer report.** A Doc Writer return is untagged and unrouted. As check 2 it is a `blocker` with a source-changing fix path the existing routing already carries; "contradicts" is defined against the pre-diff code and the Subtask body or directive so a pending decision on a groundwork Task is never a blocker; execute mode gets a second fix path, revise the Spec SDD child, for a deliberately refined spec.
- **The Doc Reviewer reads source and tests, but does not review their quality.** Verifying a register claim is reading code; the Code Reviewer's lane is judging it.
- **One relayed section per heading, plus the directive's own clarification in fix mode; one fixed none-line; a lost proposal is re-derived, never substituted.** "The invariant lines of Blast radius" would be an orchestrator extraction over free-form prose; adding both doc roles to the existing verbatim relay is b.ag8's design. The fixed line is unreachable in fix mode and no branch is built for it.
- **The Doc Writer dispositions the Blast radius doc sites and check 1 reads the list.** The doc-site kind-groups are b.ag8 Gap 2's doc half; leaving them unconsumed while relaying the list would be a relay with no consumer. b.sb7 takes that half and says so in the annotation.
- **Promote rules through `### Policy decisions this change implies`, not `### Blast radius`.** Blast radius feeds the Code Reviewer's sweep verification; a relied-upon-but-unchanged invariant listed there would produce a finding against the Engineer at every unchanged site.
- **PM and Doc Reviewer both receive both relays.** In execute mode the per-Task doc review is the PM's Skill invocation; the doc-reviewer subagent runs only at Bee scope. Without the Blast radius list a removed invariant whose entry survived is undetectable. Execute mode has no Blast radius row, so that hole stays open there by construction; b.eid owns it.
- **Every reviewer check is scoped; pre-existing over-cap is silence; the cap finding has a severity and two fix paths.** "Over cap is a defect regardless" strands every unmigrated repo; "note it once" was rejected because a cold reviewer cannot do "once" and an untagged item routes to a gate; "remove something" is a whole-document judgment, so the fix paths are compact-what-you-touched then defer to the migration Issue.
