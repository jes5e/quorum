## Problem Statement

The context-window guard shipped by Plan b.55r lets the three long-running orchestrator skills (`/quo-execute`, `/quo-fix-issue`, `/quo-breakdown-epic`) stop cleanly at an Epic or Issue boundary when the session's context usage is high, so the harness's automatic compaction does not land in the middle of a unit of work. The guard's core works and is well tested. Three problems surround it:

1. **The missing-reading behavior is a hard stop with a four-way decision.** When no usage reading is published for the session, every boundary crossing forces the operator through a gate (configure now / proceed this run / never guard me / stop). The "never guard me" choice depends on a persistent opt-out marker whose writer and readers disagree about where the platform temp directory is, so on macOS — where the per-user `TMPDIR` is not `/tmp` — the opt-out is silently ineffective and the operator is re-gated at every boundary despite having opted out.
2. **The guard procedure is written out three times.** Each orchestrator carries a near-identical ~100-line copy of the procedure, all loaded into the orchestrator's context at skill start even though the procedure runs only at boundaries. Three copies drift (one already carries a stray instruction to read the entire helper script at run time), and the volume works against the very context budget the guard protects.
3. **The stop threshold is a fixed number anchored on a wrong one, and it ignores what it is protecting against.** The 50% stop point was derived from an assumed ~83% compaction trigger. Measured against the installed Claude Code CLI, compaction actually triggers when usage reaches the *effective* compaction window minus the reply reservation and summary buffer — about 96.7% of a 1M-token window at default settings — and that effective window is lowered by an operator's compaction-window setting or environment variable, which a fixed percentage cannot see. The margin the guard keeps below that line is also fixed at "one worst-case Epic", so a one-Task Epic is stopped as early as a six-Task one. None of the inputs — the compaction point, the per-Task cost — has ever been measured, and nothing in the workflow measures them.

Operators of quorum on long runs bear all three costs: an opt-out that does not work on the most common developer platform, orchestrator context spent on boundary-only prose, and stops that are either needless (small next unit, default window) or too late (lowered compaction window).

## Goals

- Preserve the guard's guarantee: a run whose usage reading at a boundary leaves insufficient room for the next unit stops there with a fresh-session resume command; a stale or untrustworthy reading also stops.
- Replace the missing-reading hard-stop gate with a single one-line notice that names how to configure a producer, after which the run continues.
- Eliminate the persistent opt-out mechanism entirely, so there is no artifact whose writer and readers can disagree.
- Reduce the guard procedure to exactly one canonical copy that the orchestrators consult only when a boundary is reached, with each orchestrator retaining only what genuinely differs per skill.
- Derive the stop threshold at run time from the operator's *effective* compaction window and the *size of the next unit*, so the guard stops neither needlessly before a small unit nor too late for an operator who lowered their compaction window.
- Begin measuring the per-Task and per-unit context cost on real runs, durably enough to recalibrate from, by recording readings at run start, at every Task and unit boundary, and at run end.
- Reduce the contract documentation to one shipped source of truth plus user-facing and contributor-facing summaries, and describe the gauge path truthfully (the helper and the skills' prose-written scratch files resolve the temp directory differently).

## Non-Goals / Out of Scope

- Fixing the producer's crash when the gauge directory is unwritable — tracked separately as Issue b.y2q.
- A post-compaction recovery mechanism (a `SessionStart` hook with the `compact` source) — a separate Plan.
- Removing or simplifying the status-line installer (`inspect-statusline`, `install-statusline`, wrap-don't-replace, the post-write self-check). It stays as-is.
- Changing the *consumer* contract from a percentage to token arithmetic: the orchestrators keep comparing one integer percentage from the helper against one integer percentage from the gauge. (The helper computes that percentage from token quantities internally.)
- Unifying the two temp-directory conventions (the helper's platform lookup versus the skills' literal `/tmp`) — documented here, fixed by a follow-up Issue.
- Changing the reader's four-value output vocabulary (`integer` / `no-reading` / `stale` / `missing`), its exit codes, or the freshness-window semantics.
- The process-improvement Issues b.pdq, b.q3f, and b.nn8, which are sequenced before this work but are not part of it.

## Functional Requirements

- **FR-1 — Fail-open on a missing reading.** When an orchestrator reaches a boundary that invokes the guard and the reader reports `missing`, the orchestrator emits exactly one notice line stating that no context gauge exists for this session, that the run is continuing unguarded, and that `/quo-setup --configure-gauge-producer` configures a producer. It then continues to the next unit. No question is asked and no marker file is consulted.
- **FR-2 — Unchanged stop and continue behavior for all other readings.** An integer reading at or above the threshold stops the run at the boundary with the skill's fresh-session resume command. A `stale` reading, a non-zero reader exit, or empty reader output also stops with the resume command. An integer below the threshold and a `no-reading` value continue silently. The reader's output vocabulary and exit codes are unchanged.
- **FR-3 — Opt-out mechanism removed.** The persistent opt-out marker, the helper subcommand that writes it, the inspector's opt-out report fields, `/quo-setup`'s "run unguarded — don't ask again" option and its opt-out skip rule, the marker's documented scratch-file exception, and every mention of the marker in shipped skills, agent contracts, README, CLAUDE.md, and internal docs are removed. `/quo-setup`'s producer gate offers exactly two choices: configure it, or not now. The two-option gate and the customer-facing opt-out prose are removed in the *same* Epic that changes the boundary behavior, so no intermediate state offers an opt-out that nothing honors.
- **FR-4 — One canonical guard procedure.** The full guard procedure exists in exactly one shipped file beside the gauge helper. Each orchestrator's own guard text is limited to what differs per skill — which flow paths invoke the guard, the resume command, and the size of the next unit — plus a short instruction to consult the canonical procedure when a boundary is reached. No orchestrator carries a branch table of its own. The stray instruction in `/quo-breakdown-epic` to read the helper script at run time is removed.
- **FR-5 — Threshold derived from the effective compaction window and the next unit's size.** The helper's threshold command computes, at run time, the usage percentage at which the harness will compact — from the operator's compaction-window setting or environment variable when present, otherwise the model's window, less the harness's reply reservation and summary buffer, expressed against the model window the gauge reports — and subtracts a margin proportional to the next unit's size (its Task count) plus a fixed per-unit overhead. When the next unit's size is not supplied, the margin is the conservative whole-Epic estimate. The command prints one integer percentage; its accompanying rationale states the formula, the harness version the formula was verified against at implementation time (labeled version-bound), and that the per-Task and overhead figures are provisional until FR-6 supplies data. No artifact in the repository continues to state the superseded "~83%" figure or the earlier "~98.7%" figure. The freshness-window rationale no longer claims the status line does not refresh mid-turn.
- **FR-6 — Readings recorded durably enough to recalibrate from.** The orchestrator records the gauge reading (the integer, or the literal `no-reading` / `stale` / `missing` / `skipped` — never a fabricated number) together with the model window size it was measured against, at run start, after every Task boundary in `/quo-execute`, and after every unit boundary in all three orchestrators, including the run's final unit (a record-only read on run-ending paths, with no stop decision). Each recording is written into the run-state manifest immediately after the reading is taken — before any stop or continue action — and echoed as one transcript line, so the series survives in session logs even though the manifest is truncated by the next run. The internal architecture docs describe how to recalibrate the per-Task cost and overhead from these series.
- **FR-7 — Documentation reduced to one source of truth plus summaries.** The helper's own documentation is the shipped, authoritative statement of the gauge-file contract. The customer-facing docs keep the user-facing contract without opt-out prose and state both temp-directory locations plainly: helper-written files (the gauge) resolve via the platform temp-directory lookup (on macOS typically `$TMPDIR`), while prose-written scratch files (manifests, body files) use literal `/tmp` on POSIX. The contributor guide's contract section is reduced to contributor rationale plus a pointer to the helper's documentation. The cumulative PRD and SDD gain a `### Feature:` subsection for this work, and the b.55r subsection's opt-out and threshold statements are corrected.

## Edge Cases and Error Handling

- **No session identifier available:** the guard is skipped silently, as today — the only silent-skip path; the manifest records `skipped`.
- **`no-reading`:** continue silently, as today.
- **`stale`:** stop, as today, with a note that the producer appears stalled.
- **Reader exits non-zero or prints nothing:** stop, as today; a non-zero exit does not imply a corrupt file.
- **Canonical procedure file cannot be found or read:** the orchestrator surfaces the missing file by path and stops at the boundary with the resume command rather than guessing or continuing unguarded.
- **Next unit's size unknown** (the orchestrator has not yet enumerated the unit's Tasks, or the unit has no Tasks): the helper applies the conservative whole-Epic margin.
- **Operator lowered the compaction window** (setting or environment variable): the derived threshold lowers accordingly, and the guard stops at any reading at or above it. A configured window *larger* than the model's is treated as the model's (as the harness itself does), never as a higher compaction point.
- **Derivation yields no usable headroom** (e.g. a small window where a whole unit cannot fit): the helper clamps to a documented floor and reports the clamp in its explanation output; the guard stops at any reading at or above the floor. The floor is an honest "a unit of this size cannot fit", not a safety guarantee.
- **Small context window** (e.g. 200K tokens): a whole Epic may not fit at any threshold. The guard is best-effort there — it stops when the arithmetic says to, and the rationale states plainly that on small windows the margin cannot be guaranteed.
- **Leftover opt-out marker from the superseded design:** ignored; deleting it is optional housekeeping, documented as such.
- **Re-running `/quo-setup`** on a machine that previously opted out: the producer offer is made again; the operator picks configure or not now.

## Non-Functional Requirements

- **Context footprint.** The guard prose loaded at skill start shrinks from ~100 lines per orchestrator to ~20 or fewer. The shared procedure is read when a boundary is reached; a run with several boundaries reads it more than once, so the saving is drift elimination plus a smaller start-of-skill footprint, not a per-boundary saving.
- **Portability.** Every shell snippet in the canonical procedure ships in paired POSIX and Windows PowerShell forms; the file is project-neutral and references no repository-only documentation.
- **Compatibility.** The helper keeps its Python 3.9 floor. The gauge-file path, field names, and the reader's output contract are unchanged; third-party producers that satisfy the published contract keep working. The threshold command still prints one integer.
- **Quality gate.** Full test suite passes and the linter is clean after every Epic; tests for removed behavior are deleted, not skipped.

## UI/UX Requirements

There is no graphical interface. The operator-visible surfaces are: the one-line notice at a boundary when no reading exists (FR-1); `/quo-setup`'s two-option producer gate (FR-3); the stop message at a boundary — current percentage or stall note plus the exact resume command (unchanged); and the one-line context-reading echo after each recorded boundary (FR-6).

## Background and rationale

This PRD came out of a full review of Plan b.55r (2026-09-02) grounded in the repository and the installed CLI, and was revised after a fresh-eyes plan review (2026-09-03) that read the CLI binary independently. The review confirmed the guard's core — producer, per-session gauge file, four-value reader, stale-means-stop, single-definition-site threshold — and confirmed the mechanism live (the sandbox's gauge rose from 12% to 56% across two days of this planning work, with the reader returning it correctly).

Four facts drive the design. First, the opt-out marker is written through Python's temp-directory lookup but checked through a literal `/tmp` path; on macOS the opt-out is therefore inert. Second, the harness compacts at the effective compaction window minus a reply reservation and a summary buffer — ≈96.7% of a default 1M window — and that effective window is configuration-dependent, so no fixed percentage is correct for every operator; the status-line payload carries nothing about it, so only the helper, reading the operator's settings, can know it. Third, the margin below the compaction line should scale with what is about to be started: the orchestrator knows the next unit's Task count at exactly the moment the guard runs, so a one-Task Epic need not be stopped as early as a six-Task one. Fourth, all the numbers in that arithmetic are estimates today, and the readings needed to replace them are already in hand at every boundary — recording them costs one manifest line and one transcript line.

The plan reviewer also caught a sequencing defect in the first draft (the manifest is rewritten before the guard runs, so "record at the boundary" had no write to ride), an intermediate state between Epics that would have offered an opt-out nothing honored, and the fact that README's single-namespace framing of `.quorum` becomes false the moment the gauge path is described truthfully. All three are folded in.

## Decisions and rejected alternatives

- **Fail-open with a one-line notice** replaces the hard-stop gate. Rejected: keep the gate and fix the macOS path via the helper — preserves the apparatus for one decision a notice covers.
- **Remove the opt-out entirely,** in the same Epic as the fail-open change. Rejected: a two-Epic split that leaves the setup option live but unhonored in between.
- **One canonical procedure file read at the boundary** replaces three copies. Rejected: three copies plus a mirror rule.
- **Threshold derived at run time from the effective compaction window and next-unit size**, printed as one integer by the helper. Rejected: (a) a fixed constant with a corrected rationale — simpler, but wrong for any operator who lowered their compaction window and needlessly early before small units; (b) changing the consumer to token arithmetic — the orchestrators' one-integer contract is worth keeping; the helper can hide the token math.
- **Task count as the unit-size proxy.** Rejected: no proxy (worst case every time); a per-Task complexity estimate (nothing measures it, and Task count is what the orchestrator already has).
- **Record readings at run start, per Task, per unit, and at run end, with a transcript echo.** Rejected: manifest-only at unit boundaries — truncated by the next run, blind to the first and last units, and useless for per-Task cost.
- **State both temp-directory namespaces in README; defer unification to a follow-up Issue.** Rejected: unify inside this plan — cross-cutting the scratch-file convention every skill uses.
- **Keep the guard; keep the installer; reader contract unchanged; `stale:<n>` stays rejected.**
- **Identifiers kept in this PRD where they are the product surface**; implementation-shaped detail lives in the SDD.
