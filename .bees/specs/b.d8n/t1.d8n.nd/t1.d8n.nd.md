## Codebase exploration findings

Findings are from a file-by-file sweep of the repository (2026-09-02/03; line numbers refer to branch `fix/b.ja9` at `52f76d9`) and from reading the installed Claude Code CLI binary (v2.1.259) for the harness behavior the design depends on.

**Architecture.** The guard is a producer/consumer pair meeting only at the gauge-file contract. Producer and reader live in one helper, `skills/quo-setup/scripts/context_gauge.py` (1,462 lines), with six argparse subcommands: `produce`, `read`, `stop-threshold`, `inspect-statusline`, `install-statusline`, `write-opt-out`. The consumers are the three orchestrator skills, each carrying its own copy of the boundary procedure.

**Harness behavior (read from the v2.1.259 binary).** Compaction fires when context tokens reach `threshold = (W_effective − min(max_output_tokens, 20000)) − 13000` — the minified `Knt` level-classifier compacts at `f = ZPe(XB(window))`, where `XB` subtracts the reply reservation (`Von = 20000`) from the effective window and `ZPe` subtracts the 13,000-token summary buffer. `W_effective` is resolved by `wT` from, in precedence order, `CLAUDE_CODE_AUTO_COMPACT_WINDOW` (env), the `autoCompactWindow` setting, a server-provided per-model cache (first-party only), an experiment, and a per-model/per-surface table (the CLI surface uses the model window; a 500K entry exists only for the Cowork `local-agent` surface), falling back to the model window. Two details of `wT` matter for mirroring it: the env var is parsed as a plain integer (`mne` → `al` → `parseInt`; `500k` parses as 500 and is then floored to 100,000; a non-numeric value such as `auto` is skipped and resolution falls through to settings; values are capped at 1,000,000 and floored at 100,000), and every configured value is clamped to the model window — `window = min(W_model, configured)` — so a setting larger than the model's window is inert rather than raising the compaction point. The status-line payload's `used_percentage` is `round(tokens / context_window_size × 100)` against the **model** window (`o6t`). Therefore the compaction point expressed as a `used_percentage` is `(W_effective − 33000) / W_model` — ≈96.7% at default 1M, ≈83.5% at default 200K, and lower whenever an operator lowers `W_effective`. A separate `qnt = min(0.8·W, ZPe(W))` gate arms background *precompute* of the summary (telemetry: "generated in the background at the autocompact threshold and swapped in when prompt-too-long fired"); it is not the compaction trigger. The status-line `context_window` object carries exactly: `total_input_tokens`, `total_output_tokens`, `context_window_size`, `current_usage{...}`, `used_percentage`, `remaining_percentage` — nothing about the effective compaction window, so only the helper, reading settings/env, can know it. `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` is a test override. Skill bodies are replaced at compaction by the literal `[... skill content truncated for compaction; use Read on the skill path if you need the full text]`. The status line refreshes during a turn's tool calls (observed live).

- **SR-2.2** `stop-threshold` becomes a derivation (**Epic 1**), backward-compatible with the bare call the installed orchestrators make today: `stop-threshold [--session-id <id>] [--units <n>] [--explain]`. `W_model` = the session gauge's `context_window.context_window_size` when `--session-id` is given and the field is present, else `DEFAULT_MODEL_WINDOW_TOKENS = 1_000_000`. `W_effective` mirrors the harness's `wT`: read `CLAUDE_CODE_AUTO_COMPACT_WINDOW` as a plain integer (`int(value.strip())`; on failure skip to settings), capped at 1,000,000 and floored at 100,000; else the `autoCompactWindow` key from the **highest-precedence settings scope that defines it** (managed, then local, then project, then user — the harness merges scopes before reading the key, so only the winning definition counts; project/local resolve from the current working directory, as `inspect-statusline` does without `--repo-root`): a numeric value is used as-is, and `"auto"` or any non-number in that winning scope means `W_model` (stop searching — it is the operator's deliberate override); else `W_model`; then **`W_effective = min(W_model, configured)`** for every source. The margin is token-denominated so it means the same thing on every window: `margin_percent = (PER_TASK_COST_TOKENS × units + UNIT_OVERHEAD_TOKENS) / W_model × 100`, with provisional `PER_TASK_COST_TOKENS = 50_000`, `UNIT_OVERHEAD_TOKENS = 50_000`, and `units` defaulting to `DEFAULT_UNIT_TASKS = 5` when `--units` is absent (so the 1M default margin equals the prior whole-Epic estimate, 30 points). Result `floor(compaction_percent − margin_percent)` clamped to `[STOP_THRESHOLD_FLOOR_PERCENT = 10, 95]`. Prints one integer; `--explain` prints one JSON object on stderr naming every input, its source, `configured_window`, `clamped_to_model_window`, and `clamped_to_floor`. Exit 0 on every normal derivation; exit 2 only on argparse error or an invalid `--session-id`. Each constant's comment records the formula, the harness functions it mirrors (`wT`/`mne`/`XB`/`ZPe`/`Knt`), the CLI version verified at implementation time (version-bound), that the per-Task/overhead/default figures are provisional (recalibrate per SR-5.4), and that on small windows the floor may be the honest answer ("a unit cannot fit"). `STOP_THRESHOLD_PERCENT` as a constant is removed.

## Background and rationale

This design follows a full review of Plan b.55r (2026-09-02) and a fresh-eyes plan review of the first draft (2026-09-03) that independently read the CLI binary and found the first draft's anchor incomplete. Four findings drive it.

First, the opt-out marker is written via `tempfile.gettempdir()` but checked via literal `/tmp`; on macOS it never takes effect. Removing the decision it protected removes the artifact.

Second, the harness compacts at `(W_effective − 20,000 − 13,000)` tokens, and `W_effective` is configuration-dependent while the gauge's percentage is computed over the model window. The first draft anchored on `W_model − 13,000` (98.7%); the correct default is 96.7%, and no fixed percentage is correct for an operator who lowered `autoCompactWindow`. The status-line payload cannot see `W_effective`; the helper can, by reading the same env var and settings keys the harness reads. Deriving the threshold in the helper keeps the orchestrators' one-integer contract while making the number right for every configuration the helper can observe. (The per-model server cache and per-surface table are not observable from disk; the CLI surface uses the model window, so the default derivation is correct there.)

Third, the margin should scale with what is about to start. The orchestrator knows the next unit's Task count at exactly the moment the guard runs; a Task-count-proportional margin with a fixed overhead stops a one-Task Epic much later than a six-Task one, without inventing any signal the orchestrator does not have. The provisional constants are chosen so the default (unknown size) reproduces the prior whole-Epic estimate.

Fourth, every number in the arithmetic except the harness constants is an estimate, and the plan reviewer showed the first draft's instrumentation could not have produced data: the manifest is rewritten before the guard runs, is truncated by the next run, and the final unit was never read. Recording immediately after each read, echoing to the transcript, and reading at run start, per Task, and at run end make the series survivable and complete.

The reviewer also surfaced the dead-option gap between Epics 1 and 2 and the false single-namespace framing in README; both are folded in, and namespace unification is deferred to a follow-up Issue rather than expanded into this plan.

## Decisions and rejected alternatives

- **Fail-open notice instead of the gate.** Rejected: keep the gate and route the marker check through the helper.
- **Delete the opt-out entirely, in Epic 1.** Rejected: leaving a no-op subcommand; splitting the gate change from the behavior change.
- **Shared file at `skills/quo-setup/context-guard.md`, sibling-resolved, `Read` at the boundary; four placeholders supplied by the invoking skill.** Rejected: three copies plus a mirror rule; placing the file under `agents/`; inlining the procedure in `--help` output.
- **Derived threshold: `floor((min(W_model, configured) − 33,000)/W_model × 100 − (50,000·units + 50,000)/W_model × 100)`, clamped, printed as one integer; `--session-id` optional.** Rejected: (a) a fixed constant with corrected rationale — wrong under lowered compaction windows and needlessly early before small units; (b) token-based consumer arithmetic — changes the orchestrators' contract for no gain the helper cannot provide; (c) reading `W_effective` from the harness's autocompact-state frame — not exposed to the status line or the shell; (d) percent-denominated cost constants — a 5% margin is 10K tokens on a 200K window and 50K on 1M, so the margin would shrink exactly where the guard is weakest.
- **Task count as the size proxy; provisional 50K tokens per Task + 50K overhead; default 5 Tasks.** Rejected: worst-case-always; a complexity estimate nothing measures.
- **Mirror `wT` exactly: env parsed as a plain integer (cap 1M, floor 100K, invalid → settings), managed > local > project > user for `autoCompactWindow`, and `min(W_model, configured)` for every source.** Rejected: accepting `k`/`m` spellings (the harness's env parser does not) and treating an over-window setting as raising the compaction point (the harness clamps it).
- **Backward-compatible Epic 1.** `--session-id` optional and helper opt-out removal deferred to Epic 2, so the installed orchestrators keep working between Epics. Rejected: deprecated no-op `write-opt-out` (a false contract) and collapsing to one Epic (loses the green helper-first step).
- **Clamp to `[10, 95]` and stop on nonsense.** Rejected: printing a negative or >100 value and letting the consumer sort it out.
- **Record after every read with a minimal manifest rewrite plus a transcript echo; record-only reads at run start, per Task, at run end.** Rejected: manifest-only at unit boundaries (truncated, blind to first/last units); moving the stop decision before the checkpoint (state must be durable before any stop).
- **README states both namespaces; unification deferred to a follow-up Issue.** Rejected: unifying here — cross-cutting the scratch-file convention every skill uses.
- **Remove the two inspector keys** rather than null them. **Keep `FRESHNESS_WINDOW_SECONDS = 1200`.** **Reader contract unchanged.** **Installer kept.**
